## Context

The committed detector-fixture set (`pkg/tuidriver/testdata/*.bin`) is hand-curated. The corpus pipeline now surfaces triaged screens worth pinning as permanent regressions — especially screens where #257's independent label disagrees with the structural detector (each is either a detector bug or a mislabel). Today, turning such a screen into a committed fixture + test is ad hoc and needs bespoke test code per screen.

This ticket closes the loop with **one promotion mechanism**: a promote mode on `cmd/corpus-sampler` that writes a raw-snapshot `.bin` fixture + a manifest entry, and **one** table-driven test that classifies every manifest entry through the same detector path the existing `.bin` fixtures use. New fixtures then need zero new test code.

## The core insight — raw bytes are reconstructed, not stored

The sampler JSONL persists the **rendered `Grid` string** and its normalized `Hash`, *not* the raw buffer-snapshot bytes. But every detector (`IsIdle`, `IsThinking`, `DetectModalClass`, `HasMcpFailureBanner`, `HasNetworkFailure`, `HasUnknownDialog`) takes `snap []byte`, and the committed `testdata/*.bin` fixtures are raw snapshots. So the promoter cannot copy bytes out of the JSONL; it must **reconstruct** the raw snapshot by replaying the sample's source cast to the recorded event index and taking `buf.Snapshot()`.

That is why promote needs the **recordings directory** too — the JSONL alone is necessary but not sufficient — and why it is a **mode of `cmd/corpus-sampler`** rather than a new leaf CLI: a `package main` cannot import another's helpers, so folding it in reuses this package's existing replay path (`parseOutputEventTS`, `normalize`, `hashGrid`, the detector set), the same reason #255 copied corpus-replay's helpers.

### Reconstruction (source-independent rule)

For a sample with field `Event = E`, the raw snapshot is: **append output events `0 … E` inclusive to a fresh `NewBuffer(0)`, then `Snapshot()`.** This single rule covers all sources because of how `sampleCast` stamps `Event`:

| source | buffer state when sample taken | `Event` stamped | events in buffer |
|--------|--------------------------------|-----------------|------------------|
| gap | after events `[0…idx-1]`, before appending `idx` | `idx-1` | `0 … Event` |
| fire / midstream / final | after `Append` of event `idx` (final: last event) | `idx` | `0 … Event` |

Both collapse to `0 … Event` inclusive. Promote therefore does **not** need to know which source produced the sample — it replays, appending each output event, and stops after appending the output event at index `E`.

### Promote mode — `main()` branch

`main()` gains a `-promote` bool that selects the mode. In promote mode the meaningful flags are:

- `-promote` — select promote mode.
- `-in <file>` — the sampler JSONL to read the screen's provenance from (Cast, Event, Cols, Rows, Hash).
- `-hash <hex>` — which distinct screen to promote (the sampler's normalized-grid hash).
- `-dir <dir>` — recordings directory (reused from sampling mode) holding the source `.cast`.
- `-outdir <dir>` — target corpus dir; **default `pkg/tuidriver/testdata/corpus`** (so a bare `go run ./cmd/corpus-sampler -promote …` from repo root writes into the tree the human then `git add`s).

Contract: when `-promote` is set, validate `-in`/`-hash`/`-dir` are non-empty (mutually-exclusive with the sampling path's `-out`/`-gap`/… — a few lines of flag validation; error to stderr + `os.Exit(2)` on misuse, mirroring the existing guard) and call `promote(...)`; otherwise take the existing sampling path unchanged. Keep the sampling path byte-for-byte as-is.

### `promote.go` — contracts (signatures + behaviour, not bodies)

- `func promote(inJSONL, hash, recordingsDir, outDir string) error`
  Orchestrates: find sample → reconstruct+verify snapshot → write fixture → upsert manifest. Returns a wrapped error at each failure; `main` prints it and exits non-zero.

- `func findSample(inJSONL, hash string) (sample, error)`
  Scans the JSONL line-by-line (reuse the `sample` struct; `bufio.Scanner` with the same large-line buffer as `sampleCast`), returns the entry whose `Hash == hash`. Error if not found or the file is unreadable. First match wins (the sampler dedupes on hash, so at most one).

- `func reconstructSnapshot(castPath string, event, cols, rows int, wantHash string) ([]byte, error)`
  Replays `castPath` via `parseOutputEventTS`, appending each output event's bytes to `NewBuffer(0)`; after appending the output event at index `event`, takes `snap := buf.Snapshot()`. **Integrity check:** `hashGrid(normalize(Render(snap, cols, rows))) == wantHash`; error on mismatch (the recordings dir is stale / doesn't match the JSONL). Error if the cast has ≤ `event` output events. Returns the raw `snap`.

- `func computeVerdicts(snap []byte) manifestEntry` (axes only)
  Pre-fills the six axes from the **public detectors on the raw snap** (see § Two renders): `DetectModalClass` (string), `IsThinking` (busy), `IsIdle` (idle), `HasMcpFailureBanner`, `HasNetworkFailure`, `HasUnknownDialog`.

- `func readManifest(path string) ([]manifestEntry, error)` / `func writeManifest(path string, entries []manifestEntry) error`
  Read tolerates a missing file (→ empty slice, first promotion creates it). Write is **deterministic**: entries sorted by `Fixture`, marshaled with fixed indentation, trailing newline — so re-writes are byte-stable.

### Manifest — schema and location

Committed at `pkg/tuidriver/testdata/corpus/manifest.json` as a JSON **array** (a handful of hand-reviewed entries; a pretty-printed array reads best for the human-review step). One entry per fixture:

```
manifestEntry {
  Fixture        string  `json:"fixture"`         // basename under testdata/corpus/, e.g. "<hash>.bin"
  ModalClass     string  `json:"modalClass"`      // DetectModalClass value; "" == ModalClassUnknown
  Busy           bool    `json:"busy"`            // IsThinking
  Idle           bool    `json:"idle"`            // IsIdle
  McpFailure     bool    `json:"mcpFailure"`      // HasMcpFailureBanner
  NetworkFailure bool    `json:"networkFailure"`  // HasNetworkFailure
  UnknownDialog  bool    `json:"unknownDialog"`   // HasUnknownDialog
  Cast           string  `json:"cast"`            // provenance
  Event          int     `json:"event"`           // provenance
  Hash           string  `json:"hash"`            // idempotency key + provenance
  Note           string  `json:"note,omitempty"`  // optional human eyeball label
}
```

**Field-name contract.** The manifest is consumed as a *data artifact*, not an imported Go API: `promote.go` (package `main`) writes it and `corpus_fixtures_test.go` (package `tuidriver` / `tuidriver_test`) reads it with a **separately-declared struct of identical JSON tags**. Keep the two tag sets in lockstep — this is the intended, low-risk coupling the ticket's size note calls out (no mid-flight Go-API drift).

### Fixture naming and idempotency (AC1)

Fixture basename is a **pure function of the hash** (the full hex `<hash>.bin`, or a fixed-length prefix — developer's call, but it MUST derive from the hash alone; no user-chosen name). This makes re-promotion trivially byte-identical: reconstruction is deterministic, so writing `<hash>.bin` again yields identical bytes (git sees no change).

Idempotency of the manifest: **skip the append when an entry with this `Hash` already exists — never overwrite.** This both prevents duplicates AND preserves any human-confirmed axis value a prior review committed (the promoter's prefill is a convenience; the committed value is the human's call — see § Human review). Net effect of a same-hash re-run: byte-identical fixture, unchanged manifest.

### Two renders — the correctness landmine

There are two distinct renders in the promote path; do not conflate them:

1. **Integrity render** (in `reconstructSnapshot`): `Render(snap, sample.Cols, sample.Rows)` → `normalize` → `hashGrid`, compared to `sample.Hash`. Uses the sampler's stored dims so the hash matches what the sampler wrote. This only guards "did we reconstruct the right frame."
2. **Verdict render** (in `computeVerdicts`): the public detectors, which internally `NewGrid(snap, 0, 0)` → render at **default** dims.

The **manifest verdicts MUST be computed via the public detectors** (render #2), because the table test re-computes them the same way. Computing verdicts at `sample.Cols/Rows` instead would risk manifest ⇄ test disagreement. Both the manifest and the test operate on the same raw `snap` through the same public entry points, so they agree by construction regardless of the sample's cols/rows.

### Table-driven test — `pkg/tuidriver/corpus_fixtures_test.go` (AC2, AC4)

One test, `TestCorpusFixtureClassification` (name at developer's discretion). Behaviour:

- Read `testdata/corpus/manifest.json`, unmarshal to `[]manifestEntry`.
- Skip cleanly (not fail) if the manifest is absent or empty? **No** — the seeds guarantee ≥2 entries (AC3), so an empty/missing manifest is a real failure. `t.Fatal` on read/parse error.
- For each entry, `t.Run(entry.Fixture, …)`:
  - `snap, err := os.ReadFile(filepath.Join("testdata", "corpus", entry.Fixture))` — mirror `TestDetectModalClassRealFixtures`. `t.Fatalf("read fixture %s: %v", entry.Fixture, err)`.
  - Assert all six axes: `DetectModalClass(snap) == ModalClass(entry.ModalClass)`, `IsThinking(snap) == entry.Busy`, `IsIdle(snap) == entry.Idle`, and the three banner detectors.
  - **Failure messages: fixture path + axis name + expected-vs-actual class/bool ONLY.** Never print `snap`, the grid, or any byte content (AC4, self-reference discipline). Example: `t.Errorf("%s: DetectModalClass = %q, want %q", entry.Fixture, got, entry.ModalClass)`.

Adding a fixture = run promote + `git add` the new `.bin` + manifest entry. Zero new test code.

## Seed generation — claude-free and corpus-free (AC3)

AC3 needs two committed seeds (one plain-idle, one modal) whose recorded classifications match the detectors so `make check` stays green. The developer does **not** have the real recording corpus (external, operator-run, hand-run like corpus-replay), and `make check` is claude-free. So the seeds are **synthesized deterministically**, exactly as #274 generated its `.cast` via a throwaway Go helper:

1. Author a tiny **seed cast per screen** (single output event each; separate casts avoid rolling-buffer frame-accumulation across frames — the `IsIdle`-true-on-a-later-modal-frame flap noted in the ESC-escaping lesson):
   - **idle seed** — plain text that renders a bare `❯ ` input prompt in the bottom rows with some transcript text above (no ESC needed; `❯` is UTF-8, not a control byte). Detectors: `idle=true`, `modalClass=""`, `busy=false`, banners `false`.
   - **modal seed** — lift the plain-text `ask-user-question` grid form from `modal_test.go:322-326` (`"Which option do you prefer?\r\n❯ 1. Alpha\r\n  2. Beta\r\n(Enter to select · Esc to cancel)\r\n"`). Detectors: `modalClass="ask-user-question"`.
2. Run `corpus-sampler` (with `-final`, so a single-output-event cast emits its ending frame) over the seed-cast dir → a JSONL with two distinct screens + their hashes.
3. Run promote once per hash with `-outdir pkg/tuidriver/testdata/corpus` → writes the two `.bin` + the manifest.
4. `git add` the two `.bin` and `manifest.json`. The seed casts are **throwaway** (not committed) — `*.cast` is globally gitignored and the table test reads only the committed `.bin`/manifest; `promote_test.go` carries its own embedded synthetic cast for regression coverage of the mechanism.

**Expected idle-on-modal interaction (not a bug):** the `ask-user-question` seed's `❯` option row lands in the bottom status region, so `IsIdle` returns **true** on it as well. The axes are independent — record `idle=true` AND `modalClass="ask-user-question"` honestly; both match the detectors, so the suite is green. AC3 requires the recorded classifications to match the detectors, not that the modal seed be non-idle. (If a cleaner non-idle modal is preferred, pad rows so `❯` sits above the last `statusRegionRows`; not required.)

## Human review (AC5)

The promoter **pre-fills** each axis with the detector's current verdict as a convenience, but the committed value is the **human's confirmed call** — that is the documented review step. Document in `README.md` (and a one-line pointer in the manifest header comment is not possible in JSON — put it in README):

- Before committing a promoted fixture, a human MUST eyeball it for **(a) privacy** — raw snapshots can contain paths/prompt content from the source recording — and **(b) anchor content** — the fixture embeds detection-anchor literals by design.
- The seed screens are chosen so detector and human agree (green). Promoting a *disagreement* screen (a #257 label vs. detector conflict — the tool's later purpose) would legitimately turn the suite **red** as a documented detector bug; that is **out of scope here**, and #258's seeds keep `make check` green.

## Concurrency model

None. Promote is a single-threaded, one-shot CLI invocation: read JSONL → replay one cast → write one fixture → rewrite one manifest. No goroutines, no channels, no shutdown sequence. (The sampling path's determinism guarantees are unaffected — promote is a disjoint mode.)

## Error handling

| Failure | Detection | Response |
|---------|-----------|----------|
| `-in`/`-hash`/`-dir` missing in promote mode | flag validation in `main` | stderr message + `os.Exit(2)`, mirror existing guard |
| hash not in JSONL | `findSample` | wrapped error `"hash %s not found in %s"`, non-zero exit, no write |
| source cast missing/unreadable in `-dir` | `os.Open` in reconstruct | wrapped error, no write |
| cast has ≤ `event` output events | replay walk exhausts before index `event` | error `"cast %s: only %d output events, need index %d"`, no write |
| reconstructed hash ≠ `sample.Hash` | integrity check | error `"reconstructed hash mismatch for %s"` (never print grid), no write — recordings/JSONL are out of sync |
| manifest unreadable / malformed JSON | `readManifest` | error, no write (don't clobber a corrupt manifest) |
| same hash already promoted | `readManifest` membership | **success no-op**: rewrite identical `.bin`, skip manifest append |

**Ordering:** reconstruct+verify **before** any write, so a failed promotion leaves the tree untouched. Write the `.bin` then upsert the manifest.

## Testing strategy

`cmd/corpus-sampler/promote_test.go` — fully hermetic (`t.TempDir`, no external corpus, no claude), embedded synthetic cast bytes (no-ESC plain text, generated in-test or as a `[]byte` literal):

- **Round-trip / fixture bytes** — synth a cast + its JSONL (drive `collect`/`sampleCast` in-process to get a real matching hash, or hand-build a JSONL whose hash you compute via the same `normalize`/`hashGrid`); run `promote`; assert the written `.bin` equals the expected reconstructed `Snapshot()` bytes and the manifest entry has the correct axes + provenance.
- **Idempotent re-run (AC1)** — run `promote` twice for the same hash; assert `.bin` byte-identical and manifest length unchanged (no duplicate).
- **Human-value preserved** — pre-seed a manifest entry with a hand-edited axis differing from the detector verdict; re-run promote for that hash; assert the edited value survives (skip-not-overwrite).
- **Hash mismatch aborts** — feed a JSONL whose `Hash` doesn't match the cast's reconstructed frame; assert `promote` errors and writes nothing.
- **Event out of range** — `Event` beyond the cast's output events → error, no write.

`pkg/tuidriver/corpus_fixtures_test.go` — the manifest-driven table test itself, green against the two committed seeds. Verify the failure-message discipline by inspection (no `%v` of `snap`).

`make check` (= `go vet ./...` + `go test ./...`) green.

## Self-reference / security posture

Fixture files contain detection-anchor literals by design, identical to the existing committed fixtures. The discipline (an AC, not optional): the harness references fixtures **by path** and **never prints their bytes or grid content** — a printed anchor could forge a live detector when the suite runs inside the agent pipeline (as #152/#154/#155). This governs both the table test's failure messages and promote's error strings (the hash-mismatch error prints the hash, never the grid).

**Not `security-sensitive`:** the fixtures feed detector *tests*, not any live routing/grant/answer gate. A forged fixture would only make a test assert a wrong classification, caught by the mandatory human-review step — no runtime decision is influenced (consistent with the corpus-tool family: report-only/test-data corpus tooling is not security-sensitive). The ticket carries no `security-sensitive` label, so the label-gated security-review pass does not run.

## Open questions (resolve during implementation)

- **Fixture basename length** — full 64-hex hash vs. a fixed prefix (e.g. 16 hex). Full hash is zero-collision and simplest; a prefix reads better in test output. Either satisfies the pure-function-of-hash idempotency requirement. Developer's call.
- **JSONL vs. JSON-array manifest** — spec prescribes a pretty-printed JSON array for review ergonomics + deterministic re-write. If append-idempotency proves cleaner as JSONL, that is an acceptable substitution provided re-writes stay byte-stable and the reader struct matches; array is the default.
