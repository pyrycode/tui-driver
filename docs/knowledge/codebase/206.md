# #206 — `probe-cwd-encoding`: observe how claude encodes a non-ASCII cwd into its projects-dir name

[Issue](https://github.com/pyrycode/tui-driver/issues/206) · [Spec](../../specs/architecture/206-probe-cwd-encoding.md) · [PR #209](https://github.com/pyrycode/tui-driver/pull/209) · Split from [#166](https://github.com/pyrycode/tui-driver/issues/166) · Unblocks [#207](https://github.com/pyrycode/tui-driver/issues/207) · Feature doc: [e2e harness](../features/e2e-harness.md)

## Summary

Adds a **second probe** binary, `cmd/probe-cwd-encoding`, an `make e2e` recording rig that observes how real `claude` encodes a **non-ASCII** working directory into the `~/.claude/projects/<name>` directory it writes its per-session JSONL under. `tuidriver.EncodeCwd` (`pkg/tuidriver/cwd.go`) maps every **byte** outside `[a-zA-Z0-9]` to one `-` (so `ö` → two hyphens); whether that matches `claude` was unverified — the empirical derivation behind `EncodeCwd` ([#47](47.md), [#57](57.md)) exercised only ASCII specials, and the `café → caf--` unit case in `cwd_test.go` was the byte loop describing *its own output*, never observed from `claude`. The probe launches `claude --session-id <fresh-uuid>` with `cmd.Dir` set to a temp cwd whose leaf is `Työ😀`, sends one trivial prompt (only to make `claude` materialise the JSONL — deferred until first input, [#185](185.md)/finding #9), then discovers the projects-dir **independently of `EncodeCwd`** by globbing `~/.claude/projects/*/<session-id>.jsonl` and taking the parent dir's base name. It records that name byte-for-byte and derives which of {per-UTF-8 byte, per-UTF-16 code unit, per-Unicode character} produced it via a leaf-suffix match. It **ships green whenever it observes** (including — expected — when the observation contradicts `EncodeCwd`), red only when no observation is possible (spawn failed / never idle / JSONL never appeared). It **does not change `EncodeCwd`** — that is #207, blocked on this finding. Wired into `make e2e` (`Makefile` `PROBES` + `cmd/e2e-runner` `buildChecks`, `SuccessMarker: ^OBSERVED`, `.gitignore` entry); nil blast radius — touches no existing symbol.

### The observed result (the payoff — unblocks #207)

First live run, real `claude` **2.1.199**, 2026-07-06 (session `cf16bdbf…`):

```
leaf=Työ😀  observed=…-probe-cwd-encoding-2549730227-Ty---
derived_rule=per-utf16-code-unit   whole_path_cross_check=per-utf16-code-unit
encode_cwd_current=…-Ty------       matches_observed=false
```

**`claude` encodes per UTF-16 code unit** — JS `.replace(/[^a-zA-Z0-9]/g,'-')` semantics: `ö` (U+00F6, BMP, 1 UTF-16 unit) → **one** hyphen; `😀` (U+1F600, astral, surrogate pair, 2 UTF-16 units) → **two** hyphens. So `Työ😀 → Ty---` (5 chars). The current per-byte `EncodeCwd` produces `Ty------` (8 chars) — **wrong** (`matches_observed=false`). The hypothesised rule ([spec Technical Notes](../../specs/architecture/206-probe-cwd-encoding.md)) was confirmed, not merely assumed. The golden is transcribed into [`cmd/probe-cwd-encoding/README.md`](../../../cmd/probe-cwd-encoding/README.md) § Empirical log + § Derived rule; #207 pins `Työ😀 → Ty---` and reimplements `EncodeCwd` per-UTF-16 code unit.

**Latent library defect this exposes:** because `SessionJSONLPath` / `WaitForSessionJSONL` ([#58](58.md)) route through `EncodeCwd`, they compute a projects-dir path `claude` never writes for **any** cwd containing a multi-byte char → they time out against a real non-ASCII cwd. That is the bug #207 closes.

## Patterns established

- **A verification rig must discover ground truth independently of the artifact it verifies.** The load-bearing design constraint: to observe whether `EncodeCwd` is *wrong*, the probe must find `claude`'s directory by a path that does **not** run through `EncodeCwd`. It globs `~/.claude/projects/*/<session-id>.jsonl` (the fresh UUID makes the filename globally unique, so the glob is unambiguous — no stale-match race) and takes `filepath.Base(filepath.Dir(match))`. Using `SessionJSONLPath` / `WaitForSessionJSONL` would have been silently self-referential — a wrong `EncodeCwd` makes them wait on a path `claude` never wrote → timeout → *nothing observed*, and even on success they could only ever *confirm* the current transform. Reuse posture: whenever a rig exists to test whether transform `T` matches an external system, the discovery path must be `T`-free; if the only way to find the evidence routes through `T`, the rig can prove agreement but never disagreement, which defeats it.
- **One discriminating fixture beats several runs.** The leaf `Työ😀` was chosen so per-byte (`Ty------`), per-UTF-16 (`Ty---`) and per-rune (`Ty--`) are all **distinct** in a single observation — a BMP multi-byte char (`ö`: 2 bytes / 1 unit / 1 rune) plus an astral char (`😀`: 4 bytes / 2 units / 1 rune) together separate all three candidate rules at once. A compile-time Go string literal (no shell interpolation) is safe on APFS/ext4/tmpfs. Reuse posture: when a probe must distinguish N hypotheses, engineer one input that fans them out rather than running N narrower probes.
- **Leaf-suffix derivation is immune to prefix-canonicalisation surprises.** `claude`'s encoding is position-preserving and the `/` before the leaf encodes to `-`, so the observed dir ends with `"-" + candidate(leaf)` for the winning rule. Matching on the *known compile-time leaf* means the derivation never depends on canonicalising the ASCII prefix (`EvalSymlinks` vs `claude`'s `getcwd`, macOS `/var`→`/private/var`, case-folding). The probe reports an optional whole-path cross-check as a bonus; when the two disagree the leaf-suffix wins. Here they agreed, but the design tolerated disagreement by construction.
- **Green-on-observation, red-only-on-no-observation is the correct verdict semantics for a recording rig.** A mismatch against the current transform is the *expected, useful* result, so it must not be a failure; `derived_rule=unknown` (no candidate matched — e.g. NFC/NFD normalisation) still exits 0 with the raw dir recorded. Red is reserved for "could not observe" (a real problem). Same posture as the observation spikes (`multiselect`, `ask-user`) that use `^OBSERVED`.
- **A probe with a long internal poll must NOT inherit the 30s `probeCheckTimeout`.** `probe-first-prompt-hang` sets `Timeout: probeCheckTimeout` (30s), but this probe's internal glob-poll deadline (`sessionFileWait`) is itself 30s, so it leaves `Timeout` **unset** → the runner's 60s `defaultCheckTimeout`, letting the 30s poll fit with lead-in room. The `probe` *Kind* does not imply a timeout — the per-check `Timeout` field does; the two probes now sit at 60s and 30s respectively. (Feature doc [e2e-harness.md](../features/e2e-harness.md) § Check kinds corrected accordingly.)

## Lessons learned

- **A recording rig shipping green does NOT mean its golden was captured — the transcription step had no owner.** The rig ran green in QA's first live `make e2e` (claude 2.1.199, `pass`, 1361 ms) and passed code review, yet the `OBSERVED:` block was **not** transcribed into the README by anyone: the spec/arch assigned "transcribe the golden" to "code-review's live-capture pass, or the operator," and neither did it (QA's job is baseline comparison; code review reviewed the diff offline by hand-computing the three transforms). The README's Empirical log sat `_pending_` even though the ticket's *entire deliverable* is the recorded golden. The documentation agent recovered it from the surviving `observation.log` under `$TMPDIR/probe-cwd-encoding-20260706-204004/` (the probe writes a durable artifact there) and transcribed it — genuinely unblocking #207. Lesson for any observe-and-record ticket: **a manual post-run "someone transcribes the log" step is a dropped-owner hazard.** The belt-and-suspenders (different fabric) fix is deterministic capture — persist the golden into a committed artifact the pipeline can't skip, not a `/tmp` log a human must copy. Filed as a follow-up below.
- **The pure claude-free transforms shipped untested on a factually-false premise.** `perByte` / `perRune` / `perUTF16` / `deriveRule` are deterministic and belong under a `make check` table test — exactly the safety net #207 needs for the value it pins. They shipped untested because the spec's Testing-strategy section (which the developer faithfully followed) asserted "no `_test.go` in any `cmd/spike-*` or `cmd/probe-*`." That is false — `cmd/spike-queued-modals/main_test.go` proves the real convention is that claude-free logic in a `cmd/*` binary *does* get table-tested. Code review flagged it non-blocking (SHOULD-FIX on the code, NIT on the README); both are corrected/tracked here and folded into #207's fix rather than re-opening #206. Root cause is a spec claim, not a developer error — when a spec asserts a repo convention, verify it against the tree (`spike-queued-modals` was the counter-example) before it propagates into code + README + a per-ticket doc.
- **All three of the arch doc's open questions resolved green on the first run.** (1) `claude` **tolerated the astral char** `😀` — idled, accepted trust, wrote JSONL, emitted two hyphens as the JS-UTF-16 hypothesis predicted; the BMP-only `Työ` fallback was not needed and stays out. (2) The **whole-path cross-check agreed** with the leaf-suffix rule — no prefix-canonicalisation surprise (`EvalSymlinks` gave the expected `/private/var/...`). (3) **No NFC/NFD normalisation** — `ö` came through as a single BMP code unit, so `derived_rule` resolved cleanly rather than `unknown`. The `do-not-pre-emptively-downgrade` discipline (decide astral tolerance on the live run, not up front) paid off: the stronger fixture held.
- **Cross-repo parallel: the pyrycode consumer already "observes, doesn't infer."** pyrycode's [`jsonl-reconciliation`](https://github.com/pyrycode/pyrycode) feature verifies the encoding *against an existing entry under `~/.claude/projects/`, not inferred* — the same observe-don't-assume posture this probe formalises for the library's own `EncodeCwd`. The two encoders are known to diverge (pyrycode#633: `sessions.encodeWorkdir` maps only `/` and `.`; `tuidriver.EncodeCwd` maps every non-alnum byte + canonicalises symlinks); this observation adds the multi-byte axis to that divergence map and is what #207 uses to close the tui-driver side.

## Follow-ups

- **[#207] Flip `EncodeCwd` per-byte → per-UTF-16 code unit** — pin the leaf golden `Työ😀 → Ty---`, reimplement the transform (range by rune; emit `len(utf16.Encode([]rune{r}))` hyphens per non-alnum rune — `perUTF16` in this probe is the reference), replace the self-referential `café → caf--` unit case, and **add the deterministic `cmd/probe-cwd-encoding/main_test.go` table test** the code-review SHOULD-FIX called for (folds into #207 so `make check` gains teeth alongside the fix). Blocked on this finding — now unblocked.
- **Deterministic golden capture (defeats the dropped-owner hazard).** Consider having the probe/runner persist the `OBSERVED:` block into a committed report artifact (e.g. an `e2e-report.json` field, or a checked-in `observations/` file) so a green live run cannot leave the durable golden uncaptured. Deterministic code, not a manual transcription step. Out of scope here; the transcription was done by hand this once.
- **Widen the CI `probe-recordings` artifact glob.** `.github/workflows/e2e.yml` uploads only `/tmp/probe-first-prompt-hang-*`; this probe writes to `<tmp>/probe-cwd-encoding-*`, so a red run on CI leaves the `observation.log` uncollected. #206 added the probe but did not touch the workflow — widen the glob (or generalise it to `/tmp/probe-*`) in a follow-up so the new probe's forensics survive CI.
- **Emoji-named projects-dir accumulation.** Each `make e2e` leaves a `~/.claude/projects/…-Työ😀-encoded` dir as evidence (matches every sibling spike, which never clean `projects/`). If the accumulation becomes noise, add targeted cleanup in a follow-up.
