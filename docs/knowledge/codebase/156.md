# #156 — Add `esc to interrupt` as a second busy anchor

[Issue](https://github.com/pyrycode/tui-driver/issues/156) · [Spec](../../specs/architecture/156-esc-to-interrupt-busy-anchor.md) · Commit `db08107` · Labels: `security-sensitive` · Related: [#153](153.md) (built the `busyInRegion` seam this folds into), [#150](150.md) (`Grid` / `ContainsInLastRows`), [#154](https://github.com/pyrycode/tui-driver/issues/154) (removes dead whole-buffer paths — none on this axis), [#13](13.md) (space-eating landmine), [#69](69.md) (stuck-`✻` wedge), [#11](11.md)/`spike-cancel` (first observed the hint at runtime)

Second, **independent** busy anchor on the idle/busy axis. Before this ticket the spinner glyph `✻` was the *sole* busy signal, and it has already drifted once — the `✻ <verb> for Ns` text format matches 0/667 captured frames at claude 2.1.158 (CLAUDE.md § Spinner caveat). If the glyph itself changes next, `busyInRegion` goes false mid-turn with **no error at any layer** and the consumer types its next prompt into an in-flight turn (the attacker-relevant CRITICAL-B failure mode from the Cross-Repo Code Review 2026-07-03). This folds claude's on-screen `esc to interrupt` hint into the *same* region-scoped grid predicate as an OR, so the check now survives a change to *either* anchor alone — claude would have to change **both** the spinner glyph and the interrupt-hint wording in one release to defeat it.

## Summary

One production file (`pkg/tuidriver/state.go`), no signature changes anywhere, zero caller edits (~15 call sites across `events.go`/`ready.go`/`deliver.go`/every `cmd/spike-*`/`cmd/probe-*` untouched). Two edits:

- **New exported `const InterruptHint = "esc to interrupt"`** beside the `IdleGlyph`/`SpinnerGlyph` vars.
- **One OR clause in `busyInRegion`** — the single busy predicate #153 established:

  ```go
  func busyInRegion(g *Grid) bool {
      return g.ContainsInLastRows(string(SpinnerGlyph), statusRegionRows) ||
          g.ContainsInLastRows(InterruptHint, statusRegionRows)
  }
  ```

Because `IsIdle` and `IsThinking` both route through `busyInRegion`, they inherit the new anchor coherently from this one change: `IsThinking` returns true when the spinner glyph **or** the hint is in the bottom `statusRegionRows = 6` rows; `IsIdle` returns false whenever *either* is present (idle still requires `❯` present in the region **and** `!busyInRegion`). `busyInRegion`'s doc-comment was updated from "#156 *will* fold the hint in" to describing both anchors as present, keeping the "must never reintroduce a StripANSI whole-buffer path" warning (now doubly load-bearing — see Lessons).

Three table tests added to `state_test.go` (all use the existing `gridRows` `\r\n`-join helper; no new `.bin`):

- `TestIsThinkingInterruptHintDrivesBusy` (AC #3) — hint in the status region, **no** `✻` anywhere ⇒ `IsThinking` true, `IsIdle` false. The `❯`-present-but-still-not-idle assertion is the load-bearing one: it proves the hint *alone* flips busy. Asserts the fixture contains no `✻` so the second-anchor test can't silently become a spinner test.
- `TestIsIdleInterruptHintInTranscriptNotThinking` (AC #4, the security-relevant test) — the literal `esc to interrupt` printed as transcript body ≥ 8 rows above the bottom, genuine idle `❯` at the bottom, no `✻` ⇒ `IsIdle` true, `IsThinking` false. Mirrors `TestIsIdleSpinnerGlyphInTranscriptNotThinking` including the raw-substring contrast (`strings.Contains(string(snap), InterruptHint)` asserted **true** — a whole-buffer path *would* forge busy; only region-scoping gets it right).
- `TestIsThinkingPickerCapturesNotBusy` — real-fixture false-positive guard against `picker-snapshot.bin` + `picker-truecolor-snapshot.bin`, both of which render `…without interrupting the main conversation` (the `/btw` description) inside the 6-row region. Pins the full-phrase decision against a future shortening of the anchor.

## Patterns established

- **The one-seam-per-axis payoff, realised.** [#153](153.md) deliberately routed both idle/busy predicates through one unexported `busyInRegion` so a future anchor could be added in a single place and stay coherent. #156 is the first ticket to cash that in: one OR clause, both predicates updated, zero call-site edits, no signature change. When a design leaves a named single-seam extension point with a doc-comment naming the follow-up, the follow-up is genuinely XS — this is the confirming datapoint.
- **Full contiguous phrase, never a shorter substring — load-bearing against benign in-region content.** A shortened anchor (`interrupt`, `to interrupt`) would false-positive on the picker captures' `…without interrupting the main conversation`, which renders *inside* the status region on an idle screen. The full phrase `esc to interrupt` does not occur in that benign content. This is the inverse of the usual "shorter matcher is more robust" instinct: here the longer, more specific anchor is *strictly safer* because it narrows the match surface. Pinned by a real-fixture regression, not just reasoning.
- **`const string` for a grid anchor with no external `[]byte` consumer.** `IdleGlyph`/`SpinnerGlyph` are `[]byte` vars only because they have external `[]byte` consumers (`deliver_test.go`, spike PTY-quiescence predicates) and get wrapped `string(...)` at the `ContainsInLastRows` call. `InterruptHint` has no such consumer and `ContainsInLastRows` takes a `string`, so an immutable `const string` is the natural fit — no conversion at the call site. Exported for symmetry with the two glyph anchors and because CLAUDE.md now designates the hint the *preferred* in-flight anchor (spinner dead), so consumers writing their own PTY-quiescence checks are the documented next users — documented demand, not speculative surface.

## Lessons learned

- **The space-eating landmine is exactly why this stayed on the grid.** The single-rune glyphs (`✻`, `❯`) sidestepped claude's `\x1b[1C` inter-word cursor-forward rendering — one rune, no interior gaps. A multi-word anchor does not (see [13.md](13.md) finding 3). `StripANSI` collapses claude's inter-word cursor-forwards to nothing (`esc to interrupt` → `esctointerrupt`); the Grid (vt10x render) repaints each skipped column as a real space (→ `esc to interrupt`). So the anchor **must** key on the grid's space-preserved rendered form via `ContainsInLastRows` — which is already how `busyInRegion` works, so the anchor is simply one more `sub`. A `StripANSI`/whole-buffer substring path for this hint would both re-corrupt the phrase's spaces *and* re-open the mid-transcript forgery #153 closed. The doc-comment warning against that path is now doubly important because the multi-word anchor is precisely what a stripped-buffer path would mangle.
- **Synthetic fixtures can't verify the rendered-space identity — flagged, accepted as safe-degrading.** No committed `.bin` captures the hint (`spike-cancel` #11 observed it at runtime but never snapshotted it), so the tests use synthetic `gridRows` grids with single ASCII spaces (U+0020) between the words. The architect's Open Question #1 noted this can't catch a wrong space-identity assumption — `picker-truecolor-snapshot.bin` proves claude emits a literal NBSP (U+00A0) in its input area, so if the hint's inter-word gaps were NBSP or multi-column, `"esc to interrupt"` (ASCII spaces) would silently fail to match. **This degrades safely**: a non-matching anchor falls back to spinner-only detection (today's behaviour), never to a *more*-idle classification — a wrong anchor cannot make a running turn look idle. Shipped the regular-space anchor + synthetic fixture rather than balloon an XS ticket on fixture capture; if a clean thinking-frame capture becomes cheap, swap it in as the positive fixture and confirm the exact bytes. Left as a code-review note.
- **Case sensitivity is an accepted silent-death mode, symmetric with glyph drift.** The hint is lowercase `esc to interrupt` (spike-cancel #11 / CLAUDE.md) and `ContainsInLastRows` is case-sensitive. If a future claude capitalizes it, this anchor goes dead with no error — acceptable, because the spinner anchor still covers busy and it's the same way glyph drift is handled today. Not worth a case-insensitive match absent evidence claude varies the case.
