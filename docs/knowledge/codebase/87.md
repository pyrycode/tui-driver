# #87 — library API: promote `TypePrompt` + `ClearInputLine` PTY primitives to `pkg/tuidriver`

[Issue](https://github.com/pyrycode/tui-driver/issues/87) · [Spec](../../specs/architecture/87-typeprompt-clearinputline.md) · [PR #95](https://github.com/pyrycode/tui-driver/pull/95) · Predecessors: [#9](9.md), [#11](11.md), [#13](13.md), [#71](71.md)

## Summary

Promoted the byte-by-byte prompt-submit helpers copy-pasted across four spike binaries into `pkg/tuidriver` as `(s *Session).TypePrompt(text string) error` and `(s *Session).ClearInputLine() error`. Both mirror the existing [`WritePrompt`](../../../pkg/tuidriver/session.go) shape exactly — thin method on `*Session`, writes to `s.PTY`, lives next to `WritePrompt` in `session.go`. `TypePrompt` writes the body one byte per `s.PTY.Write` call, calls `sleepFn(PromptInterByteDelay)` (10 ms) between bytes, then `sleepFn(PromptCommitSettle)` (50 ms), then a single `\r` byte as a separate write. `ClearInputLine` writes `[]byte{0x15}` (Ctrl-U) and calls `sleepFn(ClearLineSettle)` (50 ms). All three timing constants are exported (`PromptInterByteDelay`, `PromptCommitSettle`, `ClearLineSettle`) so consumers calibrating their own retry/timeout budgets can read them directly rather than re-derive from spike source. The `sleepFn` package-private `var sleepFn = time.Sleep` is the clock seam — tests swap it for a recorder so timing can be asserted as `[PromptInterByteDelay, PromptInterByteDelay, PromptInterByteDelay, PromptCommitSettle]` against `TypePrompt("abc")` without depending on wall-clock fidelity.

`cmd/spike-ask-user/main.go` migrated to call `session.TypePrompt(prompt)` and `session.ClearInputLine()` as proof of usability; its local `clearInputLine`/`typePrompt` functions plus the `clearLineSettle` constant are deleted (38 lines down to 2 call-site edits). The three other spikes (`spike-multi-turn`, `spike-cancel`, `spike-permission`) keep their local copies — separate follow-up tickets, one per spike, each trivial after this lands.

Two architectural decisions worth flagging. First, **no pure-helper factoring** like `WritePrompt`'s `bracketedPaste(text string) []byte`. The byte stream `TypePrompt` writes IS the input verbatim followed by `\r` — there's nothing meaningful to factor as a payload-builder. Instead, the spec factored the **clock seam** (`sleepFn`) so the timing behaviour is testable without `time.Sleep`-based assertions. Second, `TypePrompt` and `WritePrompt` both survive — different prompt-size regimes: `TypePrompt` for short single-line prompts where claude 2.1.148's paste-detection heuristic would mis-classify a bulk-write-with-trailing-`\r`; `WritePrompt` for long/multi-line prompts where bracketed-paste markers tell claude "this IS a paste, don't heuristic-detect."

## Patterns established

- **Package-private `sleepFn` as the clock seam for any time-sensitive primitive.** `var sleepFn = time.Sleep` plus `sleepFn(d)` at every sleep site, tests do `old := sleepFn; sleepFn = fake; t.Cleanup(func() { sleepFn = old })`. Reuse posture: when promoting a spike helper whose behaviour depends on `time.Sleep` calibration, define the seam as a package-private var at promotion time — even if the only initial caller is one method. The cost is two lines and one indirection; the payback is timing tests that assert exact recorded duration sequences against the exported constants, not wall-clock thresholds. The seam is deliberately **not** public — exposing it would invite consumers to plug in untested values; the calibration is what gives the API its contract. Mirrors the `mergeEvents` `snapshot func() []byte` seam pattern from #61 (function parameter rather than package var because `Events` is the only call site, but same principle: an internal seam that the unit test can drive without spawning real I/O).
- **Exporting empirical-calibration constants alongside the method that uses them.** `PromptInterByteDelay`, `PromptCommitSettle`, `ClearLineSettle` are exported (not `promptInterByteDelay` lowercase). Reasoning per the spec: "consumers calibrating their own retry/timeout budgets should be able to read these constants rather than re-derive them." Reuse posture: when a library primitive's behaviour depends on a magic number derived empirically from a specific upstream version (claude 2.1.148 here), name it AND export it. Consumers downstream computing "how long until I should expect this `TypePrompt` to have committed" can multiply `PromptInterByteDelay * len(prompt) + PromptCommitSettle` directly. Same approach as `DefaultShutdownGrace` (which is exported even though `Spawn`'s only caller in-tree is the spike-binary set).
- **PTY-line-discipline tests need raw mode for byte-preserving echo.** `TestSessionClearInputLineSendsCtrlU` can't use the bare `exec.Command("cat")` pattern the other PTY tests use, because `0x15` is the VKILL character — the kernel's line discipline consumes it before it reaches `cat`'s stdin in cooked mode. The fix is `exec.Command("sh", "-c", "stty raw -echo 2>/dev/null; printf READY; exec cat")` — switch the slave to raw mode (no line discipline), then `exec cat` for the echo round-trip. The `READY` sentinel is the synchronisation point: tests poll `Buffer.Snapshot` for `"READY"` before calling `ClearInputLine`, then poll for `0x15` in the bytes after the `READY` substring. Without the sentinel the test could see `0x15` arrive before stty finishes the mode switch (race). Reuse posture: any future test that needs to round-trip a kernel-special byte (VINTR `\x03`, VEOF `\x04`, VEOL, etc.) through the PTY-and-back loop must use raw mode and a sentinel; the cooked-mode line discipline silently rewrites them.
- **Clock-seam tests are NOT safe to run in parallel.** Every `TestSession*Timing` test mutates the package-level `sleepFn`. None of the existing session tests call `t.Parallel()`, so this matches existing conventions — but the spec called it out explicitly: "tests that mutate `sleepFn` are NOT safe to run in parallel with each other; do not introduce `t.Parallel()` in the new tests." Reuse posture: any future test that swaps the `sleepFn` (or any other package-level var serving as a test seam) inherits this constraint. If a future PR adds `t.Parallel()` calls to `session_test.go`, the seam-swapping tests must be skipped or moved to a parallel-safe shape (e.g. injecting the sleep function through a SpawnOpts field — explicitly rejected here under YAGNI but available if the constraint ever bites).

## Lessons learned

- **The "no pure-helper factoring" rejection was correct — there was no payload-builder shape to extract.** `WritePrompt` factors out `bracketedPaste(text string) []byte` because the byte-stream is non-trivial (`\x1b[200~ … \x1b[201~\r` wrapping), and the wrapping logic is the part that benefits from table-tests in isolation. `TypePrompt`'s byte stream is the input verbatim plus `\r` — there's literally nothing to factor. The clock-seam swap supplied the testability the pure-helper would have provided for the wrapping logic. Reuse posture: when porting a primitive that's "behaviour + timing" rather than "payload-shape + behaviour," factor the clock seam, not a pure helper. The shape of the test matters: `TestBracketedPasteWrapping` table-tests payload bytes; `TestSessionTypePromptInterByteTiming` asserts duration sequences. Same testability goal, different seam.
- **The migration is provably small because the local helpers were verbatim copies under attribution comments — extraction is the inverse of the attribution chain.** Each spike's local `clearInputLine`+`typePrompt` carried a `// copied from cmd/spike-cancel/main.go — keep in sync until library extraction` (or equivalent) comment, naming the sibling source and explicitly anticipating this ticket. The 38-line diff in `spike-ask-user` (4 lines added at call sites + 34 lines deleted: 30 LOC of helpers + 4 LOC of constants and comments) is the canonical shape: 2 call-site edits + delete the function bodies + delete the constants no other code in the file references. Reuse posture: when extracting any of the remaining three spike copies (`spike-multi-turn`, `spike-cancel`, `spike-permission`), the diff should look identical in shape — call-site replacement + deletion of the locally-attributed helpers + deletion of the now-unused constants. If any of those three diffs grow beyond ~40 lines, something has drifted from the verbatim-copy contract and the divergence needs to be either reverted or absorbed into the library API. (Per [#71](71.md)'s "attribution-chain shape": the comments cite the immediate source sibling, not the original — `spike-ask-user` → `spike-cancel` → `spike-multi-turn`. The chain collapses to one import in the post-extraction world.)
- **Method placement next to `WritePrompt` (not in a sibling `input.go`) was the right call — "prompt-submission" is one concern, not three.** The spec named this explicitly: "A sibling `input.go` would split a tiny related surface across two files for no benefit. Existing precedent is one file per concern; 'prompt-submission' is one concern." Reuse posture: when promoting a small primitive that shares a concern with existing library code, default to placing it in the existing file. Create new files only when the new concern is structurally distinct (e.g. `jsonl.go` for JSONL primitives, `events.go` for the merge loop — each owns a different data flow). Three prompt-submit methods in one file at ~70 LOC of new code is well below any "split for readability" threshold.
- **`go vet` flagged that `os` and `time` imports in `cmd/spike-ask-user/main.go` were still needed post-migration — the local-helper-delete didn't drop them automatically.** The `os` import is needed for `ptmx := session.PTY` (still bound at line 143 — `sendKeystroke`-style writes at lines 181/286 use `*os.File` directly). The `time` import is needed for the other timing constants in the file (`askUserQuestionLimit`, `postAnswerLimit`, `settleWindow`). No goimports edit was required; both imports stayed. Reuse posture: when migrating away from local helpers in any of the remaining three spikes, `go vet ./cmd/spike-<name>` is the cheap check, but expect both `os` and `time` to still be needed — every spike has other `*os.File` / `time.Duration` references beyond the helpers being deleted.
