# #161 — Lock #152's region-scoping at the `modalDismissed` seam (dismissal-seam regression)

[Issue](https://github.com/pyrycode/tui-driver/issues/161) · [Spec](../../specs/architecture/161-harden-modaldismissed-history-anchor.md) · Commit `bce1ffc` · Blocked by (satisfied): [#152](https://github.com/pyrycode/tui-driver/issues/152) (region-scoped `DetectModalClass`, merged to `main`) · Seam owner: [#147](147.md) (`AnswerModal` / `modalDismissed`) · Grid chain: [#150](150.md), [#151](151.md), [#153](153.md)

**Cross-Repo Code Review 2026-07-03 follow-up — test-only, zero production lines.** Locks the fix #152 already shipped at the exact call site whose false positive caused consumer churn. After `AnswerModal` sends the selecting keystroke, `modalDismissed` (`answer.go:117`) confirms dismissal by re-running `DetectModalClass(snapshot())` and checking the class no longer matches. Pre-#152, `DetectModalClass` substring-matched anchors over the whole append-only *history* buffer, so the answered permission modal's anchor (`"Do you want to proceed"`) lingered in scrolled-up history after dismissal → the re-read reported the class **still present** → `AnswerModal` returned a spurious `"… modal still present after answering"` error → the consumer re-drove an already-committed turn (the destructive re-paste class the review flagged downstream at `deliver.go:155-208`). #152 ported `DetectModalClass` onto the region-scoped rendered grid *in place* (kept the `func(snap []byte) ModalClass` signature and `answer.go:123` as an untouched caller), so `modalDismissed` inherits region-scoping for free. This ticket adds the regression that pins that inheritance.

## Summary

One new `TestModalDismissed` sub-case in `pkg/tuidriver/answer_test.go` (+28 lines), no production change. `answer.go` is untouched — AC #2. The sub-case (`history-only permission anchor counts as dismissed`) builds a forged buffer with the **same shape as #152's `TestDetectModalClassPermissionRegion`**: the permission anchor `"Do you want to proceed?"` at the top, pushed above the bottom permission overlay window by ~25 `\r\n`-terminated transcript-body lines. It asserts `modalDismissed(ctx, ModalClassPermission, snap, time.Second) == true` (the answered class is gone from the live region → dismissed) and that it short-circuits in `< answerConfirmPoll` — because `DetectModalClass(forged) == Unknown` on the top-of-loop check, `modalDismissed` returns before the first poll tick, pinning that the `true` comes from the class-gone signal, not an accidental timeout (which returns `false`, never `true`). A `strings.Contains(…, "Do you want to proceed")` sanity guard asserts the anchor **is** present in the buffer — the whole point is that a naive whole-buffer match would forge "still present" and only region-scoping rejects it.

`security-sensitive` label; architect self-review verdict **PASS** (test-only, asserts the existing trust boundary without moving or widening it). `TestModalDismissed` now runs 5 sub-cases, all green; `TestDetectModalClassPermissionRegion` green.

## Patterns established

- **Pin a shared fix at every seam that consumes it, not only at the detection layer.** #152 asserts `DetectModalClass(forged) == ModalClassUnknown` (detection). #161 asserts the seam that *consumes* that detection returns *dismissed* (`modalDismissed(...) == true`) for the same fixture shape — one layer up. Same forged buffer, **different call and different assertion target** (see table). The two are complementary, not redundant: #152 proves detection excludes the forgery; #161 proves the consuming seam reports *dismissed* rather than *still present*, which is where the destructive re-paste would otherwise trigger. Do **not** re-file #152's `== Unknown` case here (the spec forbids duplicating it).

  | | #152 `TestDetectModalClassPermissionRegion` (modal_test.go) | #161 new sub-case (answer_test.go) |
  |---|---|---|
  | Layer | detection | dismissal seam |
  | Call | `DetectModalClass(forged)` | `modalDismissed(ctx, Permission, ()->forged, t)` |
  | Assert | `== ModalClassUnknown` | `== true` (dismissed) |

- **Pair the positive with a retained negative so the fix can't silently invert.** The history-forged → dismissed assertion alone would still pass if region-scoping regressed into "*every* permission modal reads dismissed". The retained `still present times out to false` sub-case (real `permission-snapshot.bin`, a genuine live-in-region modal → `false`, AC #3) is what forbids that inversion — the `"still present after answering"` error must still fire for a modal that genuinely remains. Both assertions must coexist.

- **Assert the raw-substring contrast, mirroring the [#153](153.md) forgery-regression lesson.** The `strings.Contains` guard makes explicit that a whole-buffer match *would* forge the wrong answer for these exact bytes and only region-scoping gets it right — so the test can never silently pass on a fixture that lost the anchor, and a future reintroduction of a whole-buffer path flips the assertion RED while the raw match stays true.

## Lessons learned

- **A fix's four existing sub-cases didn't cover the bug because none placed the anchor in history-only.** `TestModalDismissed`'s pre-existing cases (`gone` / `still-present` / `different-modal` / `ctx-cancel`) all put the anchor either in the live region or nowhere — so none would have caught the original whole-buffer false positive or would notice a future regression of #152's fix. A regression that locks inherited behaviour belongs at the inheriting seam even when the fix itself lives elsewhere.

- **Blocked-by-#152 was a hard gate, not a courtesy.** The sub-case can only pass once region-scoping lands; a developer implementing it against a pre-#152 `DetectModalClass` would see RED and be tempted to patch `answer.go`. The discipline (spec + ticket): the test asserts *inherited* behaviour, so if it ever fails after #152 that is a #152 region-scoping gap → route back to #152, **do not patch `answer.go` here**. Same shape as the spike/fix-gated split lesson — a caller-side regression that depends on an upstream production change must wait for that change rather than grow a local fix.

- **Fixture built inline, not extracted into a shared cross-file helper.** The forged buffer duplicates #152's shape by hand in `answer_test.go` rather than importing a shared builder from `modal_test.go`. Cross-file coupling for a one-line fixture is scope creep the AC doesn't ask for; the two tests staying independent is worth the small duplication. Grid fixtures use `\r\n` row terminators per the [#150](150.md)/[#153](153.md) rule so vt10x renders flat rows (a bare `\n` staircases them).

- **No new feature doc / ADR — same posture as [#147](147.md)/[#146](146.md).** This is regression coverage of an already-decided, already-shipped mechanic (the dismissal confirm is documented in [system-overview](../architecture/system-overview.md) beside `AnswerModal`), so it lives here, not on a feature page or in INDEX. Test-only tickets create no new evergreen doc → no INDEX line.
