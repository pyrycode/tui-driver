# #141 — `stall_detected` typed Event off the existing watchdog arms

[Issue](https://github.com/pyrycode/tui-driver/issues/141) · [Spec](../../specs/architecture/141-stall-detected-event.md) · [PR #145](https://github.com/pyrycode/tui-driver/pull/145) · Commit `ac3c746` · Extends: [#61](61.md), [#100](100.md) · Reuses: [#89](89.md) (`Tracker` / watchdog)

**Part of pyrycode#596** (Phase 2 structured streaming). Implements the library half of the **safe-degrade marker** from consumer ADR 025 (`pyrycode docs/knowledge/decisions/025-mobile-remote-head-interactive-session.md`): *"Stall (safe-degrade): not-idle + PTY quiet + no JSONL progress → `stall_detected`."* The Phase 5 promise is that the consumer can always render *something* — never go dark — so a broken screen-parser or a claude gone quiet mid-turn degrades to a visible "stalled" state instead of a silent hang.

## Summary

Adds one new `EventKind` constant, `EventKindStallDetected`, to the unified [`Session.Events`](100.md) merge stream (now **eleven** kinds), emitted on the **rising edge** of a three-condition predicate evaluated each poll tick:

```
stalled = !cur.idle                              // (a) mid-turn, not parked at ❯
       && quietFor() > ptyQuietLimit             // (b) PTY quiet beyond the watchdog limit
       && now.Sub(lastJsonlAt) > ptyQuietLimit   // (c) no JSONL progress within that same window
```

The merge loop is the **only library goroutine that sees both inputs** — it tails JSONL *and* polls PTY state — so it is the only correct home for a condition that needs both. The fatal watchdog (`RunWatchdog` / `Tracker.CheckWatchdog`) reads only the buffer, never JSONL, and its PTY-quiet arm terminates the loop with an error. This ticket leaves that arm **completely unchanged**: `EventKindStallDetected` is a separate, **non-fatal** degrade marker on a different goroutine. It reuses only the watchdog's *limit value* (`Tracker.ptyQuietLimit`), not its loop, so exactly one PTY-quiet timeout governs both mechanisms (AC4 — one field, two readers).

The event is **payload-free** (`Source = EventSourcePty`, `Time` set by the merge loop, no `Modal`/`Entry` fields), mirroring the idle/thinking/banner edges. ADR 025 has the consumer emit `stall_detected {conversation_id}` on the wire — `conversation_id` is consumer state, not derivable from the library event — and the only library-side diagnostic (quiet duration) is already reachable via `Session.QuietFor()` at the instant the consumer receives the event. A duration field stays deferred (additive if a real need surfaces; evidence-based).

### Mechanics

- **`ptyState` gains a `stalled bool` field**, but unlike the other five axes it is **NOT** set by `classify` — `classify` sees only the snapshot bytes, never the quiet timings. The merge loop computes `cur.stalled` in the ticker arm *after* `classify` returns, then the existing `prev = cur` machinery carries it forward so the event fires once and re-arms only after the condition clears (a PTY byte, a JSONL entry, or a return to idle).
- **`lastJsonlAt`** is a new goroutine-local `time.Time`, refreshed by **every** JSONL arrival (user / assistant / delta / end_turn — any structured output is "progress" per the safe-degrade ladder). Its zero value (no JSONL yet) makes condition (c) hold, but the arm still cannot fire until (b) — `QuietFor` returns `0` until the first PTY byte, so no false stall at session start.
- **Modals suppress naturally in the common case**: at a *detected* modal the snapshot renders ❯ with no spinner → `IsIdle` true → (a) false → no stall. No explicit `cur.modal` guard is needed for the AC (see Lessons learned for the broken-modal residual).

### The signature change (the one non-additive note)

`mergeEvents` gains two params (`quietFor func() time.Duration`, `ptyQuietLimit time.Duration`) and **`(*Session).Events` gains a required `tr *Tracker` param**:

```go
func (s *Session) Events(ctx context.Context, jsonlPath string, startOffset int64, tr *Tracker) (<-chan Event, error)
```

This **breaks the public `Events` signature** — a deliberate contrast with the additive-only posture of [#136](136.md) / [#138](138.md), which preserved the v1.0.0 / v1.1.0 seal precisely because they added no parameter to an existing symbol. Here the stall arm genuinely needs the tracker's limit, and the architect chose a required `*Tracker` (matching `RunWatchdog`'s "nil tr panics on first dereference" contract) over a getter or a second `TrackerOpts` field, so the limit is *provably* the same value `CheckWatchdog` uses. `tr.ptyQuietLimit` is read directly (same package, immutable after `NewTracker`) — no getter added, keeping the production change to `events.go` alone. The sole production caller, `cmd/spike-long-prompt/main.go`, was updated to `session.Events(rootCtx, jsonlPath, 0, tr)` (`tr` already in scope).

## Patterns established

- **A merge-loop axis that depends on timing, not on the snapshot, is computed in the loop — not in `classify`.** The pre-#141 invariant (since [#100](100.md)) was "every `ptyState` field is set by `classify`." #141 deliberately breaks it for `stalled`: `classify` is a pure function of the snapshot bytes and structurally *cannot* see quiet timings or JSONL arrivals, so forcing `stalled` through it would mean threading the timing inputs into a function whose whole contract is "snapshot → axes." Instead the field lives on `ptyState` (so `prev`/`cur` carries it for rising-edge detection) but is assigned in the ticker arm after `classify` returns. The field's doc-comment flags this explicitly so a future "consistency" pass doesn't try to move it into `classify`. Reuse posture: when a new merge-loop axis is a function of cross-tick state (quiet duration, last-JSONL instant, anything `classify`'s snapshot arg can't reach), give it a `ptyState` field for the edge machinery but compute it inline; keep `classify` snapshot-pure.
- **Reuse a configured value across two mechanisms by reading the same immutable field, not by re-declaring a constant.** AC4 ("don't introduce a second, independently-configured timeout") is satisfied structurally: the fatal watchdog and the stall arm both read `Tracker.ptyQuietLimit`, one field with two readers. Because the field is set once in `NewTracker` and never mutated, the merge goroutine reads it unlocked with no race against the watchdog goroutine (which touches the mutex-guarded spinner/transition state, never the limit). Reuse posture: when two subsystems must agree on a tuning value, share the field; don't pass the value twice or mint a parallel `DefaultX` constant that can silently drift.
- **A new event kind that reuses an existing predicate-bearing struct is an XS slice — the cost is the *seam decision*, not the code.** Like #100's banner axes, the production diff is small (78 lines of `events.go`). The architect-level work was the seam: where the three-condition detection lives (merge loop, not the fatal arm), how it relates to the fatal watchdog (reuse the limit, leave the loop alone), and whether to break the `Events` signature (yes, required `*Tracker`). The ticket's size-guard explicitly bounded this — "if reconciling fatal-vs-degrade requires touching `RunWatchdog`'s contract AND the merge loop AND the tracker, split it" — and the chosen design touched only the merge loop + one call site, staying inside S.

## Lessons learned

- **The "broken-modal-looks-idle" residual is faithful to both the AC and the ADR, and is correctly deferred.** A *broken* (anchor-undetected) permission modal can render ❯ with no spinner → `IsIdle` true → condition (a) false → stall suppressed — even though that is exactly the "dangerous hang" ADR 025 cites. This is not a bug: both the AC ("being at the idle prompt suppresses it") and the ADR ("PTY quiet while **not-idle**") specify the not-idle discriminator, so `!IsIdle` is the literal contract. In the common case the documented 4 KB rolling-buffer ✻-retention (see [#62](62.md) / [system-overview](../architecture/system-overview.md)) keeps `IsIdle` false long enough that the stall *does* fire. A more robust mid-turn signal (turn-state tracking via `end_turn`) is a larger design; defer unless a real broken-modal hang is observed escaping the stall. Evidence-based fix selection — don't ship a defence for a failure mode that hasn't been observed.
- **No explicit modal guard, no diagnostic payload — both deferred for the same reason.** The predicate could also require `cur.modal == ModalClassUnknown` (so a stale ✻ glyph under a *detected* modal can't fire a redundant stall the consumer already knows about), and the event could carry the quiet duration in-band. Both are deferred: the modal case is implicitly handled by condition (a) in the common case (add the guard only if a consumer reports false stalls at modals), and the duration is already reachable via `Session.QuietFor()`. Keeping the predicate and the `Event` struct minimal matches the dominant precedent (idle / thinking / banner kinds are all payload-free).
- **Migrating the existing merge-loop tests was a one-`replace_all` mechanical change.** The 9 identical `go mergeEvents(ctx, snap.Snapshot, jsonlCh, out, DefaultPollInterval)` call sites all took the two new params via one `replace_all`, inserting a `neverQuiet` helper (`func() time.Duration { return 0 }`) + `DefaultPTYQuietLimit`. With `quietFor` returning 0, condition (b) never holds → no stall fires → every pre-existing assertion is unchanged, proving the stall arm doesn't perturb the other axes. This is the [#100](100.md) playbook: additive axes that are by-construction independent of the existing axes migrate cleanly. (`TestEvents_TailJSONLErrorBubbles` took a `NewTracker(TrackerOpts{})` arg — the error path fires before the tracker is dereferenced, so a zero-opts tracker is fine.)
