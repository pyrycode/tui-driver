# #129 — snapshot-drift: drop the `/` picker case (irreducibly host-dependent)

[Issue](https://github.com/pyrycode/tui-driver/issues/129) · [Spec](../../specs/architecture/129-drop-picker-snapshot-case.md) · Split from [#127](https://github.com/pyrycode/tui-driver/issues/127) (sibling [#128](128.md) = `/mcp` empty-state) · Builds on [#81](81.md) · Code: `cmd/e2e-snapshot-check/main.go`, `cmd/e2e-runner/main.go`, `cmd/e2e-runner/main_test.go`, `Makefile`, `pkg/tuidriver/testdata/picker-snapshot.json` (deleted)

## Summary

snapshot-drift's `/` **picker** case was red on `main` as a plain parsed-shape `diff` — no error, the sidecar was written and the parser was sound. The committed `picker-snapshot.json` embedded **operator plugin/skill** commands (`/code-review`, `/figma-use`, `/walkthrough`, `/dependency-graph`, `/logo-creator`) that are **not** claude built-ins, so the fixture diffed whenever the operator's plugin set changed (the `main` failure) and would diff on a clean CI runner (GitHub Actions push-to-main, no plugins, only built-ins render). This is spec [#81](81.md)'s host-portability tension surfacing as a hard failure.

The "scope to built-ins only" approach was investigated live against claude 2.1.158 (PTY capture of the `/` picker) and **ruled out** — no host-portable built-in-vs-plugin discriminator exists (detail in Lessons learned). The chosen fallback is to **drop the picker case** rather than commit operator-specific state.

The change is removal + two consistency edits + a fixture deletion — no new code, no behaviour added:

1. **`cmd/e2e-snapshot-check/main.go`** — removed the `{name: "picker", trigger: "/", settle: 0}` fixture-table entry; dropped the `SNAPSHOT picker match|diff|recorded` line from the stdout-protocol doc comment; updated the `fixture.name` field comment to `// "mcp" | "agents"`. `dumpPathRe` / the `picker-snapshot path=` label is **untouched** — it's the spike's trigger-agnostic dump-path label, reused by mcp/agents. `runFixture` / `emitDiff` / `enrichMissingSidecar` / `-record` path all unchanged.
2. **`cmd/e2e-runner/main.go`** — narrowed `snapshotResultRe` from `^SNAPSHOT (picker|mcp|agents) (match|diff)$` to `^SNAPSHOT (mcp|agents) (match|diff)$`. `parseSnapshotResults` itself is **unchanged** (it derives each fixture path generically from the `SNAPSHOT <name>` line); only the protocol whitelist regex follows the table.
3. **`cmd/e2e-runner/main_test.go`** — `TestParseSnapshotResults` updated to the two-fixture shape; the "partial output (timeout mid-run)" case re-modelled as a genuine partial over the two-fixture set (`SNAPSHOT mcp match` only → `[mcp match]`), preserving its "truncated output still parses" point.
4. **`pkg/tuidriver/testdata/picker-snapshot.json`** — deleted. The `.bin` byte fixtures (`picker-snapshot.bin`, `picker-truecolor-snapshot.bin`) are **retained**.
5. **`Makefile`** — `rerecord-snapshots` comment: "three snapshot-drift JSON fixtures" → "two". Recipe body unchanged (`-record` iterates whatever the table now holds).

**Coverage is not lost.** The picker *parser* stays fully exercised by `TestParsePickerRealFixture` (`pkg/tuidriver/picker_test.go`) and the `DetectModalClass` modal-class regression table (`pkg/tuidriver/modal_test.go`), both reading the **retained** host-independent `.bin` byte fixtures. The snapshot-drift check keeps end-to-end coverage via its `mcp` and `agents` cases.

**Precondition (already satisfied):** [#128](128.md) merged (PR #130) flipped `mcp` to `match` (strict-mcp empty-state); `picker` was the sole remaining red. After this removal the aggregate `snapshot-drift` check is green on `main` and would pass on a clean CI runner.

## Patterns established

- **Drop the e2e case when the fixture is irreducibly host-dependent — but keep the parser covered by host-independent unit fixtures.** This is the deliberate *inverse* of [#128](128.md)'s "recognise the empty-state, don't drop the case", and the split between the two siblings is principled, not arbitrary:
  - #128 found a **host-portable shape to anchor** — `/mcp` under `--strict-mcp-config` renders an identical empty-state on every host, so a live e2e drift signal could be preserved.
  - #129 found **none exists** — the picker render is coupled to the operator's local plugin/skill set, and three candidate discriminators all fail host-portability (see Lessons learned). When a live e2e signal genuinely *cannot* be made host-portable, drop it from the e2e gate rather than re-commit operator-specific state. Coverage migrates to `.bin` unit fixtures, which **are** host-independent (raw captured bytes fed into the parser, not a live capture against the operator's environment).
- **Resolve the dead protocol-whitelist alternation, not just the table entry.** The ticket's Technical Notes said "no change to `parseSnapshotResults`" — true of the *function body* (generic path-derivation), but `snapshotResultRe` is a separate package-level var: a whitelist of names the protocol can emit. After the table entry is gone the binary can never emit `SNAPSHOT picker …`, so the `picker|` alternation is dead — functionally inert but a misleading stale enumeration a future reader would read as "a picker fixture still exists." The architect ruled to remove it (a 7-char deletion entailed by the same logical change, not adjacent refactoring). Lesson for reading "leave X alone" notes: distinguish the function *body* from a sibling *enumeration var* that names the same dropped entity — the latter still needs to follow.

## Lessons learned

- **Spec #81's picker Open Question is now resolved with a negative result: there is no host-portable built-in-vs-plugin discriminator on claude 2.1.158.** All three candidates were tested live (PTY capture of the `/` picker) and failed:
  - **`category` presence — unsound.** Operator skills (`/code-review`, `/walkthrough`, `/dependency-graph`, `/logo-creator`) all render with an **empty** `category`, identical to built-ins like `/agents`; only `/figma-use` carries one. So `category` can't separate built-ins from skills.
  - **No-plugin / scoped capture — no flag yields a built-ins-only picker.** `--disable-slash-commands` opens 0 rows (kills the feature); `--setting-sources project` and `--bare` both still surface operator skills (skills resolve from `~/.claude/skills` regardless); a clean-`HOME` capture would strip skills but breaks local subscription auth.
  - **Built-in-name allowlist — fails on the scroll window.** Operator skills occupy the top rows and push built-ins down, so the captured built-in *subset* differs operator-vs-CI. Stabilising it needs full-list capture via picker scrolling, which is explicitly **not** a library primitive (deferred loop 4 D-3) — far beyond this ticket.
  Future tickets should not re-investigate scoping-to-built-ins without a *new* claude-side affordance (a real built-ins-only flag, or full-list picker scrolling promoted to a library primitive).
- **An e2e fixture that embeds the operator's environment is a latent host-dependence bomb.** `picker-snapshot.json` passed when first recorded only because it matched the recorder's plugin set; it went red the moment the operator's plugins changed, and would have been red on day one on a clean CI runner. Same shape as [#128](128.md)'s "a fixture captured against a fast-moving upstream is a snapshot of that version, not a contract" — except here the volatile input is the operator's local plugin/skill set, not the claude renderer version. The `--strict-mcp-config` seam neutralises MCP/renderer host-dependence for the `mcp` case; nothing analogous exists for the picker's plugin coupling, which is exactly why dropping was the only portable option.
- **The exact-equal parsed-shape policy (#72/#81) was *not* relaxed to "rescue" the picker case.** Whitelisting the volatile picker rows would have been the #72-rejected subset-matching failure mode dressed up. Removing the case keeps the policy load-bearing for the fixtures that remain.
