# #243 — busy predicate recognises the dot spinner frame, shape-bound to the spinner row

## Summary

`busyInRegion` (`state.go`) — the single predicate behind `IsIdle`/`IsThinking`
— gained a third, independent anchor: `dotSpinnerRe`, an anchored per-row regex
matching claude's plain middle-dot thinking frame (dot at row start, verb,
ellipsis) over the same bottom `statusRegionRows` window the spinner-glyph and
`InterruptHint` anchors already scope to. This is a sixth thinking frame the
five `spinnerGlyphs` sparkles miss; on long turns claude also swaps the
`InterruptHint` row for a rotating tip line, leaving the dot frame as the only
busy anchor on those frames. Hand-run per-frame census over the two named
recordings (commit message, not committed as a file): busy rising edges
764→275 and 209→122; frames with no busy anchor 20.7%→6.8% and 20.7%→10.8%.

Same shape-over-literal move as #219 (trust) and #242 (permission), ported to
the busy/idle axis instead of modal classification: the dot is deliberately
**not** added to `spinnerGlyphs` as a bare glyph, because claude renders the
identical middle dot as an in-region separator elsewhere in the bottom chrome
(`mcp_banner.go`, the class-C spinner's token-count parenthetical) — a bare-dot
anchor would hold busy true at idle and break `isIdleGrid`'s "❯ present AND not
busy" conjunction. The row-start anchor and the region scope are independently
load-bearing, mirroring `busyInRegion`'s existing "must never reintroduce a
`StripANSI` whole-buffer path" invariant. Not `security-sensitive` (architect's
call): a forged busy read delays a keystroke or adds a noise edge, it routes no
grant/answer keystroke, unlike the modal-class chain #242 closed.

## Patterns established

- **Shape-gate family now spans two axes.** #219/#242 shape-gated *modal
  classification* (a structural co-signal beyond the anchor phrase); #243
  applies the identical discipline — anchor + shape, never a bare literal — to
  the *busy/idle* axis. The recipe generalizes: identify the forgeable bare
  anchor, find the shape that only the real frame satisfies (here: dot leads
  the row, not merely appears in it), express it as an anchored regex over a
  single rendered row (`^`-anchored, mirroring `modalOptionRe`'s idiom), wire it
  as one more OR arm in the existing single predicate, extend the existing
  forgery test rather than adding a new one.
- **`Grid.LastRows` for anchored per-row shape, `ContainsInLastRows` for
  substring.** The existing two `busyInRegion` anchors use
  `ContainsInLastRows` (unanchored substring); the new one needs
  `LastRows(statusRegionRows)` + a per-row anchored regex because the shape
  requires row-start anchoring that a substring scan can't express. Both
  helpers share the same region bound (`statusRegionRows`), so the "region
  scope lives in exactly one place" invariant holds even though the two
  anchor *kinds* use different `Grid` accessors.

## Lessons learned

- **Spec's open question resolved by dropping the tolerance, not keeping it.**
  The architect's recommended regex was `^\s*\x{00b7}\s+\S.*\x{2026}`, with an
  explicit open question to "drop `\s*` if the extracted frame renders at
  column 0." The shipped regex is `^\x{00b7}\s+\S.*\x{2026}` — no leading
  `\s*` — confirming against the extracted fixture that the dot renders at
  column 0, same as the `✻` sparkle spinner. Tighter anchor, per the spec's own
  guidance for that outcome.
- **Residual uncovered-frame fraction is nonzero, not a regression.** The
  hand-run census dropped uncovered mid-turn frames from ~21% to 6.8%/10.8%,
  not to zero. The ticket's AC asked for "near zero," and the architect's
  design note only guarantees the dot frame *and* the two pre-existing anchors
  are covered — some other claude chrome state (not investigated by this
  ticket) still slips through on a real fraction of frames. Not a regression:
  it's the same shape of residual `#242`'s corpus-replay evidence left as
  hand-run-only, not a CI gate. Worth flagging to PO as a possible follow-up if
  the remaining ~7-11% matters to a future consumer.
- **Self-reference discipline held again.** Same "hand-run outside the
  pipeline" warning as #219–#227 and #242 (discussing a detector's own literal
  anchor on screen risks forging the very state being fixed). Source comments,
  the spec, and the commit message all reference the dot/verb/ellipsis shape by
  description or byte escape (`\x{00b7}`, `\xc2\xb7`), never the rendered
  literal — consistent with the established convention.
