# #252 — retire the obsolete `/mcp` snapshot-drift case (last surviving fixture)

[Issue](https://github.com/pyrycode/tui-driver/issues/252) · [Spec](../../specs/architecture/252-retire-snapshot-drift-mcp.md) · Split from [#250](https://github.com/pyrycode/tui-driver/issues/250) · Siblings: [#251](251.md) (probe-cwd-encoding de-gate), #253 (spike-permission) · Precedent: [#129](129.md) (dropped `/picker`), [#178](178.md) (dropped `/agents`) · Feature doc: [e2e harness](../features/e2e-harness.md)

## Summary

`snapshot-drift`'s last surviving fixture (`mcp`) had been un-satisfiable on a clean runner since [#223](https://github.com/pyrycode/tui-driver/issues/223) (commit `2411344`), which deliberately removed `anchorMCPEmptySpaced` so the strict-mcp empty-state (`⎿ No MCP servers configured…`) classifies `ModalClassUnknown` — idle, not modal, correctly and on purpose (pinned by `TestDetectModalClassMcpEmptyIsIdleNotModal`, `IsIdle(mcp-empty-snapshot.bin)`, and the mcp-empty ready test). With the empty-state no longer classifying `ModalClassMCP`, `spike-multiselect` writes no `.parsed.json` sidecar, so `e2e-snapshot-check` degrades to a missing-sidecar diff regardless of the committed `mcp-snapshot.json` value. No fixture value could make the check green: the alternative populated `computer-use` picker render is host-dependent (breaks #128's host-independence contract) and still produces no sidecar on a clean runner where the empty-state renders.

This ticket **retires the check** rather than re-recording or touching the classifier — `mcp` was the sole fixture left after #129 dropped `/picker` and #178 dropped `/agents`, so retiring it retires the whole `snapshot-drift` check (the last domino). `modal.go` is untouched; #223's decision stands.

Deletion-dominated, no net new production code:

- `pkg/tuidriver/testdata/mcp-snapshot.json` deleted (`git rm`).
- `cmd/e2e-snapshot-check/` (dir: `main.go` + `main_test.go`) deleted — the single-fixture check binary.
- `cmd/e2e-runner/main.go` — removed the `snapshot-drift` `Check{}` entry, `snapshotResultRe`, `parseSnapshotResults`, `snapshotDriftTimeout`, and the entire `OnComplete` field + its `runCheck` invocation block (its sole consumer was snapshot-drift). `Kind`'s doc-comment enum dropped `"snapshot"`. `NonGating` and `OnFailure` are untouched — both are used by `probe-first-prompt-hang` and `probe-cwd-encoding` ([#251](251.md)); the PO's ticket-body framing of them as "snapshot-drift-only plumbing" was a misnomer the spec called out explicitly.
- `cmd/e2e-runner/main_test.go` — `TestParseSnapshotResults` deleted (tested the deleted function); replaced with `TestBuildChecksExcludesSnapshotDrift`, a ~10-line deterministic guard asserting `buildChecks(...)` returns no `Check` with `Name == "snapshot-drift"` or `Binary == "e2e-snapshot-check"`.
- `Makefile` — `CHECKERS := e2e-snapshot-check` and its expansion into `ALL_BINS` removed; the `rerecord-snapshots` target + its `.PHONY` entry removed.
- `claude-version.lock` — **not edited.** No re-record occurred; `claude --version` still reports `2.1.199` (the string #178 pinned). The `version=` bump convention (#47/#57) applies only to deliberate fixture re-records, not deletions.

Verified claude-free: `make check` (vet + race tests) green, retained `.bin` unit coverage (`mcp-snapshot.bin` → `ParseMcpStatus` `TotalServers==10` + `DetectModalClass==ModalClassMCP` + the #221 forgery positive control; `mcp-empty-snapshot.bin` → `Unknown`/idle) passes, `make build-bin` succeeds, and `buildChecks`'s list contains no `snapshot-drift` entry — no live `claude` capture required for any of it.

## Patterns established

- **"Retire the last-domino e2e case" now has three instances** (#129 picker, #178 agents, #252 mcp) — same shape each time: delete the JSON fixture, drop parser/classifier coverage to `.bin` unit tests only, leave the classifier/`modal.go` untouched. #252 differs from its precedents in one respect: it's the terminal instance — no fixtures remained afterward, so the *scaffolding* (the whole check binary, the runner `Check` entry, the Makefile target) came out with it rather than just a table row. When a shared-scaffolding harness loses its last case, retire the scaffolding too rather than leaving vacuous always-pass code.
- **A field shared by two structurally similar-looking checks may only actually serve one.** The ticket body's "the `snapshots[]` / `NonGating` plumbing that only snapshot-drift uses" was wrong — `NonGating` is load-bearing for both probes. Before deleting a field alongside its apparent single caller, grep every other caller; the architect's spec caught this and explicitly called it a landmine.
- **A guard test can satisfy an AC's "verifiable claude-free" clause more durably than source inspection alone.** `TestBuildChecksExcludesSnapshotDrift` is cheap (~10 lines), asserts an absence (unusual but fine here), and prevents an accidental re-add of the retired check — the recommended-but-optional shape from the spec's Open Questions, taken.

## Lessons learned

- **Read the commit message of the change that "caused" the drift before proposing a fix.** The ticket's own PO memory records this: the original architect spec (`feature/252`, `eb82b4c`) assumed a re-record was needed against claude's new built-in `computer-use` MCP server. The developer proved instead — deterministically, from the `.bin` fixture, no live `claude` needed — that #223's classifier change (not a claude-side render change) was the actual cause, and that #223 was *correct*, not a regression. The fix flipped from "re-record" to "retire" only after that re-diagnosis. See `mcp-snapshot-builtin-computer-use` memory.
- **`make e2e not run` claims in an earlier ticket can be wrong even when well-intentioned.** #223 asserted its own change wouldn't affect `make e2e` because "the snapshot check only re-derives mcp, already pinned" — but that assumption didn't account for the sidecar-write precondition (`DetectModalClass` must classify `ModalClassMCP` for `spike-multiselect` to write `.parsed.json` at all). A classifier change that looks locally scoped can silently break a downstream check that depends on its *output shape existing*, not just its content.
