# #81 — snapshot-drift: byte-compare → parsed-shape JSON compare

[Issue](https://github.com/pyrycode/tui-driver/issues/81) · [Spec](../../specs/architecture/81-snapshot-drift-parsed-shape.md) · [PR #96](https://github.com/pyrycode/tui-driver/pull/96) · Supersedes [#72](https://github.com/pyrycode/tui-driver/issues/72), [Spec 35](../../specs/architecture/35-snapshot-drift.md) · Code: `cmd/e2e-snapshot-check/`, `cmd/e2e-runner/`, `pkg/tuidriver/testdata/*.json`, `Makefile`, `claude-version.lock`

## Summary

Retires the byte-compare model in `cmd/e2e-snapshot-check` and replaces it with a parsed-shape JSON comparison. For each of the three fixtures (`picker`, `mcp`, `agents`), the check binary now invokes `spike-multiselect` (unchanged), reads the `<dump>.parsed.json` file the spike already writes alongside its raw `.bin` dump, and compares the JSON tree against a committed fixture at `pkg/tuidriver/testdata/<name>-snapshot.json`. Equality is `reflect.DeepEqual` over `json.Unmarshal`'d `any` trees — survives incidental whitespace and map-key reordering, exact-equal across every parsed field.

The renderer-byte volatility that killed [#72](https://github.com/pyrycode/tui-driver/issues/72) (Try-line rotation, bimodal whitespace-clear passes) is fully absorbed by the parsers themselves: those bytes never reach a `PickerItem` / `McpServer` / `Agent` field. Five back-to-back captures during #72 produced identical 14-item parsed lists regardless of which byte-level volatility fired. The parsed shape is stable where the byte stream is not.

New `-record` flag on the check binary overwrites the committed JSON fixtures with freshly-captured parsed output — the maintainer reviews the diff with `git diff` before commit. Surfaced as `make rerecord-snapshots` (PHONY, not invoked by `make e2e`). The check binary unconditionally sets `TUIDRIVER_STRICT_MCP_CONFIG=1` on every spike-multiselect child so re-recorded fixtures don't leak operator MCP-config paths.

`cmd/e2e-runner/main.go` change is one line: `parseSnapshotResults` now emits `pkg/tuidriver/testdata/<name>-snapshot.json` in the report's `file:` field. The `snapshotResultRe` regex is unchanged — `recorded` is the third stdout verb but only appears in operator-driven (not runner-driven) invocations.

Three committed JSON fixtures live alongside the existing `.bin` files; both coexist in `testdata/`. The `.bin` files stay because five unit tests in `pkg/tuidriver/` consume raw PTY bytes (picker_test.go, mcp_test.go, agents_test.go, grid_test.go, modal_test.go) — they cannot consume `.json` (the JSON is the parser's *output*, not its *input*). The architect overrode the ticket AC's "delete the .bin files" wording on that ground.

`claude-version.lock` bumped from `2.1.144` to `2.1.150` to match the developer's host at fixture-capture time, per [spec 64](../../specs/architecture/64-claude-version-lock-policy.md)'s "fixture re-record is a `version=` bump trigger."

Spec 35 superseded in place with a one-paragraph header pointing at [spec 81](../../specs/architecture/81-snapshot-drift-parsed-shape.md); the byte-compare design is retained as historical context.

## Patterns established

- **Reuse the spike's already-written parsed-JSON dump; the check binary never imports `pkg/tuidriver/`.** `cmd/spike-multiselect/main.go:274` writes `<dump>.parsed.json` next to the raw `.bin` after running the appropriate parser. The check binary scrapes the spike's `picker-snapshot path=<file>.bin` stderr log line (same regex as before) and computes `parsedPath := strings.TrimSuffix(dumpPath, ".bin") + ".parsed.json"`. This preserves the #34 invariant that the runner+checkers don't import library packages — orchestration only, library re-derivation is the spike's job. Future structural checks should follow the same shape: have the capture binary emit its observation as a JSON sidecar, scrape the path from stderr, deep-equal in the check.
- **`reflect.DeepEqual` over `json.Unmarshal`'d `any` trees is the canonical JSON shape-compare in Go.** Don't compare normalised marshalled bytes — Go's `encoding/json` round-trip through `any` is map-keyed, and map iteration order is not guaranteed identical across runs. Unmarshal both sides to `any`, deep-equal the trees. Slice order is preserved (load-bearing for `picker`'s render order); map keys compare structurally regardless of encoding order.
- **Exact-equal across the entire parsed struct; no field whitelist.** All fields (`PickerItem.{command, category, description, highlighted}`, `McpStatus.{total_servers, categories[...]}`, `AgentList.{tabs, current_tab, items, empty_text}`) are load-bearing — a description change is a real drift signal; a `highlighted` shift is structural; a tab reorder is structural. Subset-matching is premature concession. **If a fixture starts diffing intermittently, escalate to the parser, not the comparison policy.** Non-deterministic parsed shape means non-deterministic parser input filter — a regression worth surfacing. File a separate ticket; don't relax the comparison.
- **`-record` flag colocated with the check, not a separate binary.** Same fixture table, same invocation surface, same env (`TUIDRIVER_STRICT_MCP_CONFIG=1`). Eliminates an entire class of "I re-recorded with the wrong settle / wrong trigger / wrong env" failure modes. The `make rerecord-snapshots` PHONY target is convenience over `bin/e2e-snapshot-check -record` — both reach the same code. Future maintainer-driven sweeps over fixture data should follow this shape (one binary, one flag, one Makefile target) rather than scattering scripts.
- **`recorded` is a third stdout verb in the snapshot-protocol, deliberately segregated from `match`/`diff`.** The runner's `snapshotResultRe` only matches `(match|diff)`; `-record` lines are visible to humans but invisible to the report. Keeps the report a faithful description of the read-only check; the record-mode is operator-driven and doesn't need report representation.
- **Architect override of AC scope when verbatim compliance breaks unrelated unit tests.** The ticket said "delete the `.bin` fixtures"; the architect's spec § "Architect decision: keep the .bin files" calls out the five `pkg/tuidriver/*_test.go` sites that consume them, explains why JSON cannot substitute (output ≠ input), and ships the override. Documented in the spec so the deviation from AC is auditable. Generalizable: when AC says "delete X" and X has cross-cutting consumers, the architect's job is to scope downward visibly, not to comply silently or escalate.
- **The strict-mcp env-var seam is the reproducibility safeguard for fixtures.** The check binary sets `TUIDRIVER_STRICT_MCP_CONFIG=1` in `cmd.Env` on every spike-multiselect child unconditionally — idempotent when `make e2e` already set it (the runner does), load-bearing for `bin/e2e-snapshot-check -record` run directly. Without it, operator MCP config would leak into `mcp-snapshot.json`'s `categories[].path` field and the fixture would diff across hosts. Same env-var-as-seam pattern as `EnsureClaudeEnv` uses for `--strict-mcp-config`, `--model`, `--effort`.

## Lessons learned

- **The byte-compare model had unbounded latent volatility — every fix exposed the next layer.** #72 captured this exhaustively (Try-line rotation, bimodal whitespace-clear pass) and salvaged a normaliser approach that died on the determinism check. The architectural takeaway: when a stochastic renderer keeps producing fresh whack-a-mole, comparing what the screen *means* (parsed structure) is right; comparing how it's painted (bytes, even normalised) is wrong. The parsers were already deterministic over the same captures — the inversion was in the check binary discarding the parsed shape and byte-comparing the raw dump instead. Lesson for future fragile-fixture problems: if a deterministic projection of the input exists, compare projections, not inputs.
- **The fix was small because the plumbing was already in place.** `spike-multiselect` had been writing `<dump>.parsed.json` since #72's investigations (log lines `parsed-json path=<path>` at L299/L323/L340). The check binary was discarding that file and re-reading the `.bin` for byte-compare. The total diff is ~50 LOC in `cmd/e2e-snapshot-check/main.go` + three small JSON fixtures + a one-line runner update + a one-paragraph supersession on spec 35. When a redesign feels expensive, look for the projection your code is already computing and throwing away.
- **Keeping the `.bin` files was the right call, even though AC said delete.** Five unrelated unit tests would have broken; their reads are `os.ReadFile("testdata/<name>-snapshot.bin")` into raw bytes feeding into `ParsePicker` / `ParseMcpStatus` / `ParseAgentList` / `DetectModalClass` / `RenderMcp`. Deleting the bytes would have required either deleting the tests (loss of coverage) or embedding hand-crafted byte fixtures in `_test.go` (out of scope, churn). The architect-stage decision was the correct scope cut; the developer didn't have to re-route through PO. If a future cleanup wants the `.bin` files gone, that's a follow-up bundling either deletion or embedded byte fixtures.
- **`Categories: null` vs `[]` was a real open question that empirical capture resolved.** The architect's spec flagged it as Open Question 1 (Go marshals nil slices as `null`; `[]` if the parser ever explicitly empty-initialises). First `-record` capture against claude 2.1.150 produced `total_servers: 1` with a single "Built-in MCPs" category containing `computer-use` (status `disabled`) — neither null nor empty. Claude 2.1.150 surfaces the disabled built-in MCP even under `--strict-mcp-config`, which #72-era empirical work hadn't observed. The exact-equal comparison absorbs whatever shape claude actually renders; the spec correctly didn't predict the value. **Lesson: when a parsed-shape fixture has ambiguous null/empty semantics, the right move is `-record` and commit what claude actually produced, not desk-check the parser.**
- **Picker fixture re-record had to wait on #90's structural-anchor + RGB classifier fix.** The picker parser used to depend on the SGR colour-code encoding (`\x1b[38;2;…m` form); claude 2.1.150 rendered some plugin commands with truncated/transformed RGB sequences that broke the regex. #90 promoted the parser to structural anchors + parsed-RGB highlighting detection, decoupling it from the specific encoding. Without #90 on `feature/81`, `ParsePicker` against current claude would have produced a degenerate item list — re-recording would have committed garbage. The merge of main into `feature/81` brought #90 in, and the picker fixture re-recorded cleanly. **Lesson: when a structural-comparison check depends on parser quality, make sure the parser's structural-decoupling work is on the branch before re-recording — otherwise you commit the parser's pre-fix interpretation as ground truth.**
- **The architect-stage spec absorbed the AC override visibly; the developer didn't have to re-route.** Spec § "Architect decision: keep the .bin files" is a worked example of "architect overrides AC scope downward, documents the reasoning, ships." The dispatcher pipeline survived the deviation cleanly because the override was a spec artifact, not a hidden developer-stage call. Future architects: when AC reads "do X" and X breaks unrelated things, write the override into the spec rather than escalating to PO — but make it auditable. The override is a feature of the agent, not a bug.
