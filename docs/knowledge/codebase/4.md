# #4 — fix(spike): make `thinking-detected` optional in the state machine

[Issue](https://github.com/pyrycode/tui-driver/issues/4) · [Spec](../../specs/architecture/4-thinking-detected-optional.md) · Code: `cmd/spike-one-turn/main.go`

## Summary

Removed the spinner-gate that blocked the spike from progressing past `prompt-written` whenever the `✻ <verb> for <Ns>` regex never matched. The standalone `waitUntil(...)` thinking-gate that previously sat between `prompt-written` and the BOTH-wait loop is deleted. Spinner observation is now opportunistic, folded into the existing termination loop alongside the JSONL channel receive. Termination requires only that an `end_turn` event has been dequeued; `thinking-detected` and `spinner-gone` fire iff the spinner regex matched at some point during the turn. A `thinkingObserved && !spinnerGone` guard preserves slow-path log order (`thinking-detected` always precedes `spinner-gone` in stderr; `end-turn-detected` may interleave).

Doc changes land in the same commit: `cmd/spike-one-turn/README.md` § *Required state log lines* and `docs/specs/architecture/1-spike-one-turn.md` § *State machine* / § *State log lines* both mark the spinner pair as slow-path-only. Watchdog code is untouched — the 30 s freeze branch was already structurally inert on the fast path (`spinnerActive` stays false if `observeSpinner` is never called with `visible=true`), and the 60 s inactivity backstop still applies.

## Patterns established

- **Optional observations live inside the termination loop, not upstream of it.** A separate `waitUntil(...)` for a state that may never arrive will wedge the spike if that state happens to be optional in practice. The cleaner shape is a single termination loop where the load-bearing condition (`gotEndTurn`) is required and any soft signals (`thinkingObserved`, `spinnerGone`) are absorbed as side observations. Future state machines should default to this shape for any PTY-derived signal that is rendering-dependent.
- **Termination condition for "X required, Y optional but ordered before Z when present":** `!(X && (!Y || Z))`. Applied here as `!(gotEndTurn && (!thinkingObserved || spinnerGone))`. The two paths fall out naturally — fast path (`thinkingObserved=false`) terminates the moment `gotEndTurn` flips; slow path (`thinkingObserved=true`) waits for `spinnerGone` as well. No explicit branching needed in the loop body.
- **Slow-path log ordering via a guard, not a sequence point.** `thinking-detected` is guarded by `!thinkingObserved`; `spinner-gone` is guarded by `thinkingObserved && !spinnerGone`. The guard chain enforces the order without ever needing the goroutine to block waiting for one transition before observing the next.

## Lessons learned

- **Newest-by-mtime JSONL discovery breaks when another claude session writes to the same encoded-cwd.** Live verification of this ticket's fast path was blocked because the developer agent's own Claude Code session shares the spike's encoded-cwd (`~/.claude/projects/-Users-juhanailmoniemi-WorkSpace-Projects-tui-driver/`), and the host session's heartbeat-style writes bumped its `*.jsonl` past the spike's freshly-spawned session on every test run. The spike then tailed the operator agent's session file, never saw an `end_turn` for "What is 2+2?", and ran out the 60 s inactivity watchdog. The ticket-#3 discovery heuristic is correct for the "fresh claude in a quiet cwd" case but is racy in any cwd where another long-running claude is already active. Follow-up: the spike should pin its session by session-id (read from claude's stdout banner, or pass `--session-id <uuid>` if supported) instead of relying on `max(mtime)` — file a separate ticket; not in scope here. Operator verification path: run the spike outside any active Claude Code session in this cwd, or against a scratch cwd, then fill in the README's *Observed timings* table with the new fast-path row.
- **Concurrency-model verification doesn't always need a green run.** The change is a localized restructure: delete one block, expand the variable set of another block, modify its termination condition and ticker case. `go build` clean + `go vet` clean + the slow-path log-ordering guard chain are sufficient evidence the code is correct, given the watchdog math (no false-positive on the fast path; backstop still trips if JSONL hangs). The verification block in the spec asked for an empirical fast-path run, but the empirical blocker (above) is structurally unrelated to this ticket's change.
- **The spinner regex / ANSI strip bug (finding #8) is now decoupled from happy-path progress.** Before this ticket: a missing `thinking-detected` wedged the spike. After this ticket: the slow path is dormant until the regex / strip is fixed, but the fast path runs through every turn. When finding #8 is independently fixed (separate, smaller ticket), the slow-path branch will start firing and producing verb captures with no further code change here.
