## Summary

New `cmd/corpus-label` leaf CLI: a resumable, subscription-login labeling queue
over `corpus-sampler`'s output JSONL. Each sampled screen gets exactly one label
from a judge **independent of the structural detectors** — a headless `claude -p`
reading the raw grid, never a call into `pkg/tuidriver`'s own classifiers — plus a
free-text `unusual: <description>` escape hatch for situations no enum value
covers (the dot-frame spinner gap #243 was found exactly this way, by reading
frames rather than by any detector).

Split along the seam the architect named: `queue.go` (pure, deterministic —
decode, resume filter, priority order, batching, JSONL persistence, no
subprocess) versus `label.go` (spawn `claude -p`, prompt build, env scrub,
parse/validate, retry-once/park). `main.go` wires flags and the sequential
persist-or-park loop.

- **Resume**: selection skips any input hash already present in `-out`, and
  de-dupes within the run (first wins) — each hash queued at most once. Labels
  flush **per batch** (`appendLabels`, `O_APPEND` + explicit `Flush`), so a
  mid-run kill loses at most the in-flight batch.
- **Priority**: three stable tiers — `source` contains `"fires"` (#273, not yet
  merged; graceful no-op today) → `tag == "err"` → the rest. Highest tier wins
  (a fire sample is never also placed in err).
- **Taxonomy**: built at startup from live `tuidriver.ModalClass` constants
  (`taxonomyLabels()` in `label.go`) plus five package-local labels each mapped
  in a comment to the library concept it names (`idle`→`IsIdle`,
  `busy`→`IsThinking`, `mcp-failure`→`HasMcpFailureBanner`,
  `network-failure`→`HasNetworkFailure`, `startup`→`Readiness` pre-first-prompt
  family). `ModalClassAgents` (retired #245) and `ModalClassUnknown` (empty
  string) are excluded. A label is valid iff in the taxonomy set or prefixed
  `unusual:`.
- **Billing safety**: `scrubEnv` **removes** (not blanks) `ANTHROPIC_API_KEY`
  from the child's env — its presence would flip the subscription login to
  metered billing. Confirmed positively-tested (see Lessons).
- **Re-pass mode**: `-model` ≠ `haiku` (the AC's single coupled flag, not a
  separate `-repass` bool) switches selection to existing `-out` records with
  `Confidence < -min-confidence` or an `unusual:` label, and switches
  persistence from per-batch append to per-batch full-file rewrite
  (`rewriteLabels`, keyed merge over all records) so re-pass stays resumable
  too.
- **Park**: malformed model output (bad JSON, hash mismatch/omission, invalid
  label or confidence) retries the same batch once; still malformed →
  `parkRecord{Hashes, Raw, Attempts:2, Model}` appended to `-park`, run
  continues. Parked screens are never written to `-out`, so a later run
  re-attempts them.
- Sequential, no goroutines — deliberate departure from `corpus-replay`'s
  (#260) worker pool: the subscription login is a single serialized resource,
  and resume correctness wants ordered, flush-per-batch persistence that a
  parallel pool would break.

Realized size ~714 prod LOC (queue.go 291 + label.go 257 + main.go 166),
comfortably inside the corpus-replay envelope — no split warranted, confirmed
in code review.

## Patterns established

- **Positive-only billing-invariant test.** The env-scrub test needs no
  negative control: the fake `claude` (TestMain re-exec) exits non-zero if
  `ANTHROPIC_API_KEY` survives into its child env, so a passing "batch labeled,
  not parked" assertion *is* the proof the scrub worked — a broken scrub fails
  loudly via park, not silently. Any future subprocess-env-hygiene invariant in
  this repo should reach for this shape over toggling the scrub off to prove a
  negative.
- **`SCREEN-HASH:` marker + TestMain re-exec fake binary**, same idiom as
  `corpus-replay`'s table/fixture tests: `-claude` is the injection seam (test
  sets it to `os.Args[0]`), a marker env var switches the re-exec'd binary into
  fake-claude mode, and per-scenario knobs ride further env vars (which
  themselves pass through `scrubEnv` untouched — it only strips one key).
- **No `testdata/` fixtures for this tool.** Tests synthesize sampler-shaped
  JSONL directly in `t.TempDir()` at runtime rather than committing `.jsonl`
  fixtures — there is nothing to gitignore/negate here (contrast #255's
  `!cmd/corpus-sampler/testdata/*.cast` negation). Reach for this when a
  fixture is cheap to construct in-code and carries no binary/ANSI payload.
- **Confidence field can't express "absent" as a bare `float64`.** A response
  object omitting `confidence` unmarshals to `0.0`, which passes `validConfidence`
  — accepted as a safe degradation (a confidence-less screen just gets swept up
  by a later re-pass) rather than upgraded to `*float64` + nil-check. If a
  future taxonomy field needs a real presence/absence distinction, use a
  pointer type from the start rather than retrofitting.

## Lessons learned

- Code review (PASS, 3 NITs, none blocking): the confidence-omission gap above;
  `rewriteLabels`' truncate-then-write window in re-pass mode is not made
  atomic (temp-file-then-rename) because the realistic interruption
  (subscription cap) manifests during the `claude` spawn, not the local
  rewrite — evidence-based, not built; child `claude` stderr is
  `io.Discard`ed, so a login/misconfiguration failure parks with only
  `"exit status 1"` and no diagnostic detail — flagged as a minor observability
  gap for a future ticket if it's ever hit in practice, not fixed pre-emptively.
- No native blocker was set for the #272/#273 data-schema soft dependency, per
  the spec's explicit instruction — `source` field is read tolerantly
  (`hasSource` over a possibly-nil slice) so the tool is fully buildable and
  testable today against synthetic fixtures; the fire tier simply populates
  once #273 lands and the operator re-samples.
