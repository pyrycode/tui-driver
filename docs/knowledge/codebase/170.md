# #170 — Bound `Wait` so a grandchild holding the PTY cannot hang it

[Issue](https://github.com/pyrycode/tui-driver/issues/170) · [Spec](../../specs/architecture/170-bound-wait-reader-drain.md) · [PR #214](https://github.com/pyrycode/tui-driver/pull/214) · Commit `ab079a7` (spec `458d920`) · Touches [`session.go`](../../../pkg/tuidriver/session.go) + [`session_signal_other_test.go`](../../../pkg/tuidriver/session_signal_other_test.go) + [`session_test.go`](../../../pkg/tuidriver/session_test.go) · Predecessor: [#38](38.md) (`Wait` drains the reader) · Sibling: [#168](168.md) (process-group kill on `Close`, the `Close`-path twin of this hang)

**XS process-lifecycle/liveness fix.** Not `security-sensitive` (verified on the issue labels) — bounds a wait timer, no attacker-influenceable content classification, no auth/parsing/trust surface. Same class as [#38](38.md)/[#159](159.md)/[#164](164.md)/[#168](168.md)/[#169](169.md). No new type/field/config knob/exported symbol; `Wait`'s signature is unchanged.

## Summary

`Session.Wait` blocked unconditionally on `<-s.readerDone` after `<-s.exited` (`session.go:413-417`). `readerDone` closes only when the PTY reader goroutine's `ptmx.Read` returns, which needs **every** holder of the PTY slave FD to have closed it. When `claude` forks a tool subprocess that inherits the slave FD and holds it open, the master read never returns EOF — so `s.exited` closes (claude is reaped) but `readerDone` never does, and `Wait` blocked **forever** after the process the caller was waiting on had already gone.

The fix replaces the unconditional receive with a two-arm `select` against a bounded timer: `<-s.readerDone` (normal: reader drained) vs `<-time.After(s.shutdownGrace)` (grandchild holds the slave; give up the drain wait). `<-s.exited` stays first and `return s.exitErr` stays last, so on **both** arms `Wait` returns the process's **real** exit error (or nil) — never a substitute/sentinel. The three-part doc comment re-scopes [#38](38.md)'s "final bytes guaranteed visible" happens-before promise to the reader-drained path only; on the timeout path it explicitly no longer holds. The reader goroutine is **not** torn down — it stays parked on `ptmx.Read` until a later `Close()` closes the master and reaps it (which [#168](168.md)'s group SIGKILL also reaps the grandchild).

This is specific to the **natural-exit path** (consumer calls `Wait`, never `Close`). `Close` is structurally immune and untouched: it closes the PTY master (`s.pty.Close()`, `session.go:442`) *before* its own `<-s.readerDone`, forcing the read to return regardless of who holds the slave. Composes cleanly with [#168](168.md) (group-kill on the `Close` path) — disjoint code, no conflict.

## Design

One production method, ~7 lines of body plus a doc rewrite.

```go
<-s.exited
select {
case <-s.readerDone:                  // normal: reader drained the final bytes
case <-time.After(s.shutdownGrace):   // grandchild holds the slave; give up the drain wait
}
return s.exitErr
```

- **`exited` first** for [#38](38.md)'s two reasons: (a) causal order — the reader can't finish before the process exits; (b) `s.exitErr` is written *before* `close(s.exited)` (`session.go:186-187`), so receiving on `exited` first makes the subsequent `return s.exitErr` race-free **independent of `readerDone`** — which is exactly why returning it on the timeout arm is safe.
- **Grace source: reuse `s.shutdownGrace`** (from `ShutdownGrace`; `DefaultShutdownGrace = 3s`), the architect's call. It's already on the session and normalised `> 0` by `Spawn` (`session.go:164-167`), so no zero-grace guard is needed and the timer is always positive/bounded. A dedicated `readerDrainGrace` field + `DefaultReaderDrainGrace` const + `SpawnOpts.ReaderDrainGrace` knob was rejected as public API for an unobserved need (*Evidence-Based Fix Selection*). Accepted coupling: a consumer setting a short `ShutdownGrace` for aggressive `Close` also gets a tight `Wait` drain bound — coherent (both express "how long we tolerate a lingering PTY holder"), and the normal path is unaffected because the reader drains in ms so the timer never fires.
- **Match `Close`'s `time.After(s.shutdownGrace)` idiom** (`session.go:437`) — no `time.NewTimer`/`Stop` bookkeeping. `Wait` is once-per-session; the lingering timer (≤ grace) on the drain arm is negligible, mirroring what `Close` already does.
- **Do not tear the reader down.** Out of scope (ticket Technical Notes) — `Wait`'s timeout only shortens the wait; `Close`/[#169](169.md) reap the parked reader + grandchild.

### Doc comment — three-part re-scope (AC #3)

Rewritten from #38's two paragraphs into: (1) **lead** — blocks until exit, then waits up to a bounded grace for the reader to drain, returning the real exit error on **both** paths; (2) **reader-drained path** — #38's happens-before guarantee (bytes in the rolling buffer / `RecordTo` recording are visible after `Wait` returns, via the `readerDone` close) is retained, scoped here; (3) **bounded-grace path** — if a grandchild holds the slave open the guarantee **explicitly no longer holds**, `Snapshot()`/recording may miss the process's final bytes, and the reader stays parked until `Close`.

## Patterns established

- **Bounding a synchronisation wait is a `select`-against-`time.After(existing grace)`, not a new knob.** When an unconditional channel receive can wedge on a lingering external holder, the XS shape is a two-arm `select` reusing the session's already-normalised grace field — *not* a new config field/const/`SpawnOpts` member. This keeps the change to the method body + doc and inherits `Spawn`'s `> 0` normalisation for free (no zero-guard). Adding the knob is deferred until a consumer is observed needing to decouple the two windows.
- **A bounded return must not change the *return value*, only the *wait*.** The timeout arm returns `s.exitErr` — the real status — exactly like the drain arm; the timer shortens *how long* `Wait` waits, never *what* it yields. This is guaranteed structurally by writing `s.exitErr` before `close(s.exited)` and receiving on `exited` first, so the return is race-free without any dependency on `readerDone`. Re-scoping a happens-before *doc* guarantee is the correct cost of a bounded wait; substituting a sentinel error would not be.
- **Re-scoping a happens-before guarantee means re-scoping *every* doc that repeats it.** [#38](38.md)'s "final bytes visible after `Wait`" promise is echoed in three places beyond `Wait`'s own godoc: `MirrorOutput`'s exported godoc (`session.go:396-397`), the reader goroutine's LIFO comment (`session.go:195-197`), and the `system-overview.md` reader-taps paragraph. `Wait`'s godoc + system-overview were fixed here; the two in-code twins are a tracked follow-up (below). When a contract narrows, grep the phrase — the guarantee tends to be restated near every surface that benefits from it.

## Lessons learned

- **The held-slave hang is Linux-only; Darwin is structurally immune (`revoke(2)`).** On macOS/BSD the kernel `revoke(2)`s the controlling terminal when the session leader exits, forcibly invalidating **every** open descriptor to the slave PTY — even in a surviving, SIGHUP-ignoring, `setsid`-detached grandchild (verified with `lsof`: fd1/fd2 show `(revoked)`). The master then reads EOF, `readerDone` closes, and `Wait` **cannot** hang — the scenario is unreproducible on Darwin, and the test's self-validating precondition would false-*red* there. So the realistic repro `TestWaitBoundedWhenGrandchildHoldsPTY` is guarded `runtime.GOOS != "linux"` (runs on the ubuntu-latest CI gate, skips on the dev's macOS with a documented reason). This is the mirror-image of [#168](168.md)/[#169](169.md)'s "build-tagged file invisible to the darwin gate" hazard — here the *production* code is platform-agnostic but the *realistic behaviour* only manifests on Linux. (Memory `macos-revokes-ctty-slave-on-leader-exit`.)
- **When the realistic repro is platform-gated, add a deterministic unit test so the changed logic is covered on *every* platform.** Beyond the spec, the developer added `TestWaitBoundsReaderDrainAndReturnsExitErr` (`session_test.go`) — a hand-built `&Session{exited, readerDone, shutdownGrace, exitErr}` that drives **both** `select` arms directly (close `readerDone` → returns instantly with the exit error; leave it open → returns within the grace with the *same* real exit error). This covers the exact changed `select` on the Darwin dev gate where the realistic PTY-holder test skips. The code reviewer called this out as the right judgment: a Linux-CI-only behavioural test leaves the changed line unexercised on the machine the developer actually runs `make check` on.
- **The #168-class false-green trap recurs — and the fix is the same self-validating precondition.** The realistic test's grandchild must genuinely hold the slave open; if it didn't (e.g. SIGHUP not ignored), the reader would drain, `Wait` would return fast **even with the bug present**, and the test would silently pass. Defence: a non-blocking `select { case <-s.readerDone: t.Fatalf("precondition broken…"); default: }` **before** the assertion hard-fails if the reader drained early, plus registering `Close` via `t.Cleanup` so it runs *after* the assertion (calling `Close` first would close the master, let the read return, and mask the bug). Leader command `sh -c "trap '' HUP; sleep 300 & echo GC=$!; exit 7"` sets SIG_IGN *before* forking (inherited from birth → no fork-to-trap race) and `exit 7` proves `Wait` returns the real `*exec.ExitError` (code 7), not nil-by-default. An outer 5s guard turns a regression into a fast failure instead of hanging the suite. (Memory `pty-close-sighup-masks-group-kill-tests`, from #168.)

## Deferred / follow-ups

- **`MirrorOutput` godoc + reader LIFO comment still make the unconditional "always observes it already closed" claim** (`session.go:396-397`, `:195-197`) — the same happens-before promise AC #3 re-scoped for `Wait`. On the bounded-grace timeout path `Wait` now returns *before* `readerDone`/`mirrorOut` close, so a consumer that `Wait()`s (timeout) then `range`s `MirrorOutput()` finds the channel still open until `Close`. Flagged **SHOULD FIX** (+ a NIT for the LIFO comment) in the [#214](https://github.com/pyrycode/tui-driver/pull/214) code review; below the fail threshold so the PR PASSed. One-line doc scoping, worth a follow-up ticket to keep the public `MirrorOutput` contract honest on the timeout path. (The `system-overview.md` twin of this claim **was** fixed in this doc pass.)
- **Reader-teardown on `Wait` timeout** is deliberately *not* done — the parked reader is reaped by a later `Close()`/[#169](169.md) `Pdeathsig`, within `Session`'s existing "caller MUST defer `Close`" contract. Only build it if an observed consumer leaks sessions it never closes.
