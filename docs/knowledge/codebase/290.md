# 290 — TailJSONL resolves its baseline offset against its own fd

**Ticket:** [#290](https://github.com/pyrycode/tui-driver/issues/290) · **PR:** #292 (78db474) · **Size:** S · **Security-sensitive:** no · Split from #289 (sibling [#291](https://github.com/pyrycode/tui-driver/issues/291) is blocked-by this ticket)

## Summary

`TailJSONL(ctx, path, startOffset int64)` (`pkg/tuidriver/jsonl.go`) previously seeked to a caller-precomputed `startOffset` measured against a *foreign* fd (typically an earlier `os.Stat` in the caller). That's a cross-fd TOCTOU — the file can rotate or truncate between the caller's stat and the tail's own `os.Open` — and `(*os.File).Seek` doesn't error when the target exceeds the file's size, so a stale offset silently parked the reader past all content.

The fix inverts ownership of the baseline offset: `TailJSONL` now stats its **own** freshly-opened fd and resolves the start position against that size before seeking:

- `0` → from the beginning (unchanged).
- new exported sentinel `TailFromEnd = -1` → start at the current end of the tail's own fd ("skip existing content, stream only future appends," without the caller measuring size itself).
- any other `startOffset > 0` → clamped to `min(startOffset, size)` — an oversized/stale request lands at the own-fd end, never past content.
- `startOffset < -1` → rejected synchronously with an error (only `TailFromEnd` is a legal negative).

The signature stayed `int64` deliberately — this keeps `Events` (the one production caller, `pkg/tuidriver/events.go`) and all 8 existing tail tests compiling and passing with zero edits, so downstream consumer cutover is a version bump, not a rewrite.

## Patterns established

- **Own-fd size guard, not caller-supplied.** When a function takes an offset/position argument that will be resolved against a file, resolve it against a fd the function itself opens and stats — never trust a position pre-computed by the caller against a separate `os.Stat`/`os.Open`. The stat→seek window on a single fd is not a TOCTOU for an append-only log (the file can only grow under a held fd), so this closes the race without adding locking.
- **Clamp over reject, clamp to the boundary that preserves caller intent.** An out-of-range resume request degrades to the nearest *safe* position rather than failing outright — clamping to `size` (not `0`) preserves the "skip existing content" intent a warm-consumer's oversized/stale offset implies, rather than silently re-reading everything.
- **Sentinel constant for a fd-relative concept a caller can't otherwise express.** `TailFromEnd = -1` lets a caller say "current end of your fd" without doing its own `os.Stat` — the general shape for any API where "resolve against my own state, not yours" needs an escape hatch distinct from the numeric range.
