# #1 — spike: end-to-end PTY drive of interactive `claude` (one turn)

[Issue](https://github.com/pyrycode/tui-driver/issues/1) · [Spec](../../specs/architecture/1-spike-one-turn.md) · Code: `cmd/spike-one-turn/main.go`

## Summary

First code in the repo. Single-file spike that drives one interactive `claude` turn end-to-end through a `creack/pty` pseudo-terminal: waits for the idle prompt, writes `What is 2+2?\r`, watches the `✻ <verb> for Ns` spinner, tails the new session JSONL, treats the assistant event with `stop_reason=="end_turn"` as the turn-terminator, prints `SUCCESS: <text>`, then SIGTERMs `claude` and drains. The deliverable is empirical knowledge — the spike's README (`cmd/spike-one-turn/README.md`) is where verbs, timings, and surprises get recorded on every run.

Validates the architecture decided 2026-05-16 — see [ADR-0001](../decisions/0001-hybrid-jsonl-tui.md) and [ADR-0002](../decisions/0002-pattern-matching-over-emulation.md).

## Patterns established

- **Rolling buffer + on-read ANSI strip for regex matching.** `rollingBuffer` caps at 4 KB by re-slicing on append; matcher applies `\x1b\[[0-9;?]*[a-zA-Z]` strip on-the-fly to the snapshot. Raw bytes still mirror to stderr so a human can watch the spike.
- **State machine as linear sequence of `waitUntil(ctx, predicate)` calls.** No actual state machine type — for one happy-path turn it would have been over-engineered. Each step blocks until its predicate flips or the watchdog cancels the root context.
- **Three-goroutine concurrency shape** (orchestrator + PTY reader + JSONL tailer; watchdog runs on a 1 Hz ticker inside the orchestrator). All coordinated by a single `context.WithCancelCause` and joined via `sync.WaitGroup` in a `defer shutdown()`. This is the shape the eventual `pkg/tuidriver/` is likely to grow from, but the spike does NOT extract it.
- **Idle = `❯ present AND spinner regex does NOT match`** simultaneously. Lone `❯` is unreliable because the TUI redraws the input line below the spinner during thinking.
- **JSONL discovery via pre-prompt directory snapshot, then post-prompt diff.** Snapshot after `idle-detected`, before `prompt-written`; the new file is the one not in the snapshot. No `fsnotify` — 100 ms polling is fine for a spike and avoids a dependency. 5 s deadline for the file to appear.
- **Spinner-freeze watchdog requires *strictly greater* counter readings** while the spinner stays continuously visible. The "continuous visibility" qualifier matters — when the spinner disappears, the freeze tracker resets.
- **Shutdown is one `defer` with a `sync.Once`-guarded body**: SIGTERM → race a 3 s `time.After` against `cmd.Wait()` → SIGKILL if grace expires → close PTY → cancel context → `wg.Wait()`. Runs on every exit path (success, watchdog trip, PTY error).

## Lessons learned

- **Spec contradicted the ticket body in two load-bearing places** and the architect was right to override. Interactive `claude` does NOT emit `type:"result"` — the terminator is `type=="assistant"` AND `message.stop_reason=="end_turn"`. JSONL files live FLAT under `~/.claude/projects/<encoded-cwd>/` with no `sessions/` subdirectory. Both were verified against the operator's local `~/.claude/projects/` before code was written. Lesson for future tickets: when the spec explicitly says "believe this over the ticket body," trust the spec — it has empirical backing.
- **`encoded-cwd` is byte-by-byte substitution, not a normalization.** Both `/` and `.` become `-`, so adjacent `/.` produces `--` (non-reversible). Compute at runtime from `os.Getwd()`; never hardcode.
- **The `result-event-received` log token is intentionally misleading** — kept that exact wording because the AC required it, even though the underlying event is an `end_turn` assistant record, not a `type:"result"` event. The spike's README documents the divergence so post-spike readers don't get confused.
- **Spike binary leaked into git via the code-review auto-commit.** `cmd/spike-one-turn/spike-one-turn` got built then committed by the dispatcher's safety-net auto-commit because `.gitignore` only listed `tui-driver`, not the spike binary name. The `spike-one-turn` 3.7 MB blob now sits at the repo root in commit `032cf26`. Follow-up: add `/spike-one-turn` (or `/cmd/*/<binname>`) to `.gitignore`, and consider building to a dir outside the worktree by default (`go build -o /tmp/spike-one-turn ./cmd/spike-one-turn` is what the README already recommends).
- **Empirical-findings tables in `cmd/spike-one-turn/README.md` are still empty** — the timing table, verb table, and surprises section are placeholders. The spike code was built but the "run it 3+ times and record what you see" step from the spec's *Testing strategy* didn't produce data (or the data wasn't filed back into the README). Whoever runs the spike next should fill these in; they're the actual deliverable of the ticket.
