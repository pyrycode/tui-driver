## Summary

Closes the loop between the triaged corpus and the committed detector-fixture
set (`pkg/tuidriver/testdata/*.bin`). Adds a `-promote` mode to
`cmd/corpus-sampler` (not a new leaf CLI — `package main` can't import another
package main, the same reason #255 copied corpus-replay's helpers) that turns
one sampled screen into a permanent regression pin: a raw-snapshot `.bin`
fixture under `pkg/tuidriver/testdata/corpus/` plus an entry in a committed
`manifest.json` recording the expected per-axis classification (modal class,
busy, idle, mcp-/network-failure, unknown-dialog) and provenance (cast, event
index, hash). One manifest-driven table test
(`pkg/tuidriver/corpus_fixtures_test.go`) then classifies every entry through
the same detector path the existing `.bin` fixtures use — a new fixture needs
zero new test code.

**The core mechanism is reconstruction, not extraction.** The sampler JSONL
persists the *rendered* grid string + its normalized hash, never the raw
buffer bytes the detectors take (`snap []byte`). `reconstructSnapshot` replays
the sample's source cast from scratch — appending every output event to a
fresh `tuidriver.NewBuffer(0)` — and takes `buf.Snapshot()` right after
appending the event at the sample's recorded `Event` index. This single rule
covers every sampler source (gap/fire/midstream/final) because of how
`sampleCast` stamps `Event`: a gap sample's `Event = idx-1` (buffer state
*before* appending `idx`) and a fire/midstream/final sample's `Event = idx`
(buffer state *after* appending `idx`) both reduce to "replay events `0…Event`
inclusive" — promote never needs to know which source produced the sample.
Before any write, the reconstruction is verified against the sample's recorded
hash (`hashGrid(normalize(Render(snap, sample.Cols, sample.Rows)))`); a
mismatch means the recordings dir is stale relative to the JSONL and aborts
with no write.

**Two renders, deliberately different.** The integrity check above renders at
the sample's *stored* `Cols`/`Rows` — it only proves "did we reconstruct the
right frame." The manifest's per-axis verdicts (`computeVerdicts`) are instead
computed by calling the *public detectors directly* on the raw snapshot
(`DetectModalClass`, `IsThinking`, `IsIdle`, the three banner detectors), which
internally render at default dims (`NewGrid(snap, 0, 0)`). The table test
re-runs the identical public detectors on the identical raw snapshot, so
manifest and test agree by construction regardless of the sample's cols/rows —
conflating the two renders was the spec's flagged landmine.

**Idempotency (AC1) is a pure function of the hash.** The fixture basename is
`<hash>.bin` (nothing user-chosen), so re-running promote for the same hash
reconstructs byte-identical bytes. The manifest upsert is skip-not-overwrite:
if an entry for the hash already exists, promote rewrites the (identical)
fixture and leaves the manifest untouched — preserving a human-confirmed axis
value a prior review committed, since the promoter's prefill is only a
convenience.

Seeds (AC3): two hand-eyeballed screens — a plain-idle `❯` prompt and a
plain-text `ask-user-question` modal (lifted from `modal_test.go`'s existing
synthetic form) — generated claude-free by running the tool itself over two
tiny single-frame, ESC-free seed casts, then promoted. The modal seed is
`idle=true` *and* `modalClass="ask-user-question"` simultaneously (the
`❯`-option row sits in the bottom status region the idle detector scans) —
recorded honestly as both, since the axes are independent and AC3 only
requires the recorded values to match the detectors, not that a modal screen
be non-idle.

## Patterns established

- **Sampler-JSONL-to-raw-fixture reconstruction is source-agnostic by
  construction.** Any future tool that needs to turn a sampler sample back
  into detector-consumable bytes can replay `0…Event` inclusive without
  branching on `Source` — the field's stamping convention was already
  source-independent, this ticket just names and uses the rule.
- **A data-contract struct duplicated (not shared) across a `package main` and
  `pkg/tuidriver`, with a doc comment naming the "keep JSON tags in lockstep"
  invariant.** `promote.go`'s `manifestEntry` and
  `corpus_fixtures_test.go`'s `corpusManifestEntry` are two independently
  declared Go structs over the same JSON shape — deliberate per the spec (the
  manifest is consumed as a data artifact, not an imported API), and the
  intended low-risk half of the ticket's "inseparable" size justification.
  Future manifest-file contracts crossing a `package main` boundary should
  reach for this shape rather than inventing a shared import path that can't
  exist.
- **Human-confirmed values win via skip-not-overwrite, not a merge or a
  `--force` flag.** Where a re-run might disagree with a committed value, the
  simplest idempotent rule — "if it exists, don't touch it" — is enough; no
  merge logic needed since the manifest only ever grows one entry per hash.

## Lessons learned

- No deviation from the architect's spec: reconstruction rule, two-renders
  split, idempotency shape, and seed-generation approach were all followed as
  written. `make check` green on the first pass.
- The seed casts (`ask-user-seed-ok.cast`, `idle-seed-ok.cast`) are
  intentionally **not** committed — only the reconstructed `.bin` fixtures and
  the manifest are. `promote_test.go` carries its own in-test synthetic cast
  (`writeSyntheticCast`, ESC-free per the `.cast` fixture-escaping landmine
  noted in [#255](255.md)'s lessons) so the promotion *mechanism* has
  hermetic regression coverage independent of the seed screens themselves.
