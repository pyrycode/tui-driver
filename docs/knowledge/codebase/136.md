# #136 — Sealed local-attach mirror surface: `MirrorOutput` stream + `AttachInput`

[Issue](https://github.com/pyrycode/tui-driver/issues/136) · [Spec](../../specs/architecture/136-sealed-attach-mirror-surface.md) · [PR #137](https://github.com/pyrycode/tui-driver/pull/137) · Feature doc: [features/attach-mirror-surface.md](../features/attach-mirror-surface.md) · Code: `pkg/tuidriver/session.go`, `pkg/tuidriver/keys.go`, `pkg/tuidriver/mirror_test.go` (new)

**Phase 5 / Phase 1 foundation — mobile-remote-head. Governed by consumer-side ADR 025 (`pyrycode/docs/knowledge/decisions/025-mobile-remote-head-interactive-session.md`), open risk #1.** This *is* that load-bearing seam: if it couldn't be made seal-clean, the supervisor → tui-driver migration needed a rethink. It was made seal-clean.

## Summary

Two additive, opt-in `Session` surfaces let a local `pyry attach` head mirror `claude`'s live terminal byte-for-byte without reopening a parse-able seam:

- **Output** — `SpawnOpts.MirrorOutput bool` + `(*Session).MirrorOutput() <-chan []byte`: a live receive-only stream of the hosted process's raw PTY output, delivered as opaque per-chunk copies. A **third tap** on the existing reader goroutine, beside the rolling-buffer append and the `RecordTo`/`MirrorStderr` mirror tee. The reader is the sole sender + sole closer. Non-blocking **drop-newest** at capacity `defaultMirrorOutputBuffer = 256`. Returns `nil` when the opt-in is false.
- **Input** — `(*Session).AttachInput(p []byte) error`: a production raw-input path over the internal `writeRaw`, distinct from the spike-only `SendKeys`.

No existing symbol changed signature; `SendKeys` / `RecordTo` / `MirrorStderr` and the rolling buffer are byte-for-byte untouched. The full surface contract — opaque-bytes-no-parse, the SECURITY notes, the drop policy, and the lifecycle — lives in the [feature doc](../features/attach-mirror-surface.md); this file records the *why* behind the load-bearing choices.

The pipeline ran clean end to end: security self-review PASS (no MUST FIX), QA green (`make e2e` 11/11 + `go build`), code-review PASS (security obligations + concurrency verified, no `needs-rework`).

## Patterns established

- **A third tap on the shared reader goroutine ships as a channel, not another `io.Writer` mirror sink.** The existing tee (`buildMirror`, for `RecordTo`/`MirrorStderr`) is a by-value sink that never escapes the package; folding the attach stream into it would have handed the consumer an `io.Writer`-shaped seam that invites parsing and couples lifecycle. Instead the stream is a separate `<-chan []byte` tapped from the **live PTY read** (before the bytes enter the parse-oriented rolling buffer). This is the template for any future "let the consumer observe raw bytes" need: tap the live read, deliver opaque chunks, keep the rolling buffer un-exported.
- **A best-effort tap on a shared producer goroutine MUST be non-blocking; a lossless tap on a dedicated goroutine MAY block.** This is the load-bearing concurrency rule and the deliberate inverse of [#61](61.md)'s `Events()` block-on-full. The discriminator is *whose* goroutine the send sits in:
  - `Events()` / `TailJSONL()` ([#59](59.md)/[#61](61.md)) block on a full channel (cap 32) — they run on *dedicated* goroutines, so blocking stalls only that one stream, and losslessness is the contract.
  - `MirrorOutput` drops on a full channel (cap 256) — its send is in the **shared core reader goroutine** that feeds the rolling buffer state detection depends on. A blocking send there would (1) freeze idle/thinking/modal detection for every subsequent chunk, and (2) deadlock `Close` (which does `<-readerDone`, never reached by a reader wedged on a send to an absent consumer). Dropping is *correct* for a mirror: a dropped chunk heals on `claude`'s next full repaint.
  - Corollary for buffer sizing: under a **drop** policy, channel depth maps to dropped-frame frequency, not producer-stall duration — a different tradeoff that justifies 256 over `Events()`' 32.
- **LIFO `defer` close ordering gives a free "drain-after-Wait-sees-it-closed" guarantee.** Registering `defer close(s.mirrorOut)` *after* `defer close(s.readerDone)` means `mirrorOut` closes first. Since `Wait()` blocks on `readerDone`, any consumer that calls `Wait()` then drains is guaranteed to observe the stream already closed — no extra synchronization, just `defer` LIFO. Tested explicitly.
- **The per-chunk copy is the single async consumer's obligation, not a global change.** `chunk` aliases the reused 4 KB read buffer; `Buffer.Append` already copies (`append(b.buf, p...)`), and the `RecordTo`/`MirrorStderr` sinks write synchronously within the iteration — so today only the *async* channel path outlives the next `ptmx.Read` and needs `cp := make([]byte, n); copy(cp, chunk)`. Putting the copy at the tap (not earlier) keeps the cost on the opt-in path only.
- **Add a production sibling method rather than re-scope the spike-only escape hatch.** `AttachInput` is a new thin method over `writeRaw` with a production contract; `SendKeys` (and its "not for production" doc + tests) stays verbatim. Renaming/re-scoping `writeRaw`/`SendKeys` would have fanned edits across callers for zero behavioural gain. When a spike-only seam needs a production cousin, add the cousin.
- **A `SECURITY:` doc note is a code-level deliverable, not advisory prose, when a new surface carries secret-bearing bytes.** The security self-review folded two findings into the *contract* rather than leaving them as review comments: (1) `MirrorOutput`'s doc carries a mandatory `SECURITY:` paragraph mirroring `RecordTo`'s (the stream carries file contents + secrets; consumer owns transport confidentiality); (2) the drop branch carries a "NEVER log cp" comment (a debug log would leak that content). Code review verified both are present in the diff before PASS. Pattern: for a security-sensitive ticket, doc-comment security contracts are checked like code.

## Lessons learned

- **The seal held without a single new escape hatch — the existing reader-goroutine tee was the right factoring.** The worry going in (spec / ADR 025 open risk #1) was that a raw-byte stream would force reopening `Buffer`/`PTY`/`Mirror`. It didn't: tapping the live read *before* the rolling buffer satisfies "no parse-able `io.Reader` over the rolling buffer" literally, and the opt-in `nil`-channel keeps the hot loop identical for every non-attach session. The v1.0.0 seal's "tee each chunk to an optional sink" shape generalised cleanly to a third consumer.
- **No new goroutine was needed or wanted.** Reusing the reader goroutine (vs spawning a fan-out goroutine for the channel) is what makes the shutdown story trivial: the channel's lifecycle rides the reader's existing exit (`Close` or process-exit both unblock `ptmx.Read`), closed exactly once in a `defer`. A separate goroutine would have added its own join/close race to `Close`. The non-blocking send is what *lets* the reuse work — it's the precondition that keeps the shared goroutine from ever wedging.
- **The key safety test is "never drain, then `Close` returns promptly," not "bytes arrive."** `TestMirrorOutputSlowConsumerDoesNotWedgeClose` floods the PTY (`yes`) past the 256-cap with the channel deliberately never read, then asserts `Close` returns within 5 s. This is the test that would catch a regression to a blocking send — the verbatim-delivery tests would still pass while `Close` silently deadlocked. When a design's correctness *is* a concurrency policy, the highest-value test exercises the failure mode the policy prevents.
- **Flagged for a future sweep (code-review NIT, out of scope here):** the `Session` struct's leading doc comment (`session.go:104-106`) still claims "The Session exposes the buffer + a Write method" — stale since the v1.0.0 seal removed both (the struct *body* comments at 110-118 correctly state the buffer is unexported and the public `Write` seam is gone). Left untouched per scope discipline; a future doc-sweep ticket should fix it.
- **Pre-existing gofmt drift on `pkg/tuidriver/buffer_test.go` lives on `main`** and is not in this diff — left untouched per scope discipline (flagged in the PR body). Not introduced by #136.
- **`make e2e` was not exercised by this library-only change** — it needs a live `claude` subscription session (operator-run). The relevant gate for a pure-library change is `go test -race ./...` + `go vet` + `go build` (all green); QA additionally ran `make e2e` 11/11 green out of band.
