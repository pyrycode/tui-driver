# #58 — library API: deterministic session JSONL path + appearance poll

[Issue](https://github.com/pyrycode/tui-driver/issues/58) · [Spec](../../specs/architecture/58-session-jsonl-path-resolver.md) · [PR #82](https://github.com/pyrycode/tui-driver/pull/82)

## Summary

Promoted the two stable shapes that every `--session-id`-pinning spike had open-coded — composing `<home>/.claude/projects/<EncodeCwd(cwd)>/<sessionID>.jsonl` and polling `os.Stat` until the file appears — into `pkg/tuidriver/` as `SessionJSONLPath` and `WaitForSessionJSONL`. Both functions live in a single new file `pkg/tuidriver/jsonl.go`; `cwd.go` and `wait.go` are not touched. `SessionJSONLPath` is pure path composition that calls `EncodeCwd` once and `filepath.Join` once — no syscalls of its own, no session-ID validation, no error path. `WaitForSessionJSONL` runs entirely on the caller's goroutine: one short-circuit `os.Stat`, then a `time.NewTicker(DefaultPollInterval)` loop with a `select` on `ctx.Done()`. Non-`os.IsNotExist` stat errors short-circuit the loop (permission and ENOTDIR don't resolve by polling); cancellation/deadline wraps `context.Cause(ctx)` with a path-bearing message so `errors.Is(err, context.DeadlineExceeded)` and `errors.Is(err, sentinel)` both work AND the operator sees the unresolved path in the error. The package doc-comment scope sentence in `tuidriver.go` gained "session JSONL path resolution + appearance polling" between "projects-dir name encoding" and "ANSI/OSC stripping" — single 1-line edit, not a refactor. **Migrating the 7 in-tree spike binaries (`cmd/spike-{long-prompt,one-turn,multi-turn,cancel,permission,ask-user}/main.go`, `cmd/probe-first-prompt-hang/main.go`) and pyrycode's `agentrun.EncodeProjectDir` is deliberately out of scope for this slice** — those are downstream consumers tracked separately ([pyrycode/pyrycode#501](https://github.com/pyrycode/pyrycode/issues/501) for the cross-repo one). This slice ships the library API and its tests; the closing-at-source effect lands when consumers migrate.

## Patterns established

- **Library-extraction template for "open-coded across every spike" shapes: pure helper + context-driven waiter, no new types, single new file.** The two-function shape `SessionJSONLPath(home, cwd, sessionID) string` + `WaitForSessionJSONL(ctx, path) error` mirrors the `wait.go` shape (`DefaultPollInterval` + `WaitUntil`) — one helper that does the work, one waiter that polls for the result. Each function is small enough to be obvious; they compose at the call site (`p := SessionJSONLPath(...); err := WaitForSessionJSONL(ctx, p)`) without needing a struct to carry shared state. The architect explicitly rejected merging them into a single `WaitForSession(home, cwd, sessionID, ctx)` because it forces callers to re-pass home/cwd to the waiter even when they've already composed the path — and because the spike call sites already structure the sequence this way. Reuse posture: when promoting a shape that appears verbatim in N spike binaries, prefer the smallest possible public surface (two free functions, no exported struct) and let the file (`jsonl.go` here) carve thematic space for related future primitives without committing to them upfront.
- **Don't extend a bool-predicate poll primitive when you need error short-circuiting — write the loop directly.** `WaitUntil`'s `predicate func() bool` signature cannot signal "stat returned EACCES, stop polling" — adding an error-returning variant would either fork `WaitUntil` (two near-identical functions) or grow its signature with a returned error from the predicate (every existing call site changes). `WaitForSessionJSONL`'s loop is ~15 lines; writing it directly keeps both primitives simple and lets each have the exact failure semantics it needs. The doc-comment cross-reference (`// Distinct from WaitUntil because stat errors short-circuit the loop`) is the right amount of glue between them. Reuse posture: when adding a new wait helper whose failure mode differs structurally from an existing one (predicate vs stat-error, single-shot vs N-events, etc.), prefer a sibling function over generalising the existing primitive — they share the `DefaultPollInterval` constant and the cancel-cause idiom, which is the only coupling that matters.
- **`context.Cause(ctx)` + path-bearing wrap is the standard error shape for "I gave up waiting on a thing" helpers.** `fmt.Errorf("session jsonl %s did not appear: %w", path, context.Cause(ctx))` gives operators the unresolved path in the error message (so a timeout diagnostic immediately points at the right cwd / session-id) AND keeps `errors.Is(err, context.DeadlineExceeded)`, `errors.Is(err, context.Canceled)`, AND `errors.Is(err, customSentinel)` all working — `context.Cause` returns the underlying cause set by `WithCancelCause`/`WithTimeout`, and `%w` preserves the chain. Reuse this shape for any future tui-driver waiter that times out on an externally-observable resource: path-or-identifier in the message, `context.Cause` as the wrapped error.
- **Non-`IsNotExist` stat errors do NOT retry.** Permission errors (`EACCES`) and "parent is not a directory" (`ENOTDIR`) cannot be resolved by waiting longer — they reflect a configuration mistake at the call site. `WaitForSessionJSONL` returns them wrapped on the first stat call AND on every subsequent ticker stat. The non-IsNotExist branch is intentionally not under test (the AC doesn't require it and the cost of synthesising EACCES in a temp dir varies by platform), but it's a guarantee the contract makes — the function will not silently spin until timeout against a path whose parent has the wrong mode. Reuse posture: filesystem polling helpers should treat "file does not exist" as the only retryable error class; everything else is an immediate fail with the wrap.

## Lessons learned

- **Spec-verbatim implementation works cleanly when the spec names exact function signatures, an error-shape table, and a test matrix.** The architect's spec for #58 included the full doc-comment text for both functions, an explicit table of the three returned-error shapes, the test case list with cwd inputs and expected outputs verbatim, and a § "Why not extend WaitUntil" justifying the structural choice. The developer's job collapsed to typing it in — no mid-implementation design calls, no PR-time back-and-forth on the public surface. Pattern reusable for any future S-sized library promotion: specs that name the signatures + error shapes + test matrix verbatim convert directly into mechanical implementation work and one-shot code reviews. Open questions belong in the spec (the architect's "Should `WaitForSessionJSONL` accept directory + sessionID?" considered-and-rejected note saved the developer from re-deriving the answer).
- **Pre-existing red QA gates can pass code-review without the PR owning the fix.** PR #82 landed with `snapshot-drift` red, identified at QA-time as failing on both `git merge-base HEAD origin/main` (`d958b61`) AND the PR branch — the snapshot-drift fixtures (`pkg/tuidriver/testdata/{picker,mcp,agents}-snapshot.bin`) had drifted against current claude before #82 was opened. Filed as #83. Code-review accepted the PR on the baseline-comparison verdict ("PR did not cause this"). The pattern is right but requires baseline-comparison evidence in the PR review thread, not just a "looks pre-existing" assertion — otherwise the noise hides regressions whose blame chain crosses a merge.
