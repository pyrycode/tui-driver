# #128 — snapshot-drift: reconcile `/mcp` with claude 2.1.158 strict-mcp empty-state

[Issue](https://github.com/pyrycode/tui-driver/issues/128) · [Spec](../../specs/architecture/128-mcp-empty-state-classifier.md) · [PR #130](https://github.com/pyrycode/tui-driver/pull/130) · Split from [#127](https://github.com/pyrycode/tui-driver/issues/127) (sibling [#129](https://github.com/pyrycode/tui-driver/issues/129) = picker case) · Builds on [#81](81.md) · Code: `pkg/tuidriver/modal.go`, `cmd/e2e-snapshot-check/main.go`, `pkg/tuidriver/testdata/{mcp-snapshot.json,mcp-empty-snapshot.bin}`, `claude-version.lock`

## Summary

claude 2.1.158 stopped rendering a "Manage MCP servers" modal for `/mcp` under `--strict-mcp-config`. It now prints an inline empty-state instead:

```
❯ /mcp
  ⎿  No MCP servers configured. Please run /doctor if this is unexpected. Otherwise, run claude mcp --help or visit
     https://code.claude.com/docs/en/mcp to learn more.
```

`DetectModalClass` had no anchor for this text → returned `ModalClassUnknown` → `spike-multiselect`'s `default` branch wrote no `.parsed.json` sidecar → the snapshot-drift check read the missing path and degraded to `diff` with the cryptic `read parsed-json …: no such file`. The committed `mcp-snapshot.json` (1 server, built-in `computer-use`) had become unreproducible — a blind re-record reads the same missing path and fails identically.

The fix is three localised, additive changes plus a re-record:

1. **Classifier (`modal.go`).** Added three anchors and folded them into the existing first-in-switch MCP `case` as an OR: `anchorMCPSpaced` (`Manage MCP servers`), `anchorMCPEmptySpaced` (`No MCP servers configured`), `anchorMCPEmptyStripped` (`NoMCPserversconfigured`). The original no-space `anchorMCP` is retained so the untouched `mcp-snapshot.bin` (full-modal, no-space title) keeps classifying. `ParseMcpStatus` needs **no change** — the empty-state prose doesn't match `mcpTotalServersRe` (`^(\d+)\s*servers?$`) or the category-header regex, so it returns `{TotalServers:0, Categories:nil}`. `spike-multiselect`'s `ModalClassMCP` branch writes the sidecar unconditionally, so the fixture became recordable with **zero spike-multiselect change**.

2. **Spaced-title bug (`modal.go`, AC2).** The full non-strict `/mcp` modal title now strips to the spaced `Manage MCP servers` on 2.1.158, but the only anchor was the no-space `ManageMCPservers` — so a live full-modal capture classified as `Unknown`. `anchorMCPSpaced` fixes this. (The committed `mcp-snapshot.bin` was captured at an older claude where the title stripped to no-space, so the unit test had kept passing against stale bytes — masking the regression.)

3. **Re-record (`mcp-snapshot.json`).** Now `{"total_servers":0,"categories":null}` — exactly what `ParseMcpStatus` yields on the empty-state. Captured under the check binary's unconditional `TUIDRIVER_STRICT_MCP_CONFIG=1`, so it's host-portable: a clean CI runner and the operator box both render the empty-state, and no operator MCP-config path leaks in.

4. **`claude-version.lock`** `version=` bumped `2.1.150` → `2.1.158` (fixture re-record is a `version=` bump trigger per [spec 64](../../specs/architecture/64-claude-version-lock-policy.md)). `flag=`/`value=` lines unchanged — this is a renderer change, not a CLI-surface change.

5. **Diagnosability enrichment (`cmd/e2e-snapshot-check/main.go`, AC5).** On the missing-sidecar read error, `enrichMissingSidecar` scrapes `spike-multiselect`'s `modal-class detected=<X>` stderr line (`modalClassRe = modal-class detected=(\S*)`) and appends `(spike classified modal as "X" and wrote no sidecar — classifier drift, not a content diff)`. Error message only — stdout protocol, control flow, and exit codes unchanged.

Verified outcome (code-review baseline-comparison against `6bec180`): `mcp-snapshot.json` flips `diff`→**`match`** on this branch. The aggregate `snapshot-drift` check stays red **only** because of `picker-snapshot.json`, which drifts on both baseline and PR and is out of scope (sibling #129). Code review: **PASS, no findings.**

Two fixtures, two captures — do not conflate:
- `mcp-snapshot.bin` — **full modal**, 10 servers / 3 categories, non-strict. Unit-test only (`mcp_test.go`, `modal_test.go`, `grid_test.go`). **Untouched here.**
- `mcp-snapshot.json` — **strict-mcp** capture, consumed only by the e2e snapshot-drift check. **Re-recorded here** to the empty-state shape.
- `mcp-empty-snapshot.bin` — **NEW** raw byte fixture: the strict-mcp empty-state, the load-bearing real-fixture gate for the new anchors.

## Patterns established

- **The dual-form anchor convention paid for itself here.** The established convention (every text anchor comes in a space-stripped and a spaced pair, because CSI cursor-forward stripping eats inter-word spaces in *some* renders but not others) meant we committed both `anchorMCPEmptySpaced` and `anchorMCPEmptyStripped` without knowing which the real capture would contain. It turned out the empty-state prose strips to the **no-space** form (`NoMCPserversconfigured`) while the modal *title* strips to the **spaced** form (`Manage MCP servers`) on the same claude version — opposite forms in the same UI. Keeping both forms is cheap belt-and-suspenders that survives this kind of per-element renderer inconsistency. When adding a text anchor, add both forms; don't desk-check which one a real capture will produce.
- **Classifier drift hides behind cryptic capture errors — make the error name the class.** The `read parsed-json …: no such file` message had masked a classifier regression three times (the sidecar is absent because the classifier didn't recognise the UI, not because of a content diff). The fix is the correct belt-and-suspenders fabric: a *deterministic* code enrichment on the *same error path*, not another stochastic rule. `(\S*)` not `\S+` in the scrape regex — `ModalClassUnknown` logs as an empty string (`modal-class detected=` with nothing after), which must be distinguished from "no line at all" (spike crashed before logging) and rendered as `Unknown`. Reusable shape: when a capture binary writes an observation conditionally, scrape *why* it didn't write and surface that in the failure message.
- **Recognise the empty-state, don't drop the case.** The ticket's fallback was to drop the `/mcp` case from snapshot-drift entirely (MCP parser stays covered by `TestParseMcpStatusRealFixture` against `mcp-snapshot.bin`). Instead we kept a **live, host-portable** `/mcp` drift signal by asserting the empty-state claude actually renders under strict-mcp. The empty-state shape `{0, null}` is exactly as valid a drift anchor as the old 1-server shape — the parsed-shape model from [#81](81.md) absorbs the change.
- **Re-record requires the classifier fix to land first.** Under strict-mcp the sidecar is never written until the classifier recognises the empty-state, so `-record` reads the same missing path and fails identically. The classifier change is the load-bearing one; the re-record is downstream of it. `TestDetectModalClassRealFixtures` with the new `{"mcp-empty-snapshot.bin", ModalClassMCP}` case is the deterministic gate — it fails in `go test` (fast) if the anchor form is wrong, before any slow e2e run.

## Lessons learned

- **Spec 81's "built-in survives strict-mcp" premise was empirically false on 2.1.158.** [#81](81.md)'s first `-record` against claude 2.1.150 captured `total_servers: 1` (a disabled built-in `computer-use` MCP surfaced even under `--strict-mcp-config`), and spec 81's Open Question 3 flagged the strict-mcp shape as fragile. Two claude patch versions later that premise reversed entirely: `--strict-mcp-config` now suppresses the modal and renders an inline empty-state. The parsed-shape model held — the fixture just moved from `{1, [built-in]}` to `{0, null}` — but the lesson is that a fixture captured against a stochastic, fast-moving upstream renderer is a snapshot of *that version's* behaviour, not a stable contract. Anchor the drift signal on what's observable today and re-record when the renderer moves.
- **A unit fixture captured at an older claude can mask a live regression.** `TestDetectModalClassRealFixtures` kept passing against `mcp-snapshot.bin` (full-modal title stripping to the no-space `ManageMCPservers`) while a *live* full-modal capture on 2.1.158 classified as `Unknown` (title now strips to spaced `Manage MCP servers`). The `.bin` fixture is a point-in-time capture; it does not track the installed claude. When the live behaviour and the committed fixture can diverge, the unit test guards the fixture's *interpretation*, not the *current* renderer — the e2e gate is what catches live drift. Both layers are needed; neither substitutes for the other.
- **The empty-state prose and the modal title strip to opposite space-forms on the same version.** Surprising and the reason the dual-form belt-and-suspenders was load-bearing rather than ceremonial here (see Patterns). Don't assume a single claude version strips all its UI text consistently.
- **`categories: null` vs `[]` resolved the same way as [#81](81.md) OQ1: commit what `-record` produces.** `ParseMcpStatus` leaves `Categories` nil on the empty-state → marshals to `null`. The exact-equal comparison handles either form; no need to desk-check the parser. If a future claude reintroduces a category header under strict-mcp, commit what `-record` produces — that would itself be a legitimate drift signal worth a fresh look.
