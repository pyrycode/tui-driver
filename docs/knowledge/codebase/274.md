`source []string` / `mergeSources` union seam this ticket rides). Sibling of
[#273](273.md) (`-fires`) — both are independent additive sources with no

## Summary

Adds a fourth sample source to `corpus-sampler`: `-midstream N` (int flag,
default 0/off) emits up to N deterministically chosen mid-stream frames per
cast (`source: ["midstream"]`). Streaming-state variety lives between output
bursts, where the quiet-gap rule (#255) rarely fires — the dot-spinner frame
#243 fixed went uncounted in the original glyph census for exactly this
reason, since it appears mid-stream rather than at a quiet wait-state.
`-midstream` surfaces a thin, fixed sample of that variety for the #257
labeling pass without exploding the sample set.

Selection is a pure function of stable per-cast data, not processing order or
wall-clock time: every output-event index `i` in a cast is a candidate keyed
by `sha256(name + "\x00" + strconv.Itoa(i))`, and the N candidates with the
smallest keys (lexicographic byte compare of the digest) are retained. Fewer
than N eligible events emits all of them, no padding, no error (AC3).
Selection by key alone means the retained set is independent of insertion
order, so re-running over the same input directory reproduces the identical
distinct set (AC2/AC5b) — the same "byte-identity rests on determinism, not
incidental behavior" property #260's parallel-replay work established.

Retention during the walk is single-pass and bounded at ≤ N: a candidate is
inserted while `len(retained) < N`, and once full a new smaller-key candidate
evicts the current largest-key one (`maxKeyPos`, linear scan over the bounded
set). Each retained candidate holds `buf.Snapshot()` — a fresh copy
(`buffer.go:56-64`), safe to keep across later `Append`s — so at most N
`tuidriver.Render` calls happen at the end of the walk, never one per
eligible event (a cast can hold tens of thousands of output events).
Rendering happens post-append, matching where the `-fires` source classifies.
Winners are appended after the walk sorted by event index ascending, for a
deterministic within-cast discovery order.

Attribution and dedupe ride the #272 mechanism unchanged: `sourceMidstream =
"midstream"` added to the existing source-const block, no new struct field,
no second merge path. A mid-stream candidate whose normalized-grid hash
collides with an existing gap/final/fire sample unions `"midstream"` onto
that entry via `mergeSources` (AC4).

`collect`/`sampleCast` gained a fifth positional param, `midstream int`
(mirroring how #272/#273 threaded their bool params) — the 13 pre-existing
test call sites got a trailing `, 0`. With the flag off, the mid-stream block
is skipped entirely; `-out` and stdout stay byte-identical to prior behavior
(AC1), and no stdout field was added — mid-stream samples fold into
`distinct` only, same posture as `-final`/`-fires`.

A new fixture, `testdata/midstream-ok.cast`, holds a tight burst of ~6 output
events at sub-threshold gaps, each painting a distinct streaming frame (no
digits/spinner glyphs, so no hash-fold) — making all 6 eligible and N=3
meaningfully less than the eligible count. `stable-sample-ok.cast` was reused
for the emit-all/union case (N ≥ eligible): with N=10 over its 5 events, all
5 are selected, and dedupe collapses to distinct=3 — the idle and thinking
gap-samples pick up `"midstream"` via union, and the Working spinner (caught
by no quiet gap) surfaces with `Source = ["midstream"]` alone, the same
"uncounted mid-stream frame" case #243 motivated.

## Patterns established

- **A deterministic selection scheme keyed by `sha256(stable-name +
  "\x00" + index)`, retaining the N smallest digests, is the established way
  to pick a bounded, reproducible subset of a large per-cast event stream**
  without wall-clock time or an RNG. Any future corpus-sampler source that
  needs "N representative samples, not all of them" should reuse this shape
  rather than inventing a new one.
- **Bounded single-pass retention (≤ N snapshots, evict-the-max-key-on-a-
  smaller-key-arrival) is the pattern for holding candidates across a walk
  over an unbounded event stream** — confirmed here after #272/#273 established
  the const/flag/positional-param/`mergeSources` shape; this ticket's
  contribution is specifically the "don't retain or render more than N" bound.
  `Buffer.Snapshot()`'s fresh-copy guarantee (`buffer.go:56-64`) is what makes
  holding a retained snapshot across later `Append`s safe.

## Lessons learned

- No deviation from the architect's spec — the spec's positional-param count
  ("this is the last #256 child, so the param list does not grow further"),
  post-append render point, and sorted-by-event-index emission order were
  followed as written; `make check` green on the first pass.
- The `cmd/corpus-sampler/README.md` "Scope" line ("random mid-stream slices
  are `-midstream` (#274)"), written speculatively during #272/#273, was
  stale on two counts once this ticket shipped: the selection is
  deterministic, not random, and the flag itself was undocumented in the
  Run/Flags sections. Fixed as part of this ticket's documentation pass —
  worth checking a sibling ticket's forward-reference prose against what
  actually ships, not just carrying it forward.
