# #272 — corpus-sampler: `-final` source + multi-valued `source` provenance

[Issue](https://github.com/pyrycode/tui-driver/issues/272) · Code: `cmd/corpus-sampler/main.go`, `cmd/corpus-sampler/main_test.go`, `cmd/corpus-sampler/testdata/no-output-ok.cast`

Split child of #256 (extra sample sources), built on the shipped `corpus-sampler`
core ([#255](255.md)). First of three #256 children; [#273](https://github.com/pyrycode/tui-driver/issues/273)
(`-fires`) and [#274](https://github.com/pyrycode/tui-driver/issues/274) (`-midstream`) are blocked-by this
ticket and build on the mechanism it lands here.

## Summary

Adds a second sample source to `corpus-sampler` — the quiet-gap rule from #255
only samples a screen that sat stable through an inter-event gap, which misses
how a run *ended* when the last events arrive in a burst with no trailing gap.
`-final` (bool flag, default off) renders the buffer once more after a cast's
event walk completes and appends one more sample tagged `source: ["final"]`,
guarded on `idx >= 1` so a zero-output cast emits none. The final sample is
appended before the existing Tag/Segment stamping loop, so it inherits them like
every other sample, and it is excluded from the `gaps` stdout stat (now an
explicit counter rather than `len(samples)`, since that would over-count once a
non-gap sample can be appended).

Every sample — including the previously-unlabeled gap samples — now carries a
`source []string` field (JSON key `source`), always serialized as a sorted,
distinct array even for one value. `collect`'s hash-collision merge
(`distinct[pos].Seen++`) gained a matching union step: `mergeSources(a, b []string) []string`
folds an incoming sample's source into the kept entry's set (dedup + sort),
independent of `Seen`, which still counts total occurrences. This union is the
one seam #273/#274 reuse — they emit samples carrying their own source name and
the same merge folds them in, so no per-source special-casing was added to
`collect`.

The committed `stable-sample-ok.cast` fixture (#255) was reused as-is: its final
frame (idle "…ready 999") normalizes to the same hash as the gap-sampled idle
screen, so `-final` on folds into 2 distinct entries rather than 3 — exercising
the union path with no new fixture. A second fixture, `testdata/no-output-ok.cast`
(header-only, zero `"o"` events), was added to pin the zero-output guard.

## Patterns established

- **Multi-valued provenance sets merge through one shared union function at the
  dedupe site, not per-source branches.** `mergeSources` is the extension point
  for every future corpus-sampler source — a new source only needs to append a
  `sample` with its own `Source: []string{"newsource"}`; `collect`'s merge logic
  never changes. Any future tool with a similar "which rule found this" dedupe
  problem should reach for the same shape (sorted-slice union at merge, not a
  per-key map keyed by source name).
- **A provenance field added to an existing sample shape is additive, not a
  rename** — the #255 gap samples gained `source: ["gap"]` with every other field
  untouched. When extending a shared record shape for a new axis, prefer this
  over restructuring existing fields.
- **A stat counter that assumed "one sample kind" needs an explicit counter once
  a second kind exists.** `gaps` was `len(samples)`; once `-final` could append a
  non-gap sample, that silently over-counted. Any future corpus-sampler stdout
  stat should be double-checked against the same assumption before adding a
  fourth sample source (#273 `-fires`, #274 `-midstream`).

## Lessons learned

- **Check whether an existing fixture already exercises a new code path before
  authoring a new one.** The spec flagged this as an open question ("if the
  final frame doesn't fold as expected, author a minimal dedicated fixture");
  running the test against the existing #255 fixture confirmed it does fold,
  saving a new `.cast` (with its ESC-escaping landmine, see
  `cast-fixture-esc-escaping` in project memory). The zero-output guard did need
  its own trivial fixture — reuse isn't always possible, but it's worth checking
  first.
