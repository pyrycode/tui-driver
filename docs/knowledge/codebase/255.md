# #255 — corpus-sampler: deduped stable screens from the recording corpus, with provenance

[Issue](https://github.com/pyrycode/tui-driver/issues/255) · Code: `cmd/corpus-sampler/main.go`, `cmd/corpus-sampler/main_test.go`, `cmd/corpus-sampler/testdata/stable-sample-ok.cast`, `cmd/corpus-sampler/README.md`, `.gitignore`

## Summary

New standalone binary `cmd/corpus-sampler` pulls the distinct **stable screens** out of the PTY recording corpus (`SpawnOpts.RecordTo`, ~1900 casts, ~4.5M output events) so the offline model-labeling pass (#257) and fixture promotion (#258) work from a low-thousands exemplar set instead of the raw corpus. Whole-grid dedupe was measured to fail (96.9% of per-event grids unique, 76.0% even after collapsing digits + unifying spinner glyphs) because the rolling buffer window shifts on every output event.

The tool walks every `"o"` (output) event per cast and gates on **time**, not event stride: whenever the timestamp gap between consecutive output events `i-1` and `i` is `>= -gap` (default `500ms`), the frame painted by `i-1` sat stable through that quiet window and is emitted as one `sample` — rendered from `tuidriver.Render(buf.Snapshot(), cols, rows)` on the buffer as it stood *before* event `i` was appended (`Event = i-1`, `TS = ts[i-1]`). Event-stride sampling was explicitly rejected (Technical Notes): a quiet dialog emits almost no events, so a stride steps over exactly the stable screens this tool exists to catch.

Samples dedupe across the whole run on a normalized-grid hash (`hashGrid(normalize(grid))`): spinner glyphs unified to one canonical rune, ASCII digit runs collapsed to `"0"`, rows right-trimmed. First occurrence is kept (in sorted-cast, in-order-event order → deterministic across re-runs); repeats bump `Seen` on the existing entry rather than adding a line. Full provenance (raw grid, hash, cast, event index, timestamp, cols/rows, `ok`/`err` tag, prod/e2e segment, `Seen`) goes to the required `-out` JSONL file only; `stdout` prints one aggregate line (`casts=… events=… gaps=… distinct=…`) and nothing else.

`cmd/corpus-sampler` is `package main` and cannot import `cmd/corpus-replay` (#227), so three helpers are copied verbatim per the spec: `castPaths` (sorted `.cast` directory listing), `tagFromName` (`-ok`/`-err` filename suffix), `segmentOf` (prod/e2e/unknown content-cue classifier). The one designed divergence is the event parser: corpus-replay's `parseOutputEvent` discards the event timestamp (`ev[0]`); this tool's `parseOutputEventTS` returns it, since gap timing is the whole point.

A hand-authored synthetic fixture (`testdata/stable-sample-ok.cast`, 5 events: idle → spinner → spinner → idle → idle) drives the unit tests, requiring a `.gitignore` exception (`*.cast` is globally ignored — repo-wide secret-recording guard) mirroring the one already carved for `corpus-replay/testdata/*.cast`.

## Patterns established

- **Timestamp-gated sampling, not event-stride sampling, for anything walking the recording corpus.** The Technical Notes are explicit and measured: a quiet dialog emits almost no output events, so any future corpus tool that samples "every Nth event" will systematically miss stable screens. #256 ("extra sources": mid-stream slice, detector-fire moments, final frames) and any later corpus tool should default to gap/time gating unless there's a specific reason not to.
- **`package main` siblings copy shared helpers rather than share a library package.** Both `corpus-replay` and `corpus-sampler` independently define `castPaths`/`tagFromName`/`segmentOf` — Go's `package main` cannot be imported by another `package main`, and neither tool is a `pkg/tuidriver` consumer concern (both are audit tooling, not library surface). If a third corpus tool appears, this becomes an explicit "extract to an internal shared package or keep copying" call — two instances stayed a copy per the spec's own reasoning ("sibling," not "shared"), a third would tip the balance.
- **Provenance-carrying JSONL + counts-only stdout is the shape for any tool touching raw screen content.** Same posture as `corpus-replay`'s existing self-reference discipline (#152/#154/#155 lineage): grid bytes never reach a terminal or a test failure message, only a file and a hash.

## Lessons learned

- **The `.cast` `.gitignore` exception needs a new negation line per tool, not a broadened glob.** `*.cast` is repo-wide-ignored because real recordings may contain secrets; the exception list (`!cmd/corpus-replay/testdata/*.cast`, now `!cmd/corpus-sampler/testdata/*.cast`) is enumerated per fixture directory rather than something looser like `!cmd/*/testdata/*.cast`, keeping each hand-authored synthetic fixture an explicit, auditable opt-in rather than a silent blanket carve-out.
- **A fixture proving gap-gating needs a sub-threshold gap that produces no sample, not just above-threshold gaps that do.** The committed fixture's event 1→2 gap (0.1s < 0.5s) is what actually proves the tool gates on time and not on "every event boundary" — without a negative case, a stride-based implementation could pass the same assertions.
