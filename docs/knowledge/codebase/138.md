# #138 — `Session.Resize`: size the hosted PTY on the sealed surface

[Issue](https://github.com/pyrycode/tui-driver/issues/138) · [Spec](../../specs/architecture/138-session-resize.md) · [PR #139](https://github.com/pyrycode/tui-driver/pull/139) · Feature doc: [features/session-resize.md](../features/session-resize.md) · Code: `pkg/tuidriver/pty.go`, `pkg/tuidriver/resize_test.go` (new)

**Unblocks pyrycode #593** (supervisor hosts `claude` via `tuidriver.Spawn`) without regressing shipped, test-pinned resize behaviour (pyrycode #126/#131/#132/#133/#137). The gap v1.1.0 skipped: [#136](136.md) cleared the mirror surface but not the resize seam. Operator decision (2026-06-07): take the no-regression path rather than ship a bounded 40×120 regression.

## Summary

One additive public method — `(*Session).Resize(rows, cols uint16) error` — the **sanctioned replacement for the sealed `Session.PTY` accessor**. It issues `TIOCSWINSZ` on the held master FD via the same `pty.Setsize(s.pty, &pty.Winsize{Rows, Cols})` call `StartPTY` already uses for the 40×120 default; the kernel turns that ioctl into `SIGWINCH` on the hosted process so its TUI redraws. A consumer holding only a `*Session` (which is all #593's supervisor has after migrating off the bare PTY) can now size a live session to the operator's real terminal.

Fully additive and single-concern: no existing exported symbol changed signature (the v1.0.0/v1.1.0 seal is preserved, AC 5), no `SpawnOpts` field, no `Session` struct field, **no `session.go` edit at all**. The whole change is ~21 production lines in `pty.go` plus a new `resize_test.go`. A session that never calls `Resize` keeps `StartPTY`'s untouched 40×120, byte-for-byte unaffected. The full evergreen contract lives in the [feature doc](../features/session-resize.md); this file records the *why* behind the choices.

Pipeline ran clean: QA green (`make e2e` 11/11 incl. `snapshot-drift`, `go build`), code-review **PASS** (one accepted NIT, no MUST/SHOULD FIX). No `security-sensitive` label — security gate skipped (unlike #136, this surface carries no new secret-bearing bytes; `Resize` moves a winsize, not screen content).

## Patterns established

- **Reuse the exact spawn-time call for the live-update method.** `Resize` is `StartPTY`'s line-132 `pty.Setsize` call verbatim, on the held FD with caller dims instead of the defaults. The only behavioural divergence is error handling: `StartPTY` treats `Setsize` as best-effort (`_ =`), `Resize` returns the wrapped error. When a "set X at spawn" helper already exists, the "change X live" method is the same syscall on the held handle — don't invent a parallel path.
- **`SIGWINCH` is a property of the ioctl, not added code.** `TIOCSWINSZ` makes the kernel both update the slave's stored winsize (child's `stty size` reports new dims) *and* signal the foreground process group (`claude` redraws). tui-driver writes zero signal handling — a reminder that terminal-redraw-on-resize is kernel behaviour you get for free from the size-set, not a separate emit step. (The consumer-side SIGWINCH *producer* — pyrycode #133 — is a different layer: forwarding the operator's terminal SIGWINCH into `Bridge.Resize`.)
- **Placement by concern, not by type.** `Resize` lives in `pty.go` (cohesive with `StartPTY`, `DefaultPtyRows/Cols`, and the `creack/pty` import) rather than `session.go`, keeping `session.go` untouched. The package already spreads `*Session` methods by concern — input in `keys.go`, prompt delivery in `deliver.go`, window-sizing in `pty.go`. A new method goes where its concern lives, not next to the struct.
- **Deterministic post-`Close` error via the FD lifecycle, not a guard flag.** `Close`'s `s.pty.Close()` → `<-s.readerDone` order means that by the time `Close` returns the `*os.File`'s `Fd()` reads back as `-1`, so a later `Resize` ioctls fd `-1` → `EBADF` → non-nil, deterministically and safe under fd reuse (never resizes a recycled terminal). No `closed bool` mutex+flag added — the failure mode is structurally prevented (see Lessons / Evidence-Based Fix Selection).

## Lessons learned

- **`SIGWINCH`'s default disposition is *ignore*, so it won't interrupt an external `sleep` — the obvious test child is flaky.** The spec offered two AC-1/AC-2 test shapes: a `trap 'stty size' WINCH; sleep 5` child (assert the trap fires) vs. a `IFS= read -r _; stty size` child (resize *before* releasing the read, then nudge it). The developer correctly took the deterministic `read`-then-`stty size` path: `stty size` reports the post-`Resize` dims via the same ioctl regardless of signal timing, so there's no dependence on a SIGWINCH-interrupts-sleep race that may never fire. AC-1's SIGWINCH delivery remains the kernel-guaranteed response to the same `TIOCSWINSZ` whose effect (the observed `50 100`) is asserted. **When testing a signal's *effect*, assert the post-state via a deterministic read, not the signal's interruption of a blocking call.**
- **Evidence-Based Fix Selection — no mutex+flag for an already-prevented failure.** A `closed bool` guard around `Resize` was explicitly *not* added: the `Fd() == -1` mechanism already makes post-`Close` deterministically `EBADF` with no panic and no fd-reuse hazard. Adding a lock+flag would defend a failure mode that is structurally impossible. Noted as the belt-and-suspenders option if a future audit ever wants it; not built.
- **Honest error on the library side, best-effort swallowing on the consumer side.** tui-driver returns the `EBADF` rather than no-op'ing, because the consumer (pyrycode ADR 008) owns the "resize never fails the attach — log at Warn and proceed, geometry self-heals on next redraw" policy. A library that silently swallowed the error would rob the consumer of the choice. Cross-checked against the consumer convention via QMD (ADR 008/009): signature `Resize(rows, cols uint16)` and `pty.Winsize{Rows, Cols}` field order match `Bridge.Resize`, so the seams compose without an adapter.
- **Test-helper duplication was the right call (code-review NIT, accepted).** `resize_test.go`'s `drainUntil` is a one-shot factoring of `mirror_test.go`'s stateful `recvUntil` closure. Hoisting a shared helper would have edited `mirror_test.go` and risked the AC-5 "every existing test stays green with zero edits" guard; the two shapes genuinely differ (fresh `acc` per call vs. accumulation across two calls). Mild duplication beats touching a sibling test file on a seal-preserving ticket.
- **No new ADR.** This ticket follows the already-established "additive sealed-surface seam" pattern from [#136](136.md); it introduces no cross-cutting decision of ADR weight. The deferral decisions (no `SpawnOpts.InitialRows`, no `closed` guard, error-wrap-vs-raw) are recorded in the [spec's Open questions](../../specs/architecture/138-session-resize.md) and above.
