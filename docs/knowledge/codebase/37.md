## Patterns established

- **"World shifted; close the dangling promise" close-out.** When a ticket was scoped to produce a separate artifact but the content accreted into an adjacent doc during sibling tickets, the right close-out is *delete the self-reference, do not re-extract*. Re-extracting churns prose for cosmetic gain; the content already has a stable home with a working INDEX.md pointer. Reuse this shape any time a ticket's original deliverable has been silently fulfilled in a different location — the close-out is a one-line deletion, not a re-org. The PO body and the spec both walked through the "where did each AC section land?" mapping inline rather than asking the developer to reconstruct it; that mapping is what justified the close-out scope.

## Lessons learned

- **Self-referential "not yet landed" sentences age into lies.** The step-5 sentence was correct when it was written (the separate runbook was still planned) but became misleading once the runbook content accreted into the same file. Forward-referencing future tickets inside evergreen docs is a small but real footgun — the reference does not auto-rot when the world changes. If a doc must point at a not-yet-landed ticket, the safer shape is *"see ticket #N for the planned expansion"* rather than the absolute *"the full runbook lives in ticket #N"* — the former degrades gracefully into "see ticket #N for the discussion that produced this section"; the latter degrades into a contradiction. The cheapest fix is still "don't write it at all unless you have to."
- **The example lock-file comment cross-reference (lines 191-192) was deliberately left alone.** It reads *"# Update deliberately when bumping the installed claude; the docs ticket / # (#37) covers the workflow."* — which is no longer literally true now that #37 is a deletion ticket, but the spec explicitly scoped this ticket to a one-sentence edit and the PO's AC #2 said "No other doc changes". If a follow-up ticket wants to clean that comment up, the right edit is dropping the `(#37)` parenthetical so the comment reads as a generic pointer to the surrounding doc. Not in scope here.
- **XS doc tickets benefit from the spec walking the developer to the exact byte.** The architect's spec quoted the before-and-after text verbatim and called out that the leading space joining the two sentences must also go. A doc edit this small is one where ambiguity in the spec ("just drop the reference") would produce a diff that either over-edits (trims step 4 too) or under-edits (leaves a trailing space). Quoting the exact strings is cheap and removes the only failure mode.
