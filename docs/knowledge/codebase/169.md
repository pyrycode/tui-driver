# #169 — Set a parent-death signal so Claude dies with the daemon

[Issue](https://github.com/pyrycode/tui-driver/issues/169) · [Spec](../../specs/architecture/169-parent-death-signal.md) · Commit `4aad63a` (spec `ca14655`) · Touches [`pty.go`](../../../pkg/tuidriver/pty.go) + new [`pty_pdeathsig_linux.go`](../../../pkg/tuidriver/pty_pdeathsig_linux.go) / [`pty_pdeathsig_other.go`](../../../pkg/tuidriver/pty_pdeathsig_other.go) · Disjoint sibling: [#168](168.md) (process-group kill on `Close`)

**XS process-lifecycle backstop from the Cross-Repo Code Review 2026-07-03 inbox filing.** Not `security-sensitive` (verified on the issue labels) — a process-liveness signal, no auth/secrets/untrusted-input/parsing surface. Adds no exported API.

## Summary

`Session.Close` (via #168's process-group signal) only stops the driven `claude` on an **orderly** shutdown. If the host daemon crashes or is `SIGKILL`ed, no cleanup runs — the PTY child is reparented to init and `claude` keeps rendering headless, burning subscription quota with nobody driving it. This ticket wires the Linux kernel's parent-death backstop: `StartPTY` now sets `cmd.SysProcAttr.Pdeathsig = syscall.SIGKILL` before spawn, so the kernel kills the child the instant its parent dies — no cleanup code required.

**Complementary to #168, not overlapping.** #168 covers the *controlled* path (`Close` reaps the group on orderly shutdown); #169 covers the *uncontrolled* path (daemon dies without running `Close`; the kernel kills `claude` via `Pdeathsig`). #168 was scoped to `Close`-only and touches no `SysProcAttr`; #169 touches only `SysProcAttr.Pdeathsig`, in new files. Different files, no logical dependency — no native blocker (dispatcher WIP=1 serialised them; #168 merged first as `5a39443`).

## Design

Three production files, mirroring the `cwd_darwin.go` / `cwd_other.go` build-tag split. The helper `setParentDeathSignal(cmd *exec.Cmd)` is package-private.

- **`pty_pdeathsig_linux.go`** (`//go:build linux`) — allocates `cmd.SysProcAttr` if nil (so `pty.Start`'s later `Setsid`/`Setctty` still apply), then sets `Pdeathsig = syscall.SIGKILL`. Carries the platform-coverage doc comment (AC #4) and the thread-death caveat inline.
- **`pty_pdeathsig_other.go`** (`//go:build !linux`) — a no-op `func setParentDeathSignal(cmd *exec.Cmd) {}`. Imports only `os/exec` for the parameter type; **must not** reference `syscall.SysProcAttr` — darwin/windows `SysProcAttr` has no `Pdeathsig` field, so touching it would break the cross-build.
- **`pty.go`** — one line: `setParentDeathSignal(cmd)` as the first statement of `StartPTY`, before `pty.Start(cmd)`; plus a note on `StartPTY`'s doc comment. No signature change.

**Load-bearing invariant:** creack/pty's `StartWithSize` allocates `SysProcAttr` if nil and only *adds* `Setsid`/`Setctty` — it never overwrites a caller-set struct. So a `Pdeathsig` set before `pty.Start` survives. `StartPTY` is the library's single spawn seam (used by `Session.Spawn`), so the production `Session` path is covered for free. (`cmd/spike-*` call `pty.Start` directly and won't get the signal — expected; they're demo harnesses, not the `Session` path.)

## Patterns established

- **This is the third instance of the "syscall is Unix-only → build-tag split, not `runtime.GOOS`" pattern** (`cwd_darwin.go`/`cwd_other.go`; #168's `session_signal_*`; now `pty_pdeathsig_*`). A field/function absent from a platform's `syscall` package fails at **compile** time, so a runtime skip can't guard it — the platform-excluded file must not name the symbol at all. Here the `!linux` no-op deliberately does *not* mention `SysProcAttr`; the `linux` file is the only one that names `Pdeathsig`.
- **Split the platform axis on `linux` vs `!linux`, not `!windows` vs `windows`.** `Pdeathsig` is a Linux-only field (absent on *both* darwin and windows), unlike #168's `syscall.Kill` (Unix, present on darwin). Pick the tag by where the symbol actually exists, not by copying the nearest precedent's tag.
- **`setParentDeathSignal` is the agreed platform-neutral contract name** — both build-tag files must define exactly it, so `StartPTY`'s single call site resolves on every GOOS.

## Lessons learned

- **A `//go:build linux` file is invisible to the darwin `make check` gate — the cross-GOOS `go build` is the real local proof.** `make check` (`vet` + race `test`) runs natively on darwin, which **build-excludes** the Linux helper and its test; a broken Linux file would pass `make check` undetected, and a cross-compiled test binary can't *run* on darwin either. The darwin-runnable guard is `GOOS=linux`/`GOOS=darwin`/`GOOS=windows go build ./...` (all three must succeed) — baseline confirmed green before the change so a post-change break is attributable to this ticket. The Linux-tagged wiring test is the *real* behavioural spec but is Linux/CI-only and does not gate a local green. (Same hazard #168 surfaced; memory `tuidriver-builds-windows-syscall-unix-only`.)
- **A full parent-death behavioural test is a false-green trap, deliberately omitted.** Killing the parent and asserting the child dies proves nothing: when the parent dies the PTY master FD closes and SIGHUPs the whole foreground group, killing the child *regardless of* `Pdeathsig`. Isolating the mechanism would need the child to ignore SIGHUP — the exact confound #168's group-kill test hit (memory `pty-close-sighup-masks-group-kill-tests`). The wiring test instead asserts the *field is set* and that creack's `Setsid`/`Setctty` co-exist with it, proving the "preserves a pre-set struct" invariant in both directions. A real behavioural test, if ever added, belongs in a separate Linux-tagged CI-only integration test.
- **`Pdeathsig` fires on spawning-*thread* death, not process death (golang/go#27505) — and that's acceptable here.** Go parks rather than destroys threads, so a spurious early kill is rare, and it fails in the *safe* direction (claude dies rather than survives headless), which is the whole point. Flagged inline so it isn't mistaken for a bug; no mitigation warranted at this size.

## Deferred / out of scope

- **Wiring the cross-GOOS build into `make check` / CI** would make the guard permanent, but touches `Makefile` / `.github/workflows` — outside this XS ticket's boundary. Possible follow-up.
- **`cmd/spike-*` binaries** call `pty.Start` directly, bypassing `StartPTY`, so they don't get `Pdeathsig` — expected, they're demo harnesses.
