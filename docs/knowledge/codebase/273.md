# #273 — corpus-sampler: detector-fire sample source

[Issue](https://github.com/pyrycode/tui-driver/issues/273) · Code: `cmd/corpus-sampler/main.go`, `cmd/corpus-sampler/main_test.go`, `cmd/corpus-sampler/testdata/no-fire-ok.cast`, `cmd/corpus-sampler/README.md`

Split child of #256 (extra sample sources), blocked-by [#272](272.md) (the
`source []string` / `mergeSources` union seam this ticket rides). Sibling of
[#274](https://github.com/pyrycode/tui-driver/issues/274) (`-midstream`).

## Summary

Adds a third sample source to `corpus-sampler`: `-fires` (bool flag, default
off) emits a sample at each output event where a structural detector *newly*
fires — the same predicate set `cmd/corpus-replay` (#227) reports on (the flat
detectors `idle`/`thinking`/`mcp-failure`/`network-failure`/`unknown-dialog`,
plus each `DetectModalClass` class folded in as `modal:<class>`). These are the
direct false-positive-triage candidates for the #257 labeling pass — the exact
screens a live run would have acted on — and they often sit mid-stream where
the quiet-gap rule (#255) never samples.

The detector set (`detector` struct, `flatDetectors`, `activeKeys`) is copied
verbatim from `cmd/corpus-replay/main.go`, same reason #255 copied
`tagFromName`/`segmentOf`: package `main` can't import another `main`. The fire
check runs on `buf.Snapshot()` **after** `buf.Append(data)`, matching exactly
where corpus-replay classifies, so the fire moments align with its report.
Emission is edge-triggered (`{} → {key}`, tracked via a per-cast `prev
map[string]bool`) rather than every tick the key stays active — dedupe would
collapse repeats by hash either way, but the edge keeps each sample's
`Event`/`TS` at the onset moment. A fire event with N newly-active keys yields
one sample carrying all N keys, not N samples, so `Seen` counts screen
occurrences.

Attribution rides the existing `Source []string` mechanism from #272: `sourceFire
= "fire"` plus the sorted newly-fired keys (e.g. `["fire","idle"]`,
`["fire","modal:trust-folder"]`), and the whole slice is re-sorted before
storing. `activeKeys` returns a map, so both the new-key diff and the final
`Source` slice must be explicitly sorted — `collect` stores the first
occurrence's `Source` as-is (only a later hash-collision re-sorts via
`mergeSources`), so an unsorted store would make re-runs non-byte-identical
(AC3). Dedupe/merge use the #272 path unchanged — no second merge path, no new
struct field.

`collect`/`sampleCast` gained a fourth positional bool param (`fires`),
mirroring how #272 threaded `final`; the 9 pre-existing test call sites got a
trailing `, false`. With `-fires` off, the fire block is skipped entirely (no
`activeKeys` call, no `prev` map) — `-out` and stdout stay byte-identical to
prior behavior (AC1). `stdout`'s `gaps` counter and aggregate line are
untouched; fire samples fold into `distinct` only, no `fires=` counter was
added (not required by any AC).

The existing `stable-sample-ok.cast` fixture (#255) was reused as the positive
— its frames genuinely fire real detectors (event 0 idle, events 1–2 thinking,
events 3–4 idle), so `-fires` on grows the distinct set from 2 to 3: the
mid-stream "Working" spinner is caught only by the fire source, exactly the
case this ticket exists for. A new `testdata/no-fire-ok.cast` (two plain
`compiling package …` / `ok …` lines, no control bytes, no ESC-escaping
concerns) pins the AC4 negative — no detector fires, so no fire sample.

## Patterns established

- **Copying a sibling `main` package's predicate set verbatim (not importing
  it) is the established pattern for `cmd/` leaf tools that need to align with
  another leaf tool's classification** — #255 did it for `tagFromName`/
  `segmentOf`, this ticket for `detector`/`flatDetectors`/`activeKeys`. Keep
  future corpus-sampler sources (`-midstream`, #274) doing the same rather than
  reaching for a shared internal package.
- **A provenance source that needs multi-value attribution (not just "which
  rule fired" but "which specific key") still rides the one `Source []string`
  slot** — no new field was added for the detector key; it's just another
  string appended to `Source` alongside `"fire"`. Any future source needing
  finer-grained attribution should default to this before adding structure.
- **Placement of a classifier read relative to `buf.Append` is a load-bearing
  design decision, not an implementation detail** — the fire check had to run
  strictly after the append (unlike the gap check, which renders before) to
  align with where the tool it's mirroring (`corpus-replay`) classifies. Any
  future source that needs to match another tool's semantics should locate
  that tool's exact append/classify ordering first.

## Lessons learned

- **Reusing an existing fixture across two unrelated ACs (positive-case reuse)
  continues to pay off** — same as #272's lesson, `stable-sample-ok.cast`
  covered the fire-source positive case with zero changes because its frames
  were already verified (empirically, not assumed) to trip real detectors.
  Only the negative case (AC4, "no detector fires") needed a new fixture, and
  because it's plain text with no control bytes it sidesteps the `.cast`
  ESC-escaping hazard entirely (see `cast-fixture-esc-escaping` in project
  memory) — worth defaulting to plain-text fixtures when a cast's only job is
  "produce no signal."
