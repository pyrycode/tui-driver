# #242 — permission modal class requires the option-row dialog shape

## Summary

The `permission` modal class was the **last single-fabric class** in
`DetectModalClass`: the arm at `detectModalClassWithGrid` (`modal.go`) fired
whenever `anchorPermissionSpaced` (the proceed prompt) appeared anywhere in the
bottom `permissionRegionRows` overlay window, and nothing else. That forged in
production — corpus replay showed the class flapping shown/hidden 6 times in
one recording and 5 times in another, on frames whose rendered screen was plain
agent-transcript prose quoting the phrase (this org's tickets are *about* this
detector, so the false-fire rate was structural, not incidental). Two consumers
made this exploitable: `ParseModalContent` surfaces a forged dialog to a human
operator (pyrycode `modal_shown` #716) and `Session.AnswerModal` can route an
answer keystroke into a live turn (pyrycode `modal_answer` #717/#791).

Fixed by giving `permission` the same structural co-signal #219 gave
`trust-folder`: a new `gridHasPermissionDialog` (`modal.go`) requires the anchor
**and** a pointer-marked numbered option row (`modalOptionRe`, group 1 = `❯`)
within `permissionDialogLookahead = 3` rows below it, **inside the existing
bottom `permissionRegionRows` window**. One-line arm swap in
`detectModalClassWithGrid`; no caller changes needed — `ParseModalContent` and
`Session.AnswerModal` inherit the tightened classification for free. This closes
the anchor-forgery-protection arc: every modal class now requires two
different-fabric signals (region/position + shape) before classifying.

## Patterns established

- **Shape-gate mirror with one deliberate divergence.** `gridHasPermissionDialog`
  is structurally identical to `gridHasTrustDialog` (`trust.go`, #219) except it
  iterates `g.LastRows(permissionRegionRows)` instead of `g.Rows()`. Trust is a
  full-panel startup class (whole-grid scan is correct); permission is a
  bottom-overlay class where the region scope is load-bearing — it's what
  rejects an *above-window* transcript forgery (pinned by
  `TestModalPhraseAnchorsRejectBodyForgery`, predates this ticket). When porting
  this shape-gate pattern to a future class, the region-scope-vs-whole-grid
  choice is the one thing to get right per class; everything else about the
  helper mirrors verbatim.
- **`modalOptionRe` over `selectionOptionRe` for number-only dialogs.**
  `selectionOptionRe` (`dialog_shape.go`) additionally admits the `❯ [✔]`
  checkbox form (the MCP-enablement modal). A permission overlay never renders a
  checkbox — always numbered — so `modalOptionRe` is the tighter, correct choice.
  Reusing the same regex across `gridHasTrustDialog` and `gridHasPermissionDialog`
  (rather than each rolling its own) keeps the two helpers unable to drift apart.
- **Region-scope-by-construction, not a second explicit bound.** Because
  `LastRows(permissionRegionRows)` is already the bottom window and the lookahead
  can only move toward the screen bottom, both the anchor and the option row are
  guaranteed inside the region without a second explicit range check — worth
  remembering when reviewing/porting this shape, the "single window + downward
  lookahead" idiom is sufficient on its own.

## Lessons learned

- **Self-reference ticket, ran through the normal pipeline anyway.** The ticket
  body carried a "hand-run this outside the pipeline" warning (mirroring #152 and
  #219–#227) because discussing the literal anchor phrase on screen risks forging
  the very state being fixed. The spec and code held the by-symbol discipline
  throughout (`anchorPermissionSpaced`, never the literal, in spec prose/comments/
  commit messages); the one place the literal phrase appears is pre-existing test
  *fixture* byte data (`"Do you want to proceed?\r\n❯ 1. Yes\r\n..."`), which is
  categorically different from a rendered comment/commit message and was already
  the established pattern before this ticket.
- **`make corpus-replay` is hand-run evidence, not a CI gate.** It reads an
  external, machine-local, uncommitted corpus (`CORPUS_DIR`, default
  `$HOME/.local/share/pyry-recordings`) and is the operator's empirical
  confirmation that the two named recordings' false-fires are gone. The
  deterministic regression lock is the new `anchor_forgery_test.go` case alone.
