# #153 — Rendered-grid refactor 4/6: port idle/busy detection to the grid status region

[Issue](https://github.com/pyrycode/tui-driver/issues/153) · [Spec](../../specs/architecture/153-idle-busy-grid-status-region.md) · Commit `3014953` · Related: [#150](150.md) (`Grid` foundation), [#151](https://github.com/pyrycode/tui-driver/issues/151)/[#152](https://github.com/pyrycode/tui-driver/issues/152) (chain slices 2–3), [#154](https://github.com/pyrycode/tui-driver/issues/154) (removes the now-dead whole-buffer paths), [#156](https://github.com/pyrycode/tui-driver/issues/156) (`esc to interrupt` second busy anchor), [#90](90.md) (Render-vs-StripANSI split), [#69](69.md) (stuck-`✻` wedge)

**Slice 4/6 of the rendered-grid refactor (Cross-Repo Code Review 2026-07-03; the chain fixes CRITICAL A + B).** Ports the **idle/busy axis** — `IsIdle` / `IsThinking` — off `bytes.Contains(StripANSI(snap), …)` over the whole append-only *history* buffer and onto the addressable rendered `Grid` from [#150](150.md), scoped to the **bottom status region** of the visible screen. Closes both CRITICAL-B forgeries on this axis: (1) a literal spinner glyph `✻` printed as mid-transcript markdown / tool output forged "thinking" while the session was idle; (2) — the dangerous direction — a stale input-prompt glyph `❯` scrolled off into history forged "idle" while a turn was running, so the consumer wrote its next prompt into the in-flight turn with no error at any layer.

## Summary

One production file (`pkg/tuidriver/state.go`); the `IsIdle`/`IsThinking` bodies are rewritten, everything else in the file untouched. No new exported symbol, both signatures unchanged (`IsIdle(snap []byte) bool` / `IsThinking(snap []byte) bool`) — each builds its own grid internally with `NewGrid(snap, 0, 0)`, so grid dimensions never leak and all ~15 call sites (`events.go`, `ready.go`, `deliver.go`, every `cmd/spike-*`/`cmd/probe-*`) compile and behave unchanged. Same "view built inside, dimensions never leak to callers" posture as `DetectModalClass`.

Two new unexported symbols plus the inline grid build:

- `statusRegionRows = 6` — bounds the idle/busy region to the bottom 6 rendered rows. Sized to include the idle input line (`❯`, ~row −3 from bottom in the committed captures) and the spinner line redrawn adjacent above it (`✻`, ~row −5), while excluding transcript body above the overlay (~−6 and up when idle). Calibrated from the real `.bin` captures and pinned in **both** directions by the regressions: too small fails the realistic-thinking pin, too wide fails the forgery cases.
- `busyInRegion(g *Grid) bool` — **THE single busy predicate** for the axis: `g.ContainsInLastRows(string(SpinnerGlyph), statusRegionRows)`. Region-scoping lives in exactly one place so `IsIdle` and `IsThinking` stay coherent, and [#156](https://github.com/pyrycode/tui-driver/issues/156) folds its `esc to interrupt` anchor in here as an OR against the grid's space-preserved form.

`IsThinking(snap)` is `busyInRegion(NewGrid(snap,0,0))`. `IsIdle(snap)` builds the grid, returns `false` unless `❯` is in the region, then returns `!busyInRegion(g)` — the load-bearing conjunction (`❯` present in the region AND no busy anchor in the region), now region-scoped, preserved because `❯` is redrawn beneath the spinner while thinking so prompt-present alone is still not enough.

The existing `IdleGlyph` / `SpinnerGlyph` `[]byte` vars are kept (they have other consumers — `deliver_test.go`, the spike PTY-quiescence predicates) and converted to `string` at the `ContainsInLastRows` call. `StripANSI` is no longer used by these two functions — vt10x inside `Render` restores the CSI-wrapped glyphs into cells — but the import stays for `ParseSpinner` / `ParseSpinnerTokens` in the same file, which are **unchanged** (still whole-buffer `StripANSI`; only the idle/busy predicates moved onto the grid). `go test`/`go vet` green.

## Patterns established

- **One region-scoping seam per axis (`busyInRegion`), so coordinated slices edit exactly one place.** The busy check is a single unexported function both predicates call, rather than each inlining `ContainsInLastRows(SpinnerGlyph, …)`. This is what lets [#156](https://github.com/pyrycode/tui-driver/issues/156) add `esc to interrupt` as an OR in one location and stay automatically region-scoped and coherent across both predicates — and what guarantees [#154](https://github.com/pyrycode/tui-driver/issues/154) finds **no** parallel whole-buffer path on this axis to remove. The chain's "converge on one coherent busy predicate" coordination note becomes a structural property, not a review reminder.
- **Region-scoped predicates calibrate a small last-N window from the real captures, pinned in both directions by tests.** `statusRegionRows = 6` is not a guess: the `❯` row-from-bottom was measured across the committed `.bin` captures (real idle line at −3; scrolled-off cases at −20/−21) and the spinner sits adjacent-above at ~−5. The value is a floor-and-ceiling sandwich — the realistic-thinking regression fails RED if it's too small to reach the spinner, the two forgery regressions fail RED if it's widened toward the whole grid. Contrast the **tall** panels ([#152](https://github.com/pyrycode/tui-driver/issues/152) mcp header 24 rows up): idle/busy is a bottom *overlay*, so a small N is correct and widening reintroduces the forgeries. If a live thinking frame ever shows the spinner higher than −6, bump the constant one line (tradeoff recorded in its docstring), don't widen ad hoc.
- **Grid migration converts the anchor `[]byte` to `string` at the call and keeps the vars.** `ContainsInLastRows` takes a `string`; the anchors stay `[]byte` (their other consumers untouched) and are wrapped `string(IdleGlyph)` / `string(SpinnerGlyph)` at the one call site. No new anchor form, no exported-surface change — the glyphs are single-rune so the [#152](https://github.com/pyrycode/tui-driver/issues/152) `Doyouwanttoproceed` space-eating landmine does not bite them (that constraint returns for #156's multi-word `esc to interrupt`, which must key on the grid's space-preserved form).

## Lessons learned

- **Grid fixtures need `\r\n` between rows or vt10x staircases them — the same [#150](150.md) invariant, here as a shared `gridRows` helper.** The new regressions build snapshots with `gridRows(rows ...string) []byte` (joins with `"\r\n"`); a bare `"\n"` is line-feed-only through the emulator and renders a diagonal drift, not fresh rows. There is no dedicated idle/thinking `.bin` capture (the state tests use inline byte fixtures), so the two forgery cases and the realistic-thinking case are **synthetic** `\r\n` grids — same posture as #152's classes-with-no-real-fixture. Placing the forged glyph ≥ 8 rows above the bottom keeps it clear of the 6-row region regardless of minor layout drift.
- **The forgery regressions assert the raw-substring contrast so the fix can't silently regress.** Each forgery test also asserts `strings.Contains(string(snap), …)` is **true** for the same bytes — i.e. a whole-buffer substring match *would* forge the wrong answer, and only region-scoping gets it right. If a future refactor reintroduced a whole-buffer path, the raw match stays true (test stays green there) but the `IsIdle`/`IsThinking` assertion flips RED — the contrast, not just the positive case, is the guard.
- **Existing behaviour is preserved because the region clamps to all rows on tiny fixtures.** Every pre-existing idle/thinking unit test uses a 1–2-row inline fixture; `ContainsInLastRows(x, 6)` clamps `n` to the row count, so on a 1-row grid it scans that one row — identical to whole-buffer for a single-line snapshot. `TestIsIdleStripsANSIBeforeChecking` (`\x1b[…m❯\x1b[39m hint`) still classifies idle: `Render` lands `❯` in a cell, the row reads `❯ hint text`, the region contains it. The real-capture guard (`mcp-empty-snapshot.bin`, genuine `❯` at −3) still reports idle, unchanged from the whole-buffer era. The modal/scrolled captures (`agents`/`mcp`/`picker`) intentionally reclassify under region-scoping and are downstream-harmless — the `Events` merge loop's modal axis dominates idle/thinking (see [system-overview § Key signals](../architecture/system-overview.md)).
- **Region-scoping incidentally sidesteps the [#69](69.md) stuck-`✻`-in-rolling-buffer wedge — noted, not actioned.** The documented #69 wedge (a `✻` stuck in the 4 KB rolling *history* buffer after `end_turn` keeps whole-buffer `IsThinking` true forever, which the spikes work around with PTY-quiescence and by deliberately avoiding `IsIdle`) no longer bites the region-scoped predicates: once claude redraws the idle box, the stale spinner line has scrolled above the last-6 window. **This slice does not touch the spikes.** Whether a consumer can now drop the quiescence workaround is a separate consumer-side investigation — flagged, not done here.
- **Documentation stale-branch caveat (INDEX / system-overview hot lines).** This slice was cut from `main` before the sibling slices #151/#152 merged, so its edits to the shared `INDEX.md` line and the `system-overview.md` Grid-chain bullet insert a "slice 4/6 landed" clause into the pristine #150 text. If #151/#152 land first, git will 3-way-conflict on those exact lines — the resolution keeps all slice clauses. This is the known shared-append surface the per-ticket-file convention exists to avoid; the chain-wide architectural fix (auto-generated INDEX / dispatcher-side pre-doc rebase) is tracked, not re-filed per slice.
