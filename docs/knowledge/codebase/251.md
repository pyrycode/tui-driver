# #251 — de-gate `probe-cwd-encoding`: projects-dir stopped appearing within its 30s poll

[Issue](https://github.com/pyrycode/tui-driver/issues/251) · [Spec](../../specs/architecture/251-probe-cwd-encoding-degate.md) · [PR #254](https://github.com/pyrycode/tui-driver/pull/254) · Split from [#250](https://github.com/pyrycode/tui-driver/issues/250) · Siblings: [#252](https://github.com/pyrycode/tui-driver/issues/252) (snapshot-drift), [#253](https://github.com/pyrycode/tui-driver/issues/253) (spike-permission) · Feature doc: [e2e harness](../features/e2e-harness.md)

## Summary

On claude 2.1.199, `probe-cwd-encoding` ([#206](206.md)) started timing out *before* it can observe: its internal 30s `sessionFileWait` glob-poll (`cmd/probe-cwd-encoding/main.go`) never finds a `~/.claude/projects/<encoded-cwd>` directory, so the rig exits non-zero with no library signal. Diagnosis (recorded in the check-definition comment and an [issue comment](https://github.com/pyrycode/tui-driver/issues/251#issuecomment-4924790949)): **first-prompt-readiness**, the structural twin of `probe-first-prompt-hang` ([#181](https://github.com/pyrycode/tui-driver/issues/181)) — the probe's throwaway `"hi\r"` (sent only to make claude write its deferred session JSONL, which materialises the projects-dir) lands on a false idle before claude's input handler is wired, so the keystroke is dropped, no JSONL is ever written, and the glob-poll times out. An `EncodeCwd`/path change is excluded structurally: `discoverProjectsDir` globs by session-id (`.../*/<session-id>.jsonl`), never by `EncodeCwd`'s output, and this same 2.1.199 build observed the projects-dir cleanly on 2026-07-06 — the directory now fails to appear *at all*, not under a changed name.

The fix is a single field: `NonGating: true` added to the `probe-cwd-encoding` `Check` literal in `cmd/e2e-runner/main.go`, plus a rewritten leading comment carrying the diagnosis, the why-de-gate-not-re-anchor rationale, and the re-gate condition (mirrors `probe-first-prompt-hang`'s #181 comment). `SuccessMarker: observedSuccess`, the `OnFailure` `recording_dir` scraper, and the unset `Timeout` (60s default) are all preserved — the probe still runs on every `make e2e` and still ships `OBSERVED` + records its artifact when the environment lets it observe; it just no longer reddens the gate when it can't. `pkg/tuidriver/` and `cmd/probe-cwd-encoding/main.go` are untouched — no library behaviour changed. A dated entry was also appended to `cmd/probe-cwd-encoding/README.md`'s empirical log.

Re-anchoring (having the probe wait for a real readiness signal instead of the false idle) was considered and rejected: the only idle predicate in the library is `IsIdle` (the bare `❯` glyph) — the very signal that produces the false idle — and [#173](https://github.com/pyrycode/tui-driver/issues/173) Open Q1 already established that a positive "clean idle vs. pre-ready chrome" signature is infeasible to build in the claude-free `make check` gate without a live capture. Any re-anchor attempt would be an unverified, live-claude-gated hypothesis — exactly what the spike-from-fix split rule (see [#165](165.md)/[#166](166.md) precedent) exists to prevent shipping without evidence.

## Patterns established

- **`NonGating: true` is the standing de-gate mechanism, now used twice.** `gateFailed` (`cmd/e2e-runner/main.go`) returns `false` for any `NonGating` check regardless of status — the check's result still lands in the report (status, `recording_dir`, etc.) but never reddens the suite. First used for `probe-first-prompt-hang` (#181), now reused verbatim for `probe-cwd-encoding`. No runner-logic change was needed either time; the field alone is the whole behaviour. Reuse posture: when a recording/observation rig starts failing on an environment/timing crux with no in-library fix available, de-gating via this existing field is the evidence-based, minimal move — don't build a new mechanism.
- **Diagnosis lives in the check-definition comment, not just the commit message.** Both de-gated checks now carry their full diagnosis (root cause, why-not-re-anchor, re-gate condition) inline in the `Check` literal's leading comment — the in-repo authoritative record a future reader hits first when looking at `buildChecks`.

## Lessons learned

- **A claude-free `make check` gate cannot disambiguate "intermittent" from "total" non-appearance, and it doesn't need to.** Both readings — a false-idle race, or claude deferring the JSONL write even longer than before — resolve to the same posture (de-gate), so the diagnosis didn't need a live capture to be actionable. When two candidate root causes converge on the same fix, it's fine to leave them formally undistinguished rather than manufacturing evidence.
- **Re-gating is a distinct, deferred piece of work, not a footnote.** The spec's Open Questions name the re-gate path explicitly: a spike-from-fix pair (child A re-anchors + observes across N live `make e2e` runs whether it's reliable; child B, blocked-by-A, drops `NonGating` only if A proves it out). No such follow-up ticket exists yet — if the operator wants `probe-cwd-encoding` gating again, that pair needs to be filed.
