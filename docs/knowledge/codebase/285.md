# #285 — corpus-sampler: per-cast result cache keyed by a detector-version hash

[Issue](https://github.com/pyrycode/tui-driver/issues/285) · [PR #286](https://github.com/pyrycode/tui-driver/pull/286) · Mirrors [#261](261.md) (corpus-replay's cache) · Sibling of the corpus family: harness [#255](255.md)/[#256](256.md), extra sources [#272](272.md)/[#273](273.md)/[#274](274.md), fixture promotion [#258](258.md) · Code: `cmd/corpus-sampler/cache.go` (new), `cmd/corpus-sampler/cache_test.go` (new), `cmd/corpus-sampler/main.go`, `cmd/corpus-sampler/README.md`

## Summary

Same shape as #261, adapted for the sampler's cross-cast dedup. A cast's sampler result is a pure function of three inputs — the cast bytes, the four mode inputs (`-gap` resolved to seconds, `-final`, `-fires`, `-midstream`), and the detection + sampling code — so a re-run over the immutable, additive corpus (2118 recordings, 1.1 GB, ~6h cold on the fanless Air) was redoing identical work every time. This adds an on-by-default per-cast cache: a routine re-run now samples only the handful of new recordings; editing any detector source or any mode flag invalidates the whole cache.

The key is `sha256(version + "\x00" + mode + "\x00" + castName + "\x00" + contentHash)` (`sampleCache.key`, `cache.go:130`). `version` is `versionHash` folding every `*.go` file's path+content under **both** `pkg/tuidriver` and `cmd/corpus-sampler` — the #261 catch applies identically here: the sampler's own logic (`normalize`, `hashGrid`, `activeKeys`/`flatDetectors`, the gap/final/fires/midstream branches in `sampleCast`, `segmentOf`, `tagFromName`) determines what a cast yields just as much as the library detectors do. `mode` is new relative to #261 (which folds one resolved stride per-call) — the sampler has four run-level flags, so they're folded once at construction (`newSampleCache`, `cache.go:112`) into one string, so a `-fires`-on entry can never satisfy a `-fires`-off lookup.

The one real design difference from #261: **no serializable mirror struct**. corpus-replay's `castResult` has unexported fields and needs a tagged `cacheEntry` round-trip; the sampler's `sample` type is already fully `json:"…"`-tagged (it's marshalled straight to `-out`), so `sampleCacheEntry{Samples []sample; Events int; Gaps int}` wraps it directly. `Events`/`Gaps` are load-bearing — without them a warm run's `casts=… events=… gaps=…` aggregate would drift from a cold run.

The other real difference: **the cache stores the pre-dedup per-cast sample list, not an independent per-cast result**, because the sampler dedups screens across casts (corpus-replay's replay result is independent per cast). `collect` keeps its 5-arg/5-return signature (21 call sites) and delegates to a new `collectCached`, which swaps the direct `sampleCast` call for a `sampleOrLoad` wrapper and tallies hits/misses; the existing cross-cast dedup loop (the `idx` hash map + `mergeSources`) runs unchanged over the union of cached and freshly-sampled lists — a screen a cached cast contributes still dedups against an identical screen in a fresh cast, because every cast's list (cached or fresh) flows through the same `idx` map. `sampleCast` itself is untouched.

Two new flags mirror #261 exactly: `-no-cache` (bypass, never read/write) and `-cache-dir` (override; default `os.UserCacheDir()/corpus-sampler`, a distinct basename from corpus-replay's own dir). Cache-construction failure degrades gracefully to `cache = nil` with a stderr warning — stdout and `-out` stay byte-identical to a `-no-cache` run either way. The hit/miss summary line goes to stderr only. Single-threaded throughout (no `-workers` — the ticket explicitly rejects sampler parallelism: the fanless Air throttles under sustained multi-core load, so caching, not racing, is the right lever), so each cache file is touched by exactly one goroutine at most once per run — no mutex needed.

## Patterns established

- **When a cached type is already the wire format (fully JSON-tagged for its own primary output), skip the serializable-mirror step.** #261 needed `cacheEntry`/`toCacheEntry`/`toResult` because `castResult` had unexported fields; here `sample` already marshals straight to `-out`, so the cache entry is a plain wrapper struct with zero round-trip machinery. Check whether the domain type is already externally-serialized before reaching for a mirror.
- **Multiple run-level mode flags fold into one signature computed once at construction, not per-call.** Where #261 passes a single resolved value (stride) to `key` per call, a tool with several flags that jointly determine output shape (`-gap`/`-final`/`-fires`/`-midstream`) instead precomputes one delimited string in the constructor, alongside the version hash — both are "compute once, read-only after" invariants for the run.
- **A cache over a cross-item-dedup pipeline caches the pre-dedup per-item output, and the existing dedup loop runs over the union of cached and fresh items unchanged.** This is the reusable shape for any future corpus-family tool that both (a) wants a per-cast cache and (b) dedups across casts: cache what the per-cast function returns before the dedup step, not an already-deduped result — the dedup step doesn't need to know or care which per-cast lists came from cache vs. fresh work.
- **Freeze a many-call-site function's signature by having it delegate to a new cache-aware sibling.** `collect` (21 call sites) becomes a one-line delegator to `collectCached`, exactly as #261 froze `replayAll`'s signature the same way — the reusable move whenever a cache needs to thread a new parameter (here, `*sampleCache`) and a new return (`cacheStats`) through a widely-called function.

## Lessons learned

None beyond what #261 already documented (corrupt-entry-is-a-miss, byte-identity as the real cache-transparency test, resolved- not requested-value keys) — this ticket was a mirror with zero deviation from the architect's spec, so #261's lessons carry over directly rather than needing restatement.
