# #89 — library API: promote watchdog goroutine pattern + `matchSpinner` to `pkg/tuidriver`

[Issue](https://github.com/pyrycode/tui-driver/issues/89) · [Spec](../../specs/architecture/89-watchdog-loop-primitive.md) · Predecessors: [#47](47.md), [#61](61.md), [#62](62.md), [#87](87.md)

## Summary

Promoted the 1 Hz watchdog goroutine (copy-pasted inline across 7 spike binaries) and its sibling `matchSpinner` regex into `pkg/tuidriver` as `RunWatchdog(ctx, *Buffer, *Tracker, WatchdogOpts) error` + `ParseSpinner(snap) (verb string, totalSeconds int, ok bool)`. `RunWatchdog` blocks on the calling goroutine driving the per-tick work list — `Buffer.Snapshot` → `ParseSpinner` (strips ANSI internally) → `Tracker.ObserveSpinner` → `Tracker.CheckWatchdog` — and returns `nil` on `ctx`-cancel or the `CheckWatchdog` error verbatim on wedge. `WatchdogOpts.Tick` is the testability seam (zero falls through to `DefaultWatchdogTick = 1 * time.Second`); the production knob is unused (every consumer leaves it zero). `ParseSpinner` lives next to `ParseSpinnerTokens` in `state.go` under the same template — package-private regex (`spinnerForRe`), exported pure function over `StripANSI(snap)`, documented class-incompleteness (matches class A only; classes B/C/D return `ok=false`).

`cmd/spike-long-prompt` migrated as the proof-of-usability consumer: the 22-line inline `go func()` ticker collapses to 5 lines wrapping `RunWatchdog`, the in-handler `matchSpinner(tuidriver.StripANSI(rb.Snapshot()))` call (the spike's stricter-than-`EventKindPtyThinking` fast-path gate documented in [#62](62.md)) flattens to `tuidriver.ParseSpinner(rb.Snapshot())`, and the local `matchSpinner` function + `spinnerRe` var + `watchdogTick` constant + the now-unused `regexp` and `strconv` imports all delete. Net: 61 lines changed in `main.go`, the binary still builds clean, and `go test -race ./...` is green. The six remaining spikes (`spike-one-turn`, `spike-multi-turn`, `spike-cancel`, `spike-permission`, `spike-ask-user`, `spike-multiselect`) keep their local copies — mechanical follow-up sweep, one ticket per spike, each diff identical in shape to the spike-long-prompt migration here.

The architect picked design (a) from the ticket's Technical Notes (bundle the regex with the loop) over design (b) (loop-only with a per-tick callback). Two reasons stick: the regex is **identical** across all 7 spikes (verified by `grep -n spinnerRe cmd/*/main.go`) so leaving it behind would have left 7 future deletion sites for a follow-up to chase; and the spike consumer's downstream-of-the-loop call site at `main.go:250` ALSO calls `matchSpinner` (the fast-path gate from [#62](62.md)), so design (a) lets both call sites consolidate onto the library function while design (b) would have kept the local copy alive solely for the in-handler call. Library surface grew by three exported names + one constant — well under the size budget.

Two architectural decisions worth flagging. First, **returned-error rather than callback or cancel-cause** for the wedge-surfacing shape: callback couples the library to the consumer's logging/cancellation strategy and forces a decision about inline-vs-goroutine callback execution; cancel-cause integration couples the library to `context.WithCancelCause` specifically. Returned-error is the idiomatic Go shape for "blocks until done, may fail" and matches the consumer's existing `log.Printf("%v", err); cancelCause(err)` pattern verbatim — the only thing the library hides is the ticker bookkeeping. Second, **free function not a method**: neither `*Tracker` nor `*Buffer` is the natural owner (the loop reads both); putting it on either would conflate "synchronous predicates a caller invokes" with "blocking loop a caller spawns." A new `watchdog.go` file holds the loop; godoc on the loop carries the per-tick work list, the two return conditions, the recommended consumer pattern (3-line `go func()` snippet), and the cross-references to `Tracker.ObserveSpinner` + `Tracker.CheckWatchdog` + `Buffer.Snapshot`.

## Patterns established

- **Per-tick work-list bundling over callback indirection.** When a library primitive's "per-tick" body is the same composition across every observed consumer (`Snapshot` → `StripANSI` → regex → `ObserveSpinner` → `CheckWatchdog` in this case), bundle the whole list inside the primitive — don't expose a `tickFn` callback. Rationale: the callback shape forces every consumer to either reproduce the calibrated work-list or import individual helpers; bundling locks the validated composition behind one entry point and makes divergence a deliberate API addition rather than a copy-paste drift. The cost is one extra ParseSpinner-style helper per work-list step (here `ParseSpinner`), but each of those helpers is independently useful and lives next to its sibling on the package's existing axes (`state.go` for snapshot-extractors). Mirrors `Events()`'s [#61](61.md) "library owns the merge loop, consumer owns the state machine" division: the library encapsulates the well-calibrated composition; the consumer parameterises only what genuinely varies (Tick, Tracker construction, what to do with the returned error). Reuse posture: when a future primitive has a copy-pasted "per-tick body" across N spikes whose contents are byte-identical, default to bundling unless one of the steps genuinely needs per-consumer customisation today — not "could conceivably need it." YAGNI applies to API design too.
- **Returned-error shape for "blocks until done, may fail" library primitives.** `RunWatchdog`'s signature `(ctx, *Buffer, *Tracker, WatchdogOpts) error` is the idiomatic Go shape: caller spawns a goroutine, reads the return, logs+cancels as they see fit. Convention: `nil` on `ctx`-cancel (the caller asked to stop, matching `Spawn` / `Session.Wait`); the underlying error verbatim on detected failure (suitable for `log.Printf("%v", err)` without wrapping — the error string already names the failure mode). Reuse posture: when a library primitive needs to signal "I'm done, here's how it ended," default to returning the error and trust the consumer to compose it with their cancellation strategy. Callback-shaped APIs (`onWedge func(error)`) couple the library to the consumer's logging/cancellation/threading conventions; cancel-cause-shaped APIs (taking a `context.CancelCauseFunc`) couple to one specific cancellation style. Both are reasonable; both are wrong-by-default for primitives that already block on the caller's goroutine. Mirrors `Session.Wait()`'s shape from earlier work.
- **Sibling-extractor placement in `state.go`.** `ParseSpinner` (class-A verb+counter) lives next to `ParseSpinnerTokens` (class-C tokens) under the same template — package-private regex var (`spinnerForRe`), exported pure function taking `[]byte` and returning a tuple including `ok bool`, godoc that names which spinner-class renderings the regex matches AND which it skips (class-incompleteness is by-construction, the same way `ParseSpinnerTokens` is incomplete for classes A/B). The naming pair (`ParseSpinner` extracts verb+seconds, `ParseSpinnerTokens` extracts the token counter) mirrors how `IsIdle` / `IsThinking` coexist: both refer to "the spinner," the suffix tells the reader which field. Reuse posture: when adding a sibling extractor that pulls a different field from the same snapshot shape, place it next to its sibling under the same template — same file, same regex-as-package-var convention, same godoc structure listing class hits and class misses. The class-coverage doc in each godoc lets future consumers immediately see whether their snapshot variant is in scope without reading the regex. Naming disambiguation matters: the new regex var is `spinnerForRe`, not `spinnerRe`, because the existing `spinnerTokensRe` and `SpinnerGlyph` would otherwise collide on the bare "spinner" stem.
- **Synthetic-wedge tests via short Tracker limits + sub-100 ms ticks.** `watchdog_test.go` drives both wedge arms without a clock seam by composing real wall-clock with short limits: `TrackerOpts{PTYQuietLimit: 50 * time.Millisecond}` + `WatchdogOpts{Tick: 20 * time.Millisecond}` puts the PTY-quiet-arm test under 100 ms total; the spinner-freeze test adds a helper goroutine (`go func() { for { case <-warmCtx.Done(): return; case <-ticker.C: buf.Append([]byte("\x1b[?25h")) } }`) that pumps ANSI noise into the buffer to defeat the PTY-quiet arm while keeping the class-A spinner rendering frozen so the freeze arm fires. The ANSI noise gets stripped before `ParseSpinner` runs, so the spinner regex keeps matching `("Baked", 2, true)` on every tick — `ObserveSpinner` records no progress and the freeze arm trips at 50 ms. Same wall-clock-and-short-limits idiom `tracker_test.go` uses for `TestTrackerCheckWatchdogQuietBuffer` / `TestTrackerCheckWatchdogSpinnerFreeze`, scaled for the loop-wrapping primitive. Reuse posture: when a library primitive's behaviour depends on time progression but the calibration thresholds are configurable, parameterise the threshold (Tracker limits) AND the loop period (Tick) — let tests drive both small to keep test durations sub-200 ms, leave the production-time defaults untested-at-real-cadence (the constants document themselves; the loop semantics are what gets tested). The clock-seam pattern from [#87](87.md) (`var sleepFn = time.Sleep` package var) is not needed here because the Ticker IS the seam — `time.NewTicker(opts.Tick)` cycles at whatever the test asks for, no indirection required.
- **The `TestRunWatchdogDefaultTickApplied` indirect-proof pattern.** Verifying a default-value fallthrough without exporting the internal `tick := opts.Tick; if tick <= 0 { tick = DefaultWatchdogTick }` switch: pass `WatchdogOpts{}` (zero value), set `PTYQuietLimit = 50 ms` (would otherwise wedge), set `ctx` timeout to 250 ms, assert the call returns `nil` (no wedge fired because the first tick at ~1s never landed inside the 250 ms ctx window). The 1s default suppresses the early wedge that the 50 ms PTY-quiet limit would have caught with any sub-second tick; the ctx-cancel return is the proof the loop ran at all. Indirect proof — better than exporting the gate just so a test can read it. Reuse posture: when verifying a zero-value default falls through to a constant, design the test to put the default and the early-failure threshold on opposite sides of the test-window deadline. If the wedge fires before the timeout, the gate didn't apply; if the timeout fires, the gate did. No extra exports needed.

## Lessons learned

- **The architect's design (a) vs (b) choice was load-bearing — and the right call was the one that saw the downstream-of-the-loop call site, not just the loop body.** The ticket's Technical Notes framed both shapes as "satisfy the AC." What tipped the choice toward design (a) wasn't the loop-internal de-dup (either shape removes the 7 inline ticker copies); it was that `matchSpinner` is also called from `cmd/spike-long-prompt/main.go:250` inside the Events() handler — the documented fast-path gate from [#62](62.md). Under design (b) the spike would have kept its local `matchSpinner` alive solely for that one call site, defeating most of the "consumer shrinks to one library call" payoff. Under design (a) both call sites use `tuidriver.ParseSpinner` and the spike file loses 15 lines instead of 8. Reuse posture: when an architect is choosing between "extract one thing" vs "extract two related things," count call sites not just bodies. If the consumer keeps a local helper alive for a downstream use that wasn't in scope for the original extraction, the de-dup payoff partially evaporates and the smaller extraction starts to look like the wrong shape. Same scoping consideration applies to any future primitive whose helpers ride along inside an Events()-handler `switch`.
- **`time.NewTicker` panics on a non-positive duration — the default-injection guard is mandatory, not defensive.** `RunWatchdog`'s entry block reads `tick := opts.Tick; if tick <= 0 { tick = DefaultWatchdogTick }` BEFORE `time.NewTicker(tick)`. The `<= 0` check (not `< 0`) is the load-bearing one: callers passing `WatchdogOpts{}` get `Tick = 0` (Go zero value for `time.Duration`), and `time.NewTicker(0)` panics with `non-positive interval for NewTicker`. The convention conflates "zero (default)" with "negative (caller error)" because there's no production scenario where a consumer wants a negative tick AND no scenario where zero means "no ticking" (the whole primitive's contract is "tick at some rate"). Reuse posture: when a library primitive takes a `time.Duration` field on an opts struct, default-inject on `<= 0` (treats the Go zero value and the caller-error case identically), document the default value in the field's godoc, and put the gate at the top of the function before any time-typed API call. The `<` 0 variant would let `Tick = 0` reach `time.NewTicker` and panic — same crash, worse error message.
- **The spike's `regexp` and `strconv` imports were both load-bearing for the local `matchSpinner` only — `go vet` flags them as unused the moment the function deletes.** This is in contrast to [#87](87.md)'s migration of `spike-ask-user`, where `os` and `time` stayed because they had other call sites beyond the deleted helpers. The asymmetry is informative: when planning a future spike migration, check whether the import IS unique to the helper being deleted. `regexp` was unique to `spinnerRe`/`matchSpinner` here; `strconv` was unique to the `strconv.Atoi` inside `matchSpinner`. Both vanished in lockstep. Reuse posture: when the in-tree sweep migrates the other six spikes off `matchSpinner`, expect `regexp` to disappear from every spike's import list (none of them use regex for anything else); `strconv` is more variable — depends on whether the spike has any other numeric-string handling. The mechanical-template diff shape from [#62](62.md) and [#87](87.md) holds; only the import-list deletions vary per-spike.
- **The spinner-freeze test needs a warm-keep helper goroutine to defeat the PTY-quiet arm — the two wedge arms interact.** The first draft of `TestRunWatchdogSpinnerFreezeWedge` set `PTYQuietLimit = 1 * time.Hour` (disable arm A) and tried to drive only arm B with a static buffer. That works for ~50 ms then `CheckWatchdog` returns the PTY-quiet error anyway, because `Buffer.QuietFor()` reads "time since last `Append`" regardless of which arm the test wants to exercise. The fix is the warm-keep goroutine that `Append`s ANSI noise every 10 ms — short of `PTYQuietLimit` but long enough to keep the spinner-rendering snapshot stable so `ParseSpinner` returns the same `("Baked", 2, true)` tuple every tick and `ObserveSpinner` records no progress. The ANSI noise is `\x1b[?25h` (show-cursor escape, neutral); any byte string is fine as long as it doesn't contain `✻` (which would change `ParseSpinner`'s result) or `for Ns` text (would alter the verb capture). Reuse posture: when a future test exercises a multi-arm watchdog or a similar AND-of-predicates failure detector, isolating one arm requires actively defeating the others, not just disabling them via limits. The warm-keep pattern (helper goroutine pumping innocuous bytes) is the cheap shape; `t.Cleanup(warmCancel)` ensures the goroutine doesn't leak into the next test.
- **`Buffer.QuietFor()` reads "time since the last `Append`," not "time since `Append` of meaningful bytes."** Documented elsewhere but worth restating: the watchdog's PTY-quiet arm fires based on Buffer activity alone, with no awareness of what was written. This is exactly why the spinner-freeze test's warm-keep goroutine appends bytes purely for their side effect on `QuietFor()` — those bytes never need to be visible to `ParseSpinner` after StripANSI. Reuse posture: when reasoning about whether a wedge arm would fire in production, think of `QuietFor()` as "did anyone write to the buffer recently," not "did the buffer change meaningfully." A live PTY producing only ANSI cursor-position updates (no visible output) still resets `QuietFor`, which is the right behaviour — claude is alive, just not emitting content. The freeze arm is what catches the "claude appears to be working but isn't making progress" case.
