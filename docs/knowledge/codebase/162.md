# #162 — Base the JSONL commit signal on file growth, not existence

[Issue](https://github.com/pyrycode/tui-driver/issues/162) · [Spec](../../specs/architecture/162-jsonl-commit-signal-growth.md) · [PR #193](https://github.com/pyrycode/tui-driver/pull/193) · Commit `7587f20` · Touches [`deliver.go`](../../../pkg/tuidriver/deliver.go) · Sibling from the same review cluster: [#160](160.md)

**S bug fix from the Cross-Repo Code Review 2026-07-03 filing (`MEDIUM`).** `promptDidCommit` treated the mere *existence* of the per-session JSONL as a commit signal (`os.Stat(jsonlPath) == nil ⇒ committed`). But claude writes that file on the first commit of a session and **appends** to it thereafter (`jsonl.go` is explicit it is append-only), so from turn two onward "the file exists" is vacuously true: the signal fired instantly, before the current turn landed. The effect was that paste-recovery — the corrupted-paste re-deliver loop in `deliverPrompt` — was **silently disabled for every turn after the first**: a turn-two paste that never committed was reported committed, the recovery loop was skipped, and the turn wedged downstream. Not `security-sensitive` (verified on the issue labels — a JSONL-size signal correctness fix, no classification / attacker-content surface, despite the shared review-footer boilerplate that misattributes every Cross-Repo Code Review ticket to the rendered-grid classification root cause; same caveat as [#160](160.md)).

## Summary

The fix bases the signal on **growth past a pre-delivery baseline** instead of existence. Because the JSONL is append-only, a fresh append for the current turn always pushes the size up, while a stale file left by a prior turn that does not grow no longer counts as a commit. All changes are confined to `pkg/tuidriver/deliver.go`; **no public surface changes** — `DeliverOpts`, `DeliverResult`, the `DeliverPrompt` signature, and the `deliverDeps.didCommit` seam (`func(time.Duration) bool`) are all preserved. The consumer (pyrycode's `pyry agent-run`) keeps passing `JSONLPath` and reading `Committed`; it just observes more-correct `Committed` behaviour on turn two onward.

- **`promptDidCommit` gained a `baseline int64` parameter** (`func (s *Session) promptDidCommit(ctx, jsonlPath string, baseline int64, timeout time.Duration) bool`). The JSONL branch of the poll loop changed from `os.Stat(jsonlPath); err == nil` to `os.Stat(...); err == nil && info.Size() > baseline`. `int64` matches `os.FileInfo.Size()` — no conversion. Everything else in the loop is untouched: the `IsThinking(s.Snapshot())` spinner check stays **first** and still short-circuits to `true` regardless of JSONL state (AC 4); the `jsonlPath != ""` guard stays; the `time.NewTimer` + `time.NewTicker` + `select{ctx.Done/deadline/tick}` shape is byte-for-byte the same. A stat error (missing file) still reads as "no growth yet, keep polling" — identical control flow to the old `err == nil` guard simply not firing.
- **`DeliverPrompt` captures the baseline once, before delivery.** Before the `deliverPrompt(...)` call it stats `opts.JSONLPath` and records `info.Size()` into a captured `baseline`; a `""` path or a stat error reads as `0`. The `didCommit` closure threads that captured value through: `s.promptDidCommit(ctx, opts.JSONLPath, baseline, timeout)`.
- **Three godoc blocks corrected** from existence to growth wording (prose only, no behavioural weight, but leaving them stale re-teaches the bug): `DeliverOpts.JSONLPath` ("treats the file's appearance as a commit signal" → grows past its pre-delivery size), the `DeliverPrompt` "Commit confirmation" bullet ("the per-session JSONL has appeared" → has grown past its pre-delivery size), and `promptDidCommit`'s own doc.

Test coverage extends `TestPromptDidCommit` in `deliver_test.go` (the function is exercised directly against a temp JSONL under `t.TempDir()`, mirroring the existing subtest idiom). The four existing call sites gained the `baseline` argument; the single "jsonl file present" subtest was restructured into a growth pair plus the AC-4 spinner-wins case:

- **spinner wins over a non-growing JSONL** (AC 4): spinner in buffer + JSONL exists at exactly `baseline` (no growth) → true, because the spinner short-circuits before the growth check runs. This is the AC-4 case the old suite did not cover (its spinner test used `jsonlPath == ""`).
- **JSONL grows past baseline** (AC 3 / turn one): no spinner, non-empty file, `baseline == 0` → true (`N > 0`). Models the file first appearing with content, or growing from empty.
- **pre-existing JSONL that does not grow** (AC 1/2/5 / turn two): no spinner, file at size `N`, `baseline == N`, short 120 ms timeout → false, and asserts the poll **honoured** the timeout (returned in ≥100 ms, didn't short-circuit). This is the regression the ticket restores.

The `TestDeliverPrompt_*` table tests inject a fake `didCommit func(time.Duration) bool`, so the preserved seam signature means they needed **no** change (confirmed, not edited).

## Patterns established

- **Capture-once outside the retry loop is load-bearing.** The baseline is stat'd in `DeliverPrompt` (before `deliverPrompt` runs), not inside `promptDidCommit`. `deliverPrompt` may invoke the `didCommit` closure multiple times across re-delivery attempts; the closure captures the single pre-delivery baseline, so every attempt is measured against the file state *before this turn began*. If the baseline were re-stat'd inside `promptDidCommit`, attempt 2 would fold attempt 1's growth into its own baseline and the growth check would regress to always-true — the same vacuous-truth failure one turn deeper. When a poll predicate compares against a "before" snapshot, capture the snapshot at the boundary of the retried region, not inside the retried body.
- **Refining a signal's *meaning* without touching its *seam* keeps the fake-driven tests free.** The internal predicate went existence→growth, but `deliverDeps.didCommit` stayed `func(time.Duration) bool` and the growth logic lives below it in the real `promptDidCommit`. Result: every `TestDeliverPrompt_*` table test — which drives the loop through fakes — stood as-is, and only `TestPromptDidCommit` (which exercises the real predicate directly) changed. This is the same method→pure-driver→fakes seam [#160](160.md) and [#147](147.md) preserve on this file; a correctness fix that lives strictly *below* the injection boundary is a table-test-free edit by construction.
- **A stronger signal that adds a false-negative, never a false-positive, is the safe direction here.** `promptDidCommit` only observes — it never writes the PTY or the JSONL. Growth is *stricter* than existence, so the only new outcome it can produce is "not committed when existence would have said committed" → at most one extra re-delivery, never a corrupted live turn. This is the same cheap-false-negative posture already documented for `promptDidCommit` and for [#160](160.md)/[#147](147.md)'s `modalDismissed`: prefer "report not-done and let the caller re-observe" over "claim success."

## Lessons learned

- **A signal can be *vacuously* satisfied by an invariant it was written before.** The existence check was correct for exactly one session state — the very first turn, when the file does not yet exist — and silently wrong for every state after it, because the append-only invariant it shares a file with guarantees the file is present forever once written. The bug was invisible in single-turn spikes and only bites multi-turn consumers, which is why it survived to a cross-repo review rather than a unit test. When a boolean reads a shared resource, ask "what makes this false?" — if the answer is "a transient early condition that a later invariant erases," the predicate is measuring the wrong thing.
- **The append-only invariant is what makes byte-size a *sound* signal, not just a convenient one.** Because `jsonl.go` guarantees the file only ever grows (no truncation, no rotation — the "rare on an append-only file" note at `jsonl.go:148`), `size > baseline` is monotonic: once true within a poll window it stays true, and any real commit appends at least one full JSONL record (many bytes), so strict `>` on bytes needs no line-count parsing or `>=` fudge. The spec's rejected alternative — a stored line count re-read from file contents — would buy nothing over the size `os.FileInfo.Size()` hands you for free. No shrink/rotation defence was added because none is observed (evidence-based fix selection; don't ship a guard for an unobserved failure mode).
- **`IsThinking` remains the primary in-flight anchor; the JSONL signal is the backstop.** Per CLAUDE.md's spinner caveat the class-A `✻ Verb for Ns` *parse* is dead on claude 2.1.158, but bare-`✻`-presence `IsThinking` still works as "claude has started processing" and is checked first in the loop — untouched by this ticket. The growth fix only hardens the *second* signal (JSONL), which matters precisely when the spinner is absent (fast/short turns, or a delivery that never spun up).
