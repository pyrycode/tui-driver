# #167 — Distinguish a JSONL tail read error from a clean shutdown

[Issue](https://github.com/pyrycode/tui-driver/issues/167) · [Spec](../../specs/architecture/167-jsonl-tail-read-error-signal.md) · Commit `4757843` (spec `92f1b30`) · Touches [`events.go`](../../../pkg/tuidriver/events.go) + [`jsonl.go`](../../../pkg/tuidriver/jsonl.go) · Sibling error-signalling fix: [#160](160.md) · Reverses [#61](61.md)'s out-of-band discriminator

**S error-signalling fix from the Cross-Repo Code Review 2026-07-03 filing.** Not `security-sensitive` (verified on the issue labels) — same class as [#160](160.md), an error-signalling bug with no classification / attacker-content surface, despite the shared review-footer boilerplate that misattributes every Cross-Repo Code Review ticket to the rendered-grid root cause.

## Summary

`tailJSONLLoop` (`jsonl.go`) collapses every exit into one `defer close(ch)`. Three exits are ctx-driven and clean; the fourth — the `default:` arm on a non-EOF `ReadBytes` failure *after the goroutine has started* — closed the same channel the same way. `mergeEvents` read that close as `if !ok { return }` and closed its own `Events()` output identically, so a runtime tail-read failure was byte-for-byte indistinguishable, from inside the stream, from Claude finishing cleanly: a consumer blocked on `EventKindJsonlEndOfTurn` (or ranging `for ev := range events`) just saw the stream end.

The fix promotes an **existing invariant** to an in-band signal rather than adding plumbing:

- **`EventKindError`** — a new terminal `EventKind` (twelfth emittable kind), appended to the `events.go` const block. Emitted at most once, immediately before `Events()`' channel closes.
- **`Event.Err error`** — one new field on `Event`, populated only on `EventKindError` (nil otherwise), mirroring how `Modal`/`Entry` are kind-scoped.
- **`ErrJSONLTailRead`** — an exported sentinel (`errors.New("tuidriver: jsonl tail read failed")`) carried in `Err`; consumers match it with `errors.Is(ev.Err, ErrJSONLTailRead)`. It marks *that* the tail broke, not *why* — it does **not** wrap the os-level `ReadBytes` cause.
- **`mergeEvents` body-only change** — at the `!ok` branch, `if ctx.Err() == nil { send(Event{Kind: EventKindError, Source: EventSourceJsonl, Time: ..., Err: ErrJSONLTailRead}) }` before the deferred `close(out)`. `ctx.Err() != nil` (clean ctx-driven shutdown) emits nothing. Signature unchanged (~16 call sites untouched); reuses the existing backpressure-/ctx-aware `send` helper.
- **`tailJSONLLoop` reader widened `*os.File` → `io.ReadCloser`** — purely so a fault reader is injectable (a real `*os.File` cannot be made to return a deterministic non-EOF read error without platform-hacky fd tricks). `TailJSONL` still passes its opened `*os.File`; its `(<-chan JSONLEntry, error)` signature is unchanged and the production path is byte-identical. One reciprocal one-line comment binds the tail's `default:` arm to the merge-loop discriminator.

Three of the four table rows are unchanged: ctx cancel / deadline and EOF-then-shutdown still close cleanly with no error event; the synchronous open/seek failure still returns `(nil, err)` from `Events` (covered by the untouched `TestEvents_TailJSONLErrorBubbles`). This ticket only makes the fourth — the *runtime* read error — observable.

The `Events` doc-comment gained one clause naming the terminal event; `events.go` gained an `errors` import.

## The invariant the fix rests on

`tailJSONLLoop` closes its channel with `ctx.Err() == nil` **iff** it exited via the `default:` read-error arm — every other exit is ctx-driven, so `ctx.Err() != nil` at those closes. Therefore, at `mergeEvents`' `!ok` branch:

- `ctx.Err() == nil` → the tail broke on a read → emit `EventKindError`.
- `ctx.Err() != nil` → clean ctx-driven shutdown → emit nothing.

This is the **same discriminator [#61](61.md) already documented** (spec #61 line 271: "`ctx.Err() == nil` after channel close ⟺ read error") and deliberately punted out-of-band (spec #61 line 414: "consumers check `ctx.Err()` after the channel closes"). #167 reads it locally in the goroutine that already owns the emission point and makes it in-band. No new channel, holder, or relay carries the discriminator — it was already there.

## Patterns established

- **Act on an existing, already-documented invariant in-band rather than adding plumbing.** The whole fix is one `if ctx.Err() == nil { send(...) }` inside an already-existing branch. The rejected alternative — threading the wrapped `os` cause from the tail goroutine to the merge goroutine — needs either a new `mergeEvents` parameter (≈16 test call-site edits, trips the edit-fan-out red line) or a permanent per-subscription relay goroutine. The AC constrains the observable *signal* (distinguishable failure vs clean end), not the os-level cause, so a **sentinel is sufficient** and the plumbing is unwarranted. When a review flags "a signal exists but the consumer can't act on it," look for an invariant to surface, not machinery to add. (Same shape as [#160](160.md)'s "`ctx` reachability, not a missing check, was the whole bug.")
- **Widen a concrete param to an interface purely for a test fault-injection seam.** `tailJSONLLoop(ctx, *os.File, ch)` → `tailJSONLLoop(ctx, io.ReadCloser, ch)`. Production passes the opened `*os.File` (which satisfies `io.ReadCloser`), behaviour byte-identical; the one caller is `TailJSONL`, whose public signature is untouched. The type widen is the *minimal* seam — a real file fault would be nondeterministic and platform-hacky. The `faultReader` (`Read` hands out scripted good bytes, then returns a sentinel `errBoom`; `Close` returns nil) lives in `jsonl_test.go` and is shared into `events_test.go` (same package) for the end-to-end wiring.
- **The discriminator biases toward "clean" on any ambiguity — the safe report.** If a genuine read error and a consumer ctx-cancel race, `ctx.Err()` may already be non-nil at the `!ok` read, suppressing the `EventKindError`. This is intended: the consumer is shutting down anyway, and AC #2 requires ctx-cancel to close cleanly. A false-negative on a concurrent cancel is cheap; mirrors [#160](160.md)'s and [#147](147.md)'s "prefer not-done over false success" posture.
- **`Source` disambiguates origin, so the kind stays general.** `EventKindError` (not `EventKindJsonlError`) with `Source: EventSourceJsonl` naming the origin — consistent with how `Source` already separates PTY vs JSONL for every other kind, and leaving the kind free for a future PTY-side terminal error to reuse.

## Lessons learned

- **The discriminator was already there and already documented — the ticket is a reversal, not an invention.** [#61](61.md) knew about the read-error case, computed the exact `ctx.Err() == nil ⟺ read-error` invariant, and *chose* to leave it out-of-band ("consumers check `ctx.Err()` after the channel closes"). That works for a consumer that keeps the ctx handle, but is invisible to one that only ranges the stream — exactly the gap the Cross-Repo Code Review flagged, and the same "a signal that exists but the consumer can't act on it" class as #160. When a prior spec explicitly *tabled* a case with a documented invariant, revisiting it is often promoting that invariant in-band, not new design.
- **One existing test's contract flipped in place, because the fix changed what its action *means*.** `TestMergeEvents_JsonlChClosureClosesOutput` closed `jsonlCh` with ctx live and asserted a clean `out` close — but that action *is* the read-error simulation, so under this design it must now yield `EventKindError` first. It was renamed `TestMergeEvents_JsonlChClosureCtxLiveEmitsError` and its assertion flipped, rather than adding a parallel test and leaving a now-wrong one. When a fix changes the meaning of an action an existing test performs, flip that test in place. Two companions were added: `TestMergeEvents_JsonlChCloseAfterCancelEmitsNoError` (EOF-then-shutdown clean-path, AC #4 companion) and the end-to-end `TestMergeEvents_ReadFaultSurfacesTerminalError` (`faultReader → tailJSONLLoop → jsonlCh → mergeEvents → out`), plus the tail-layer `TestTailJSONLLoop_ReadErrorClosesChannelCtxLive` asserting the channel closes with `ctx.Err() == nil`.
- **A `*os.File` is the wrong seam for injecting a read fault.** The AC required injecting a read error *into the running tail loop*; a concrete `*os.File` can't be coerced into a deterministic non-EOF error without fd tricks. The type-widen to `io.ReadCloser` is the honest minimal change — the loop body is otherwise untouched, since the `default:` arm already returned on a non-EOF error; that behaviour is simply now *observable*.

## Deferred / follow-ups

- **Wrapped `os` cause vs. sentinel** — deferred (spec § Open questions). `Event.Err` carries `ErrJSONLTailRead`, not the underlying `ReadBytes` cause. Revisit only when a consumer demonstrates it needs the os-level cause for telemetry; the minimal upgrade is then a tail→merge error-holder, and the relay-vs-parameter trade-off gets re-decided against real evidence. The read error is rare on an append-only local file, and the consumer's response (mark the turn failed, re-observe the file) does not need the cause.
- **INDEX duplicate-line reconciliation (pre-existing, re-flagged).** `docs/knowledge/INDEX.md` still carries **two** `[System overview]` entries: line 8 is current (folds #153/#156/#157 and now #167); line 7 is the stale duplicate ([#161](161.md) already flagged its "remaining anchors stay substring-over-history until slice 3/6 #152" text as stale). The #167 blurb was added to line 8 (the canonical entry); the count word (`eleven-kind`→`twelve-kind`) was corrected in both. Flagged again for the sole INDEX writer's future reconciliation pass.
