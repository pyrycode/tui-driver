# #3 — fix(spike): JSONL discovery + end-turn detection aligned with observed schema

[Issue](https://github.com/pyrycode/tui-driver/issues/3) · [Spec](../../specs/architecture/3-jsonl-discovery-fix.md) · Code: `cmd/spike-one-turn/main.go`

## Summary

Realigned the spike's JSONL side with what `claude` actually does. Spike #1's three wrong assumptions are now corrected: the session JSONL exists at claude startup (not at first prompt), there is no separate `result` envelope event, and the schema carries many envelope types the spike must ignore. `snapshotJSONL` + `waitForNewJSONL` are replaced by `openSessionJSONL`, which picks the newest `*.jsonl` in `~/.claude/projects/<encoded-cwd>/` and records its byte offset; the rewritten `tailJSONL(path, startOffset, …)` seeks past startup envelopes and silently skips any event lacking a `message` map or whose `type` is not `"assistant"`. The log-line token `result-event-received` is renamed to `end-turn-detected` at the single emission site, the spike's README, and the parent spec for #1.

Architectural shape (state machine, watchdog, three-goroutine concurrency, shutdown defer) is unchanged.

## Patterns established

- **JSONL discovery = "newest `*.jsonl` by mtime in the encoded-cwd directory."** claude touches the active session file during startup, so `max(ModTime)` is unambiguous when the spike has just spawned the process. A 1 s retry (`sessionFileWait` / `sessionFilePoll`) absorbs a fresh-cwd race without masking genuine absence. No directory diffing or `fsnotify`.
- **Tail-from-offset over watch-for-new-file.** Stat for `Size()` before writing the prompt; `Seek(offset, SeekStart)` before the tail loop. The startup envelopes (`permission-mode`, `file-history-snapshot`) are skipped by I/O position, not by parser logic.
- **Permissive JSONL filter.** Inside the tail loop: drop any event whose `obj["message"]` is not a `map[string]any`, then drop any event whose `obj["type"]` is not the literal string `"assistant"`. This covers every known envelope (`permission-mode`, `file-history-snapshot`, `attachment`, `ai-title`, `system`, `last-prompt`, `user`) plus every future one in one rule, without enumerating types. Genuine `json.Unmarshal` failures still emit `jsonl-parse-warning` — malformed JSONL is a real surprise; an unknown envelope is not.
- **Synchronous file discovery before the goroutine.** `openSessionJSONL` runs in `run()` before `prompt-written`, so a missing-file error fails the spike cleanly upfront instead of racing through several state transitions before tripping `cancelCause` from inside the tailer. `jsonl-file-discovered` log inside the tailer goes away; `session-jsonl-opened path=… offset=…` is logged at the call site.

## Lessons learned

- **The spinner DOES render — but the ANSI strip eats the whitespace before the verb.** Post-fix run 3 showed the raw PTY bytes around the spinner are `\x1b[38;2;153;153;153m✻\x1b[1CBaked for 1s\x1b[39m`. The `\x1b[1C` is a CSI cursor-forward-1 — claude positions the cursor with a control sequence instead of writing a literal space. The single-pass `\x1b\[[0-9;?]*[a-zA-Z]` strip removes it the same as a colour code, so the stripped buffer reads `✻Baked for 1s` with no whitespace between glyph and verb. The spinner regex (`✻\s+(\S+(?:\s+\S+)?)\s+for\s+…`) requires `\s+` and therefore does not match. `thinking-detected` never fires; the state machine wedges at `prompt-written`; the 60 s inactivity watchdog trips. Recorded as finding #8 in `cmd/spike-one-turn/README.md`. Ticket #4 (making `thinking-detected` optional) is the right fix; a separate small change to either treat the whitespace as zero-or-more or normalise CSI cursor moves to spaces before stripping would also unblock the regex but is not required.
- **The JSONL side is now fully healthy.** Run 3's session JSONL shows the `assistant` event with `stop_reason=end_turn` and `content[].text == "4"` arriving within ~1 s of `prompt-written` and being queued in the event channel — it just never gets dequeued because the state machine is blocked upstream on the spinner. The end-of-turn detection logic was correct from the start; the bug was only in discovery and naming.
- **"Continue on any unrecognized type" is better expressed as a positive filter.** The AC asked for a `continue` on every unknown `type`, with seven known-noise types listed. A literal implementation would have been a switch-case that grows every time claude adds an envelope type. The simpler invariant — `assistant` events with a `message` map are the only thing this spike cares about — tolerates all listed noise types and every future one with two conditions. The narrower AC was a hint, not a contract.
- **The code-review auto-commit committed the spike binary again** (commit `0f9a50f` adds the freshly-rebuilt `spike-one-turn` blob, replacing the version committed by the same path during #1). The follow-up flagged in [codebase/1.md](1.md) — add `/spike-one-turn` to `.gitignore`, or build to a path outside the worktree by default — is still outstanding. The README already recommends `go build -o /tmp/spike-one-turn …` but the auto-commit fires whether or not the operator followed that.
