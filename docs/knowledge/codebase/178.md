# #178 — snapshot-drift: drop the `/agents` case (removed in claude 2.1.199) + bump lock `version=`

[Issue](https://github.com/pyrycode/tui-driver/issues/178) · [Spec](../../specs/architecture/178-drop-agents-snapshot-case.md) · Split from [#176](https://github.com/pyrycode/tui-driver/issues/176) (sibling [#177](https://github.com/pyrycode/tui-driver/issues/177) = first-prompt-deadline hang, closed by #179) · Direct precedent [#129](129.md) · Builds on [#81](81.md) · Classifier reconcile carved to [#182](https://github.com/pyrycode/tui-driver/issues/182) · Code: `cmd/e2e-snapshot-check/main.go`, `cmd/e2e-runner/main.go`, `cmd/e2e-runner/main_test.go`, `Makefile`, `claude-version.lock`, `pkg/tuidriver/testdata/agents-snapshot.json` (deleted)

## Summary

snapshot-drift's `/agents` case was red on `main` as parsed-shape drift. Investigated read-only against installed claude **2.1.199**, the re-scope found the two surviving cases resolve differently, so the original "re-record both fixtures" premise (superseded spec `178-snapshot-drift-rerecord-2.1.199.md`) did **not** hold:

- **`agents` — the modal was removed in claude 2.1.199.** `/agents` no longer opens the tabbed running-subagents modal; it prints a one-line "The `/agents` wizard has been removed…" notice. `DetectModalClass` returns `Unknown` for that render, so `spike-multiselect` writes no sidecar. The committed `agents-snapshot.json` (`tabs:[Running,Library]`, `empty_text:"No subagents are currently running."`) described a modal **that no longer exists** — it can't be re-recorded, so the case was **dropped**, exactly the [#129](129.md) picker shape.
- **`mcp` — already matched. No re-record, no fixture edit.** The committed `mcp-snapshot.json` (`{"total_servers":0,"categories":null}`) is byte-identical to a clean 2.1.199 strict-mcp capture. The initial red was a **dev-host-only artifact**: on a host with unapproved user-scope MCP servers, claude's first-run "N new MCP servers found — approve?" startup picker renders before idle and swallows the `/mcp\r` trigger (the trailing `\r` confirms the approval picker instead of opening `/mcp`), leaving `modal-class=Unknown`. A clean CI runner (no operator MCP servers) never sees the picker, so `mcp` matches there with zero change.

After the drop the surviving fixture set (`mcp` only) matches 2.1.199, so this ticket **completes the calibration sweep** — hence the `claude-version.lock` `version=` bump rides here (per the #47/#57 lesson the bump must coincide with the sweep, and the `Makefile` `rerecord-snapshots` comment says to bump it in the same commit).

The change is removal + three consistency edits + a `.json` delete + one lock line — no new code, no behaviour added:

1. **`cmd/e2e-snapshot-check/main.go`** — removed the `{name: "agents", trigger: "/agents\r", settle: 0}` fixture-table entry; dropped the `SNAPSHOT agents match|diff|recorded` line from the stdout-protocol doc comment; narrowed the `fixture.name` field comment `// "mcp" | "agents"` → `// "mcp"`. `dumpPathRe` / `modalClassRe` / the `picker-snapshot path=` label are **untouched** — trigger-agnostic, reused by the surviving `mcp` case. `runFixture` / `emitDiff` / `enrichMissingSidecar` / `-record` path all unchanged; the table is now the single `mcp` row.
2. **`cmd/e2e-runner/main.go:51`** — narrowed `snapshotResultRe` from `^SNAPSHOT (mcp|agents) (match|diff)$` to `^SNAPSHOT (mcp) (match|diff)$`. `parseSnapshotResults` itself is **unchanged** (it derives each fixture path generically from the captured `SNAPSHOT <name>`); only the protocol whitelist regex follows the table. Capture-group parens preserved (`m[1]`=name, `m[2]`=result).
3. **`cmd/e2e-runner/main_test.go`** — `TestParseSnapshotResults` reduced to the `mcp`-only shape: "all match"→"single match", "mixed match and diff"→"single diff", "noisy…interspersed"→"mcp line amid noise" (agents line dropped, surrounding noise kept). The **"partial output (timeout mid-run)" sub-case was deleted** — with one fixture there is no later fixture to truncate before, so a run that never emits the `mcp` line collapses into the already-covered "empty stdout" / "no SNAPSHOT lines" nil path (not a coverage loss). The version-lock tests in the same file are untouched.
4. **`pkg/tuidriver/testdata/agents-snapshot.json`** — deleted (`git rm`). The `agents-snapshot.bin` unit fixture is **retained**.
5. **`Makefile:44`** — `rerecord-snapshots` comment "the **two** snapshot-drift JSON fixtures" → "the **mcp** snapshot-drift JSON fixture". Recipe body unchanged (`-record` iterates whatever the table now holds — just `mcp`).
6. **`claude-version.lock:11`** — `version=2.1.158` → `version=2.1.199`. The five enforced `flag=`/`value=` lines (`--session-id`, `--permission-mode`, `bypassPermissions`, `--model`, `--effort`) were re-verified against `claude --help` on 2.1.199 and all still present, so **no `flag=`/`value=` edit** — the `version=` line is informational (not compared against the installed binary, #64), so its bump cannot itself fail `claude-version-lock`.

**Coverage is not lost.** The agents *parser/classifier* stays fully exercised by the retained host-independent `agents-snapshot.bin`: `ParseAgentList`'s real-fixture test (`pkg/tuidriver/agents_test.go:30`) and the `DetectModalClass` → `ModalClassAgents` table row (`pkg/tuidriver/modal_test.go:113`), both untouched and green. The snapshot-drift check keeps end-to-end coverage via its surviving `mcp` case.

## Patterns established

- **Third instance of the "drop the e2e case, retain the `.bin` unit fixture" shape** — after `/picker` ([#129](129.md)). The split from its `mcp` sibling ([#128](128.md), "recognise the empty-state, don't drop the case") stays principled: drop only when the live e2e signal genuinely cannot exist portably. Here the modal was **removed upstream** — there is nothing to capture at all — which is a cleaner drop than #129's "captures operator-local state." The `.bin` retention is what keeps parser/classifier coverage intact across the deletion, same as #129 kept `picker-snapshot.bin`.
- **Narrow the protocol-whitelist alternation too, not just the table entry** — repeat of the #129 §2 lesson: `snapshotResultRe` is a sibling package-level enumeration var, not `parseSnapshotResults`'s body. After the table row is gone the binary can never emit `SNAPSHOT agents …`, so leaving `agents|` in the regex is a stale, misleading enumeration. The 7-char deletion is entailed by the same logical change, not adjacent refactoring. A "leave `parseSnapshotResults` alone" note refers to the function *body* (generic path-derivation), not the whitelist var.
- **A decision-gate read-only run can re-scope a re-record ticket into a case-drop ticket.** The developer running the check against 2.1.199 *before* touching fixtures is what surfaced that `mcp` already matched and `agents` no longer existed — flipping the original "Option-C re-record both" spec to a #129-shaped drop. Re-recording a fixture for a modal that upstream deleted is impossible; verify the modal still renders before assuming a fixture is merely stale.
- **The lock `version=` bump rides the ticket that closes the calibration sweep, and only that one.** Per #47/#57, the `version=` annotation means "the committed fixtures were captured/confirmed against this claude." Since #178 is where the surviving `mcp` fixture is confirmed against 2.1.199, the `2.1.158`→`2.1.199` bump lives here. Child #182 (classifier reconcile) does **not** touch the lock.

## Lessons learned

- **`/agents` opened a tabbed running-subagents modal through claude 2.1.158; it was removed in 2.1.199** and now prints a one-line "wizard has been removed" notice that `DetectModalClass` classifies `Unknown`. This is upstream feature removal, not renderer-byte drift — the distinction matters: byte drift is a re-record (#81 parsed-shape absorbs it), feature removal is a case drop (no shape survives to compare). Don't reach for `make rerecord-snapshots` on a `modal-class=Unknown` red without first confirming the modal still exists.
- **The `mcp` red on the dev host was a first-run MCP-approval-picker artifact, not 2.1.199 drift.** With unapproved user-scope MCP servers present, claude's startup "N new MCP servers found — approve?" picker renders before idle and eats the `/mcp\r` trigger (the `\r` confirms the approval, never opens `/mcp`), so the capture lands on the main screen → `modal-class=Unknown`. The fix is operator-side (approve the servers once, or use a clean claude profile) — **never** a hand-edit of `mcp-snapshot.json`. A clean CI runner never hits this. This is the exact escape the spec's Verification Gate table warned against rationalizing past.
- **A case drop must not touch `pkg/tuidriver/` parser/classifier code.** If dropping the `agents` case had appeared to *require* editing `agents.go` / `modal.go` / `permission.go`, that would have been the signal the work belongs in #182, not that the edit should be forced (the spec's Escape A). It didn't — a table-row removal + `.json` delete + runner-test update touches no parser code, exactly as #129 dropped the picker e2e case while leaving the picker parser + `.bin` fixtures fully intact.

## Follow-ups

- **[#182](https://github.com/pyrycode/tui-driver/issues/182) (blocked-by this ticket) — retire/reconcile the now-dormant agents classifier.** `ModalClassAgents`, `ParseAgentList`, `DetectModalClass`'s agents branch, the spike-multiselect agents dispatch, and `agents-snapshot.bin` are all now dormant (the modal they classify was removed in 2.1.199). #182 is the design decision: retire them, or keep them dormant for older-claude compatibility. It is **not** required for snapshot-drift to be green (this ticket already achieves that) and does **not** touch `claude-version.lock`. Mirrors the #129 → picker-classifier deferral shape.
