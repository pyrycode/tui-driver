# #164 — Retire the spinner-freeze watchdog arm

[Issue](https://github.com/pyrycode/tui-driver/issues/164) · [Spec](../../specs/architecture/164-retire-spinner-freeze-watchdog-arm.md) · [PR #198](https://github.com/pyrycode/tui-driver/pull/198) · Commits `316d9bb` (retire) + `443f5f8` (network.go comment) · Touches [`tracker.go`](../../../pkg/tuidriver/tracker.go) / [`watchdog.go`](../../../pkg/tuidriver/watchdog.go) / [`state.go`](../../../pkg/tuidriver/state.go) / [`network.go`](../../../pkg/tuidriver/network.go) · **Resolves the root bug [#124](https://github.com/pyrycode/tui-driver/issues/124)** (`ParseSpinner` matches 0/667 pinned-Claude frames)

**XS (architect override down from PO's `size:s`), deletion-dominated.** The spinner-freeze arm of `CheckWatchdog` fired only when `ParseSpinner`'s class-A `✻ Verb for Ns` seconds-counter stopped incrementing while the spinner stayed visible. The pinned Claude (2.1.158) renders class-B/C ellipsis forms, for which `ParseSpinner` returns `ok=false` — 0/667 captured frames match (#124). So in production `ObserveSpinner(false, 0)` was the *only* call ever made: `spinnerActive` never became true and the arm could **never fire**, yet it shipped as a working, documented API with a `SpinnerFreezeLimit` knob and per-spike calibration. This ticket takes it to a defined end state: **retired**, not reworked. Not `security-sensitive` (a liveness/timeout detector, not a permission/auth gate — a forged spinner can at worst self-trigger a false wedge on the consumer's own local session; distinct from the grid-classification chain [#151](151.md)–[#156](156.md) that feeds the permission auto-answer gate).

## Summary

The freeze arm's **firing logic and plumbing** are removed; the two **public symbols** that eight spike binaries + the external `pyry` consumer name are kept as documented no-ops so the change stays library-internal and cascades zero caller edits.

Removed (`pkg/tuidriver/tracker.go`):
- **`ObserveSpinner`** method deleted entirely — its only non-test caller was `runWatchdogLoop`.
- **`Tracker` struct fields** `lastSpinnerProgressAt`, `lastSpinnerTotal`, `spinnerActive`, `spinnerFreezeLimit` deleted — no reader remains once the arm and `ObserveSpinner` are gone.
- **`CheckWatchdog` freeze branch** deleted; `now := time.Now()` (unused once the branch went) removed. The function is now `CheckWatchdog(buf *Buffer) error` returning non-nil **iff** `buf.QuietFor() > ptyQuietLimit` — signature unchanged, exactly one failure mode (`"watchdog: PTY quiet for %s (last state: %s)"`).
- **`NewTracker`** stops copying/defaulting `spinnerFreezeLimit`; `opts.SpinnerFreezeLimit` is now accepted and ignored.

Removed (`pkg/tuidriver/watchdog.go`):
- **`runWatchdogLoop`** tick body: the `ParseSpinner(buf.Snapshot())` + `ObserveSpinner(...)` lines deleted. The tick reduces to `if err := tr.CheckWatchdog(buf); err != nil { return err }`; `buf.Snapshot()` (only ever called to feed `ParseSpinner`) drops out. `ParseSpinner` stays exported and package-imported — only this *call site* is removed.

Retained as documented no-ops (the scope-cap that keeps this XS):
- **`TrackerOpts.SpinnerFreezeLimit`** field — kept, doc rewritten to "retained for source compatibility, accepted-and-ignored since #164." Eight `cmd/spike-*` binaries pass `SpinnerFreezeLimit: spinnerFreezeLimit` in `TrackerOpts`; keeping the field means **zero edits** across them.
- **`DefaultSpinnerFreezeLimit`** const — kept exported (Go permits an unused exported package-level const) to avoid an API break for the external `pyry` consumer; doc marks it a retained no-op.

Retained unchanged (has an independent consumer — **not** in scope for removal):
- **`ParseSpinner(snap) (verb, totalSeconds, ok)`** in `state.go`. Its one live production consumer is `cmd/spike-long-prompt/main.go:241`, which reads the **verb** (telemetry / `thinkingObserved` gating) and **discards the seconds**. The "Consumer paths" doc was rewritten: bullet 1 (verb is empirical telemetry) kept; bullet 2 now states the total-seconds counter is still returned but has **no in-library consumer** now that the freeze arm is retired.

Doc-only, code comments:
- **`network.go` `HasNetworkFailure`** comment dropped its "(spinner-freeze / PTY-quiet)" aside → just "(PTY-quiet)".
- **`CLAUDE.md` § Spinner caveat** (developer-owned per AC #2) rewritten from "effectively dead" to "**retired** in #164."

Tests (`-132` lines net): four freeze-arm tests **removed** — `TestTrackerCheckWatchdogSpinnerFreeze`, `TestTrackerSpinnerProgressResetsFreeze`, `TestTrackerSpinnerDisappearedClearsState` (`tracker_test.go`), `TestRunWatchdogSpinnerFreezeWedge` + its buffer warm-keep goroutine (`watchdog_test.go`). Two defaults tests **trimmed** to drop the removed-field assertions (`TestTrackerDefaultsApplied`, `TestTrackerExplicitLimitsRespected` keep their `ptyQuietLimit`/`PTYQuietLimit` halves). Three watchdog tests **trimmed** to drop the now-false `SpinnerFreezeLimit: 1 * time.Hour // disable spinner arm` lines. The PTY-quiet arm's tests (`TestTrackerCheckWatchdogQuietBuffer`, `TestRunWatchdogPTYQuietWedge`, `TestSessionRunWatchdogMethod`, `TestRunWatchdogDefaultTickApplied`, `TestRunWatchdogContextCancellation`) are **untouched and green** (AC #4). No new test — the retire path removes a detector, there is no new positive behaviour to assert.

## Patterns established

- **Retire, don't rework, when two live detectors already cover the case (Evidence-Based Fix Selection + belt-and-suspenders-different-fabric).** A reworked "spinner-visible-without-PTY-progress" arm would read the *same* PTY-quiet signal the surviving arm already reads — a redundant third detector for a failure mode no observed case escapes. The freeze case is covered by (1) the **PTY-quiet arm** of `CheckWatchdog` (a genuinely frozen claude stops repainting → `Buffer.QuietFor()` exceeds `PTYQuietLimit` → fires) and (2) **`EventKindStallDetected`** since [#141](141.md) (the JSONL-correlated form: mid-turn AND quiet-beyond-limit AND no JSONL progress). Both are deterministic and live. Building a third would violate "don't ship a defense for a failure mode that hasn't been observed."
- **Retire the plumbing, keep the public no-op — the scope-cap that keeps a cascade XS.** Removing `SpinnerFreezeLimit` / `DefaultSpinnerFreezeLimit` outright would edit >3 files and >10 call sites across the eight spike binaries and break the external `pyry` API. Keeping the field *accepted-and-ignored* + the const as a documented no-op contains the entire change to `tracker.go` + `watchdog.go` + `state.go` doc + tests. The right knob for "make an internal deletion not leak into callers" is a documented inert public symbol, not a signature change. (Full removal was left as a non-speculative follow-up — see Open questions in the spec — precisely because a gratuitous API break for a zero-cost symbol fails the same evidence test.)
- **A retained function whose signature you must not touch still needs its doc de-linked from the dead consumer.** `ParseSpinner` survives byte-for-byte (spike-long-prompt + `state_test.go` depend on the `(verb, totalSeconds, ok)` shape), but its "Consumer paths" doc named `ObserveSpinner`/the freeze arm as the total-seconds consumer. Retiring the arm made that doc a false claim about a live function. The fix is doc-only: keep the signature, rewrite the claim to "returned for callers that want it, no in-library consumer." Deleting a caller obligates you to audit the *retained* callee's doc, not just the removed one.

## Lessons learned

- **A shipped, documented, calibrated API can be structurally incapable of firing — and per-spike calibration masks it.** The arm had a public knob (`SpinnerFreezeLimit`), a default const, and eight binaries passing a value into it, all of which *look* like a working, tuned safety net. But in production `ObserveSpinner(false, 0)` was the only call ever made because its input predicate (`ParseSpinner` returning `ok=true`) matched **0/667** real frames. The calibration ceremony was signal that hid the dead code. When auditing a safety net, don't ask "is it configured?" — ask "under the pinned inputs, what makes its firing condition ever become true?" If the answer is "an input form the target never emits," the net is decorative regardless of how tuned it looks. (This is the same shape as [#162](162.md)'s vacuously-satisfied existence check: a predicate correct for one input state and silently wrong for the one that actually occurs.)
- **The root bug (#124) and its resolution were the same ticket, two years apart in the pipeline.** #124 characterised the 0/667 mismatch; #164 is its resolution — but the correct resolution was *removal*, not the "fix the regex" the bug title implies. `ParseSpinner`'s class-A regex is genuinely dead for the freeze arm's purposes, but reviving it would only rebuild a redundant detector. "Resolve the root bug" did not mean "fix the thing that's broken" — it meant "decide whether the broken thing should exist," and the answer was no. See [system-overview § Key signals](../architecture/system-overview.md) (Thinking + watchdog bullets) for the evergreen record.
- **`ParseSpinner` still misses every observed verb in practice — the verb telemetry it's retained for is itself dormant, but that's a separate, tracked gap.** Keeping `ParseSpinner` "for verb telemetry" is the correct scope call (it *has* a consumer and the signature is depended on), but note the class-A regex also fails to capture the ellipsis-form verbs claude actually renders (CSI cursor-forward between glyph and verb, no `for Ns` counter). So `cmd/spike-long-prompt`'s verb read is largely dormant slow-path logging today. That is a pre-existing `ParseSpinner`-regex gap, out of scope for a *retire-the-arm* ticket, and left as-is — the practical "claude has started processing" signal remains bare-glyph `IsThinking` (region-scoped since [#153](153.md), OR'd with the `esc to interrupt` hint since [#156](156.md)).

## Follow-ups

- **INDEX.md carries a duplicate `[System overview]` bullet** (two near-identical multi-thousand-char entries; the second is the fresher snapshot). Both were kept in sync for this ticket's freeze-arm edit via a shared-substring `replace_all`, but the duplication itself is a pre-existing doc-hygiene artifact predating #164 and out of its scope. A future documentation run (or the auto-generation/pre-doc-rebase fix the sole-writer note anticipates) should collapse the two entries to one.
- **Full removal of `SpinnerFreezeLimit` / `DefaultSpinnerFreezeLimit`** remains available but deliberately deferred (spec Open questions): a gratuitous API break for symbols that cost nothing to keep, warranted only if the merged `pyry` consumer is confirmed to reference neither. Not to be done speculatively.
