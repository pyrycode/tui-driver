# #182 — Reconcile the `/agents` modal classifier for claude 2.1.199 (keep dormant)

[Issue](https://github.com/pyrycode/tui-driver/issues/182) · [Spec](../../specs/architecture/182-reconcile-agents-classifier.md) · Split from [#178](178.md) (blocked-by, merged 2026-07-03) · Precedent [#129](129.md) · Code: `pkg/tuidriver/modal.go`, `pkg/tuidriver/agents.go`

## Summary

The decision-gated hygiene follow-up #178 deferred. Claude 2.1.199 removed the `/agents` wizard, leaving `ModalClassAgents` + `ParseAgentList` dormant against the pinned claude (they still match, but nothing on 2.1.199 renders the modal — `/agents` now prints a one-line "wizard has been removed…" notice that `DetectModalClass` classifies `Unknown`). The ticket posed a genuine design question — **retire the classifier entirely, or keep it dormant** for pre-2.1.199 compatibility.

**Decision: keep dormant.** The architect chose retain-not-retire, and the developer executed the doc-only path: **four comment annotations, zero executable change.**

- `pkg/tuidriver/modal.go` — three annotations: (1a) a dormancy clause on the `ModalClass` type-doc `agents` bullet, (1b) the **primary dormancy comment** on the `ModalClassAgents` const (removed in 2.1.199 → `Unknown` on the removal notice; matches pre-2.1.199 builds only; retained deliberately per the lock's tolerated-drift policy + #129/#178 precedent; kept exercised by `agents-snapshot.bin`), (1c) a brief pointer on the anchor-doc `agents` line.
- `pkg/tuidriver/agents.go` — one dormancy note on `ParseAgentList` pointing back to `ModalClassAgents`.

**Nothing executable moved.** The `anchorAgents*` vars, the `DetectModalClass` agents branch (`Agents` header AND `Running`/`Library` tab), `permission.go:72`'s retained `ParseAgentList` doc-reference, the `spike-multiselect` agents dispatch, every agents unit test, and `agents-snapshot.bin` are byte-identical to `main`. `go vet` / `go build` / `go test ./...` green; the agents unit tests pass **unchanged**; the grep for `ModalClassAgents|ParseAgentList|AgentList` still returns its 28 expected retained references (this is the *keep* path — references SHOULD survive). `claude-version.lock` untouched (the `version=` bump rode with #178); the e2e `agents` snapshot case stays dropped, not re-introduced.

## Patterns established

- **"Keep dormant + annotate" is the fourth beat of the retain-not-retire arc** — after #128 (recognise the empty-state, don't drop), #129 (drop the `/picker` e2e case, retain parser + `.bin`), and #178 (drop the `/agents` e2e case, retain `.bin` + classifier). #182 closes it: when claude removes a feature *upstream* but the library still supports older builds inside the lock's tolerated-drift envelope, the classifier stays and earns a **source comment recording the removal version + the pre-version-only match** — the defect is a documentation gap (a future reader sees agents as a live mapped class), not a correctness bug, and a comment is the smallest fix that closes it. Deleting working, tested coverage to close a doc gap is over-engineering (Simplicity-First / Evidence-Based Fix Selection — no observed failure).
- **Single-source-of-truth comment split.** One primary rationale comment (on the exported/defining symbol — `ModalClassAgents`), plus one-line *pointers* at the secondary sites (type-doc bullet, anchor-doc line, `ParseAgentList` doc). The pointers stop the type-doc and anchor-doc from silently going stale without duplicating the full rationale across four sites (which would itself drift). Reusable shape for any "annotate a fact that a reader might hit from several doc surfaces."
- **The lock's tolerated-drift policy makes older claude builds first-class, which is what tips retire→dormant.** `claude-version.lock`'s `version=` is an informational reviewed reference (#64 — not runtime-enforced); nothing declares 2.1.199 a hard *floor*. A ≤2.1.158 consumer is inside the supported envelope, and for it `/agents` is a live modal the classifier must still recognise. This is the concrete decision rule for the next "claude removed feature X" reconcile: check whether the lock policy still makes the pre-removal build supported before reaching for deletion.

## Lessons learned

- **A size estimate that hinges on a decision only a downstream agent makes ships as one ticket, with the split deferred behind the decision.** The dormant path is XS/doc-only; the *retire* path spans >3 files (`modal.go`, `agents.go`, `permission.go`, `cmd/spike-multiselect/main.go` + two test files + the `.bin`) and trips the split red line. The ticket deliberately did **not** pre-split — pre-splitting would have made the children meaningless if dormant was chosen — and instructed "if the architect chooses retire, route back via `needs-rework:po`." The architect chose dormant, so no split fired and the ticket stayed XS. Don't force a split (or a decision) earlier in the pipeline than the agent who actually owns it.
- **`security-sensitive` gates on the label, not the chosen path's blast radius.** The label was applied because the *retire* path would edit `DetectModalClass` (the shared classifier routing the permission/trust modals that feed the auto-answer gate). The chosen dormant path edits zero executable bytes, so the concern is *structurally defused, not merely mitigated* — but the architect still ran the full security review (verdict PASS) because the label is the gate. "Harmlessly conservative label" is not a reason to skip the review.
- **Dormant ≠ dead-and-dangerous.** The agents branch requires `Agents` + (`Running`|`Library`), none of which appear in the 2.1.199 removal notice or in a permission/trust render, and it sits after `mcp` and before ask-user/trust/permission with disjoint anchors — so it is *unreachable on 2.1.199, reachable on older builds*, and can never swallow a permission/trust render. A dormant classifier that cannot misfire is safe to retain; the annotation exists to tell the reader it's dormant, not because the code is a liability.
