# #73 — spike-multi-turn turn-complete predicate: swap to PTY-quiescence

[Issue](https://github.com/pyrycode/tui-driver/issues/73) · [Spec](../../specs/architecture/73-spike-multi-turn-pty-quiescence.md) · [PR #74](https://github.com/pyrycode/tui-driver/pull/74) · Code: `cmd/spike-multi-turn/`

## Summary

`spike-multi-turn` wedged 3/3 against `claude 2.1.148` on turn 1 (`say hello`) because the turn-complete predicate `gotEndTurn ∧ IsIdle for 250ms` (idle-stable debounce, `cmd/spike-multi-turn/main.go:347-382`) cannot make progress when a `✻ Brewed for Ns` glyph stays painted in the 4 KB rolling buffer after a fast assistant response. `IsIdle` requires the spinner glyph absent (`pkg/tuidriver/state.go:38-44`); post-`end_turn` claude emits ~1.4 KB of redraw + title-bar updates then falls silent, never rolling the stale glyph past the 4096-byte cap (`pkg/tuidriver/buffer.go:8-13`); `IsIdle` stays false forever; the 30/60 s watchdog fires. Same failure shape #11 already diagnosed and solved on the post-cancel readiness path.

Fix is a one-binary predicate swap matching spike-cancel's proven shape (`cmd/spike-cancel/main.go:513-568`): replace the conjunction with `gotEndTurn ∧ ❯-glyph-present in StripANSI(rb.Snapshot()) ∧ rb.QuietFor() >= ptyQuietWindow`, where `ptyQuietWindow = 1500ms` is the same empirical value spike-cancel calibrated (`cmd/spike-cancel/main.go:82-91`). The `IsIdle` call site is replaced with a direct `bytes.Contains(stripped, tuidriver.IdleGlyph)` so the spinner-absent clause that wedges is gone but the input-prompt-on-screen clause survives. `idleStableWindow` and `idleSince` are deleted. No exported package symbols change; `pkg/tuidriver/IsIdle` is untouched and every other consumer (`spike-one-turn`, `spike-cancel`, `spike-long-prompt`, `spike-permission`, `spike-ask-user`, `spike-multiselect`, `probe-first-prompt-hang`) keeps current behavior.

Verified per AC against `claude 2.1.148` with `TUIDRIVER_STRICT_MCP_CONFIG=1`: 3/3 trials exit 0 (41.5 s / 40.1 s / 51.6 s wall, all 5 prompts including the parallel-tool stress prompt 5 the pre-#64 baseline never re-measured). `spike-one-turn` regression check stays green in ~2.66 s. Safety property pinned by AC 2 (next prompt only written when `end_turn` observed AND TUI verifiably ready) is preserved: PTY-quiescence is strictly stronger than the old 250 ms idle-stable debounce on the rendering-activity axis (1500 ms of zero bytes cannot be faked; 250 ms of glyph-absence can), weaker only on the broken spinner-absent clause whose absence was the wedge.

`spike-one-turn`'s independence is not luck-of-the-fix — it's predicate-shape luck. Its predicate `gotEndTurn && (!thinkingObserved || spinnerGone)` (`cmd/spike-one-turn/main.go:226`) drives `spinnerGone` off the `matchSpinner` REGEX, which has documented coverage gaps (CSI cursor-forward between glyph and verb, ellipsis-form without `for Ns`); for `What is 2+2?` the regex never matched, `thinkingObserved` stayed false, the disjunction short-circuited the moment `gotEndTurn` flipped. Same buffer-residue, different predicate shape, accidentally safe in single-turn. Multi-turn cannot rely on that: a future claude version where `matchSpinner` happens to match a prompt before falling silent would wedge spike-one-turn the same way — the regex coverage gaps are a latent bug, not a feature.

## Patterns established

- **PTY-quiescence is the general "TUI ready" signal, not a post-cancel special case.** Spike-cancel (#11) introduced `rb.QuietFor()` for post-cancel readiness because the spinner glyph wouldn't roll out of the 4 KB buffer after a cancel. Spike-multi-turn (#73) hit the identical failure mode in a completely different code path (post-`end_turn`, no cancel involved) and adopted the same predicate. Two independent consumers in two different state transitions confirm: the structural property is "claude emits a small redraw then quiesces; the spinner glyph it painted stays in the buffer because the buffer's churn doesn't reach it." Any future settle scenario — modal dismissal, long-prompt completion, tool-result render-out — should reach for `QuietFor()` rather than glyph-absence-on-buffer. The library extraction (#58–#62) should lift quiescence to a first-class primitive alongside `IsIdle`, not as a post-cancel helper. See [system overview § Key signals](../architecture/system-overview.md).
- **Replace `IsIdle` with its weaker `❯-present` clause when the spinner-absent half wedges.** The pattern is: call `tuidriver.StripANSI(rb.Snapshot())`, then `bytes.Contains(stripped, tuidriver.IdleGlyph)` directly — both `StripANSI` and `IdleGlyph` are exported precisely so consumers can compose narrower predicates than `IsIdle`. Pair this with a quiescence gate (`rb.QuietFor() >= N`) to recover the safety property the dropped half was meant to provide. The post-extraction API will likely surface this as a "ReadyForInput" predicate distinct from "Idle" — they answer different questions.
- **Reuse calibrated empirical constants across binaries by citation, not by re-derivation.** `ptyQuietWindow = 1500ms` here is the same value spike-cancel calibrated; the comment block at `cmd/spike-multi-turn/main.go:59-71` cites `cmd/spike-cancel/main.go:82-91` as the empirical derivation rather than restating it. This makes the second consumer cheap (no new measurement runs) and the eventual library extraction obvious (one constant, two consumers, one home in `pkg/tuidriver/`). Whenever a spike adopts a constant from a sibling spike, the citation should point at the sibling's rationale block, not at the constant declaration alone — the rationale is the load-bearing artifact.

## Lessons learned

- **A bug "out of scope" of the immediately failing ticket is often a probe for the deeper architectural issue.** #73 was filed off #68's Path C escalation ("Turn 1 fails — extremely unlikely; if it does fail, the spike's foundation is broken, not this ticket's scope. Escalate via Path C."). The architect's Path C carve-out was prescient: the failure wasn't a flaky timeout, it was a structural predicate wedge that the same architect had already solved in spike-cancel. The lesson generalises: when a ticket has an "escalate if X" branch and X fires, the resulting follow-up ticket's right move is often to ask "has this failure shape been solved elsewhere in this repo?" before re-deriving from first principles. Here, the fix shape was already sitting in `cmd/spike-cancel/main.go:513-568`; the architect-side decision surface was choosing it over three weaker alternatives, not designing anything new.
- **The 4 KB rolling buffer is the actual root cause; predicate fixes are workarounds.** Both #11 and #73 are symptoms of the same upstream limit: `pkg/tuidriver/buffer.go:8-13`'s 4096-byte cap is small enough that claude's "small redraw then quiesce" patterns can leave a stuck glyph in the buffer indefinitely. PTY-quiescence sidesteps the problem by observing silence directly, which is the right primitive — but every consumer that asks "is glyph X absent from the buffer?" inherits the buffer-size dependency. The library extraction should re-examine this either by lifting the cap (overlaps with the deferred decision flagged at `pkg/tuidriver/buffer.go:8-13`) or by making the buffer's churn behavior explicit in the consumer API (e.g. "this predicate is buffer-size-dependent; this one is not"). The pattern of "discover a new wedge, swap to quiescence, move on" is sustainable but won't scale to every state transition the library will need to expose.
- **`spike-one-turn` being green is not validation of any architectural choice — it's a luck-of-the-prompt artifact.** During the #68 → #73 escalation chain there was a temptation to read "spike-one-turn passes, spike-multi-turn fails, therefore the multi-turn predicate is the bug" as a clean signal. It is and it isn't: the multi-turn predicate IS the bug, but spike-one-turn's pass is luck (a regex coverage gap making the disjunction short-circuit), not evidence the single-turn predicate is correct. If `matchSpinner` ever gets fixed (spike-one-turn finding #8 has been open since #3), spike-one-turn will start wedging on prompts that previously passed. The lesson: when a sibling binary is "unaffected" by a bug, dig into why before treating it as a baseline. "Unaffected" can mean "structurally immune" or "accidentally immune"; the actions you take differ.
- **Belt-and-suspenders only works if the two suspenders fail independently.** The original predicate `gotEndTurn ∧ IsIdle for 250ms` was sold as belt-and-suspenders: JSONL `end_turn` says "model done speaking," `IsIdle` says "TUI ready to receive input," both must hold. But `IsIdle`'s "spinner absent" half and the rolling buffer's churn pattern are not independent — the same `claude` process emits the spinner glyph AND controls the post-`end_turn` redraw budget. When the redraw budget is too small to roll the glyph out, both halves of the conjunction couple to the same upstream behavior and the conjunction becomes a single point of failure dressed up as two. The new predicate (`end_turn ∧ ❯-present ∧ PTY-quiet`) has the same belt-and-suspenders intent but the suspenders are truly independent: `end_turn` is JSONL-side, `❯-present` is buffer-content, `PTY-quiet` is byte-arrival-time. No shared upstream variable can wedge all three simultaneously short of "claude is broken in a way the watchdog should catch anyway." When designing safety conjunctions, ask whether the conjuncts can be co-broken by a single upstream cause — if yes, the conjunction is structurally one signal, not two.
- **The architect's "no new package symbols" discipline kept the blast radius at one binary.** The spec explicitly chose to keep PTY-quiescence inside the spike binary rather than lift it into `pkg/tuidriver/`, citing the standing pattern that all four spike binaries delete on library extraction and that prematurely committing an API shape would have to coordinate with spike-cancel's needs. This was the right call for #73 specifically — but it also means there are now two near-identical PTY-quiescence call sites with different surrounding code (spike-cancel's `waitReappeared` tracks `preCancel` state for snapshot/audit; spike-multi-turn's `check` closure composes with `gotEndTurn`). The library extraction has to reconcile both. Lesson for the extraction tickets (#58–#62): the PTY-quiescence helper's public shape should be the minimal common substrate (`func ReadyForInput(snap []byte, quietFor time.Duration, minQuiet time.Duration) bool` or similar), and each consumer's surrounding state (`preCancel`, `gotEndTurn`) stays consumer-side. Two binaries' worth of evidence is enough integration pressure now; the API design constraint is collecting both shapes' needs cleanly, not whichever spike's shape happens to land first.
