# #62 — consumer migration: `cmd/spike-long-prompt` onto the library JSONL / Events APIs

[Issue](https://github.com/pyrycode/tui-driver/issues/62) · [Spec](../../specs/architecture/62-spike-long-prompt-on-library-events.md) · [PR #98](https://github.com/pyrycode/tui-driver/pull/98) · Predecessors: [#47](47.md), [#58](58.md), [#59](59.md), [#60](60.md), [#61](61.md)

## Summary

Collapsed the spike that originally inlined every piece of the post-prompt JSONL plumbing onto the public `pkg/tuidriver` surface that grew out of it (#58 → #59 → #60 → #61). Net deletion: ~150 production-source lines down to ~30 — `projectsDir`, `openSessionJSONL`, `tailJSONL`, `isEndTurn`, `extractAssistantText`, the `chan map[string]any` plumbing, the dedicated tail goroutine, the `probe := time.NewTicker(50 ms)` arm of the dual-`select`, and the constants `statePollInterval` / `jsonlTailInterval` / `sessionFilePoll` all disappear. The same job is done by `tuidriver.SessionJSONLPath(home, cwd, sessionID)` (pure function, drops the `filepath.Join` + `tuidriver.EncodeCwd` ceremony), `tuidriver.WaitForSessionJSONL(ctx, jsonlPath)` (wrapped in a per-call `context.WithTimeout(rootCtx, sessionFileWait)` to preserve the 10 s deadline, with explicit `jsonlCancel()` on return), `session.Events(rootCtx, jsonlPath, 0)` returning the unified channel that the spike now ranges, and `tuidriver.AssistantText(ev.Entry)` for the text extraction on the synthetic `EventKindJsonlEndOfTurn` event. `resolveSession` shrinks to UUID-only — generates a v4 UUID or parses the operator-supplied flag — and the caller composes `SessionJSONLPath` separately, because session-ID policy is the consumer's concern (the library has no opinion on whether the caller wants a fresh UUID, an externally-supplied one, or a deterministic stable ID).

What stays local in `main.go`: the `expectedTokens` constant (`ALPHA_42-GAMMA_88-OMEGA_13`), the `//go:embed`'d `promptFixture`, the `spinnerRe` regex + `matchSpinner` helper, the trust-folder dance (`tuidriver.HasTrustModal` + the `1\r` keystroke + the post-trust `WaitUntil` over `!HasTrustModal && IsIdle`), the pre-`Events()` `tuidriver.WaitUntil(rootCtx, IsIdle)` initial-idle gate, and the 1 Hz watchdog goroutine with its `tr.ObserveSpinner` / `tr.CheckWatchdog` calls. All four reasons are the same: the JSONL file doesn't exist until after the first prompt is sent, so anything that needs to run before `WritePrompt` can't go through `Events()` (which requires a jsonlPath that exists). The watchdog stays local because the spike binary is the only consumer with the timeout-driver-vs-policy split today and promoting it has its own design tradeoffs the merge would defer.

The wire shape under test (`session.WritePrompt`'s bracketed-paste path) is untouched — that's the whole point of the spike binary, and any change there would defeat the regression-test purpose. The substring assertion is byte-identical to the pre-refactor version. The watchdog deadlines and the `-trust-folder` policy flag are preserved verbatim. Verified end-to-end against claude 2.1.150: `SUCCESS: ALPHA_42-GAMMA_88-OMEGA_13` in 4.26s on the fast path (class-C — the spinner regex misses the verb, so `thinking-detected` / `spinner-gone` don't fire — same outcome as the README's existing Run 1 record).

## Patterns established

- **Canonical shape of a spike-binary migration onto `Events()`.** The before/after collapses to a recognisable template that every other spike migration (`spike-multi-turn`, `spike-cancel`, `spike-permission`, `spike-ask-user`, `spike-one-turn`, etc., if and when their authors choose to migrate) should follow:
  1. **Replace** `projectsDir` + UUID + `filepath.Join(..., sessionID+".jsonl")` with `home := os.UserHomeDir(); cwd := os.Getwd(); jsonlPath := tuidriver.SessionJSONLPath(home, cwd, sessionID)`. Drop `path/filepath` from imports.
  2. **Replace** the `os.Stat` poll loop with `ctx, cancel := context.WithTimeout(rootCtx, sessionFileWait); err := tuidriver.WaitForSessionJSONL(ctx, jsonlPath); cancel()`. Keep the `sessionFileWait` constant (the library doesn't own per-consumer deadlines).
  3. **Replace** the goroutine-owned `tailJSONL` + `chan map[string]any` + dual-`select` over `eventCh + probe.C` with `events, err := session.Events(rootCtx, jsonlPath, 0)` followed by `for ev := range events { switch ev.Kind { ... } }`. Drop `bufio`, `bytes`, `encoding/json`, `io` from imports.
  4. **Replace** the spike's local `isEndTurn` + `extractAssistantText` calls with the library's `EventKindJsonlEndOfTurn` case extracting `tuidriver.AssistantText(ev.Entry)`.
  5. **Shrink** `resolveSession` to UUID-only; move the path composition to the caller.
  6. **Keep** the local fixture, the `expectedTokens` constant, the spinner-verb regex (the library's `EventKindPtyThinking` doesn't carry the verb), the trust-folder dance, the pre-`Events()` `WaitUntil(IsIdle)`, and the watchdog goroutine.
  7. **Update** the README's "What it does" steps and "Required state log lines" block in lockstep.
  Reuse posture: when a future migration's diff size diverges materially from the ~150-line-deletion / ~30-line-addition shape this slice landed, something has drifted from the verbatim-plumbing-extraction contract and the divergence needs to be either reverted or absorbed into the library API. Same pattern shape that `#87`'s `TypePrompt` / `ClearInputLine` extraction established for the prompt-submit helpers: count the call-site edits, count the deleted helper bodies, and stop.
- **Post-`Events()` consumer loop body convention: state vars + per-kind switch + tail-check predicate.** The post-refactor loop is `for ev := range events { switch ev.Kind { case EventKindPtyThinking: ...; case EventKindPtyIdle: ...; case EventKindJsonlEndOfTurn: ... } if <termination predicate> { break } }`. Each `case` mutates one or more locally-scoped state vars (`thinkingObserved`, `spinnerGone`, `gotEndTurn`, `assistantText`, `thinkingVerb`) and emits one `tr.RecordTransition` + one `logger.Printf` line. The termination predicate runs once per iteration tail (not inside any case). After the loop exits, `if rootCtx.Err() != nil { return fmt.Errorf("wait termination: %w", context.Cause(rootCtx)) }` distinguishes normal completion (channel closed because the library's merge goroutine ran out of work / shut down cleanly) from cancellation (watchdog tripped, deferred shutdown fired, etc.). Reuse posture: this is the consumer-side shape that goes naturally with `Events()`'s contract (the merge goroutine closes the channel on `ctx.Done()` or `jsonlCh` closure; the consumer's only job is to consume in arrival order, gate on state-machine predicates, and check `ctx.Err()` after the range loop exits). Avoid putting the termination check inside individual `case` arms — it's easier to read at the iteration tail and harder to forget when a new case is added.
- **The migration validates the `Events()` API as actually consumable.** This was the explicit purpose framing in #61's "follow-up tracked in #62" and in the ticket body's "doubles as proof that the library APIs are usable end-to-end against live claude" framing. Two specific outcomes worth naming: (1) `Events()`'s start-blind merge-loop semantics ("a buffer already idle at subscription fires `EventKindPtyIdle` on tick one"; `pkg/tuidriver/events.go:120-127`) showed up exactly as documented — the spike receives that immediate `EventKindPtyIdle` and the `if !thinkingObserved` gate naturally discards it. (2) The synthetic `EventKindJsonlEndOfTurn` event arrives once per `IsEndTurn(e)`-positive entry; for the spike's fixture (one assistant message, one text content block), it fires exactly once, and the `if gotEndTurn { continue }` guard is defensive against future fixtures with multiple end_turn entries under one turn (no current test case triggers it). Reuse posture: when a library API arrives without consumer-side validation, the first migration's purpose is partly to surface the lived-experience gaps — even when (as here) the API behaves to spec. Treat the first migration as a load-bearing artifact, not just a cleanup.

## Lessons learned

- **The library's `EventKindPtyThinking` fires on `IsThinking` (✻ glyph present), but the rolling buffer (4 KB) retains the ✻ bytes long past the visual end-of-spinner, so the corresponding `EventKindPtyIdle` (`IsThinking` flips back to false) often never fires for short turns.** The spec's intent for the `EventKindPtyThinking` case was "unconditionally set `thinkingObserved = true`, capture the verb opportunistically, emit `thinking-detected verb=…`." That shape works for the slow path (long turn → spinner renders for many seconds → buffer eventually rotates the ✻ bytes out as new output overwrites them → `IsIdle` flips back to true → `EventKindPtyIdle` fires → `spinner-gone` log lands). It hangs the fast path: trivial prompts can resolve before the spinner renders (regex misses the verb — the documented class-C case, `cmd/spike-one-turn/README.md` finding #8 / `pkg/tuidriver/state.go:18-26`), but `IsThinking` still flips true momentarily as the ✻ flashes once, those bytes stick in the rolling buffer, `IsIdle` never returns true, no `EventKindPtyIdle` event, and the termination predicate `gotEndTurn && (!thinkingObserved || spinnerGone)` waits forever for `spinnerGone` after `thinkingObserved` flipped. The implemented fix gates `thinkingObserved` on the local `matchSpinner` regex matching the verb on the same tick — if the regex misses (class C), `thinkingObserved` stays false and the fast path `gotEndTurn && !thinkingObserved` short-circuits. The deviation from spec is documented inline as a comment (`main.go:241-249`) and accepted by code review as a real consumer-side finding, not a developer error. Reuse posture: any future consumer that needs an unambiguous "thinking → spinner-gone" pair from `Events()` against short-turn fast paths cannot rely on the library's bare `EventKindPtyThinking` / `EventKindPtyIdle` pair — it must either gate on a stricter local predicate (verb-extraction, as here) or wait for a library follow-up that promotes verb extraction (or rolling-buffer rotation discipline) into `Events()` itself. The current library shape is fit for the slow path; the fast path needs the local gate. Future ticket candidate: extract `matchSpinner` into the library (carries the verb in `EventKindPtyThinking`'s payload) and document the rolling-buffer ✻-retention gotcha in the package doc.
- **`resolveSession` shrinking confirms `#58`'s scoping decision — session-ID policy belongs to the consumer.** The pre-refactor function did three things: generate-or-parse the UUID, encode the cwd, and concat the jsonl path. The library now owns the latter two (`SessionJSONLPath` is the public composition; `EncodeCwd` was already public from earlier work). The first one — pick a fresh UUID or accept an operator-supplied one — has no library-level "right answer" and the spike binary's preference (generate v4 when empty flag, parse-and-canonicalise when non-empty) is one of several reasonable choices a consumer might make. Reuse posture: when a library promotion targets the path-composition layer, leave the ID-choice policy entirely consumer-side. The library can guarantee the path it produces is the one claude will write to; it cannot and should not opine on which ID the consumer picks. `SessionJSONLPath`'s signature (`home, cwd, sessionID string`) takes all three because all three are policy-free at the path-composition layer.
- **The README's `Observed timings` table still has `prompt-loaded` in column headers — left intentionally for verbatim preservation but worth a one-line follow-up next time someone touches the file.** The refactor dropped the `prompt-loaded bytes=<n>` log line (one local variable; symmetry with the reduced surface; resolved the spec's open question in favour of the drop). The README's `What it does` steps and `Required state log lines` block update in lockstep. But the empirical-record `Observed timings` table (column headers `idle → prompt-loaded`, `prompt-loaded → jsonl-opened`) still references the dropped log line, and the spec explicitly said to keep the populated empirical record verbatim. Code review flagged this as a NIT (PR #98 comment, 2026-05-23): the existing Run 1 data is fine as-is — the timings between the idle/jsonl-opened anchors didn't change — but the column names will look stale to a future reader populating a new row. The right fix when someone next touches the file: rename `prompt-loaded` → `prompt-written` in both column headers. Not blocking, not done here, captured here so the next editor doesn't miss it. Reuse posture: when a refactor drops a log line that's also referenced in an "empirical record" table the spec asks be preserved verbatim, mention the column-name mismatch in the per-ticket file so the next editor doesn't re-discover it from scratch.
- **A "net-deletion refactor" is the right shape when the library API was extracted to do exactly the spike's job.** This is the second example in-tree (after `#87`'s `TypePrompt` migration of `spike-ask-user`) of a spike consumer migration that lands almost entirely as deletions, with the new code being mostly call-site edits. The shape is recognisable: when the library API was promoted *from* the spike binary's own helpers (here #58 / #59 / #60 / #61 were all extractions from spike-long-prompt's pre-refactor source), the migration back onto the library API is by definition deletion-heavy — the spike's pre-refactor source is approximately the library's post-extraction source plus the consumer-side state machine that wraps it. Reuse posture: when reviewing or specifying a "consumer-X migrates onto library-Y where Y was extracted from X" ticket, expect deletions to outweigh additions by ~5:1 (this slice: 223 deletions vs 96 additions across two files; #87: similar ratio). When the ratio drops below 2:1, something is being added beyond the strict extraction-inverse; investigate whether the scope crept or the extraction left something on the table that should land in a separate ticket.
