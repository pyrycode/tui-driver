# 291 — TailJSONL detects rotation & truncation mid-tail and recovers

**Ticket:** [#291](https://github.com/pyrycode/tui-driver/issues/291) · **PR:** #293 (c820403) · **Size:** S · **Security-sensitive:** no · Split from #289 · Blocked-by [#290](codebase/290.md) (shipped, PR #292)

## Summary

`tailJSONLLoop` (`pkg/tuidriver/jsonl.go`) held its one open fd for the life of the tail and never re-checked the file behind the path, so a mid-tail log rotation (path replaced by a new inode) or truncation (file rewritten shorter) left the subscription stranded on the gone generation or parked at a wrong offset. A best-effort recovery check now runs in the EOF-poll branch:

- **Rotation** — the path's device/inode diverges from the tail's own open fd (inode identity, not size, is what catches a same-byte-length replacement). Reopens the path fresh and reads the entire new generation from offset 0.
- **Truncation** — same inode, but the path's size drops below the fd's current read offset. Reseeks the same fd to offset 0 and re-reads.

Both recovery paths re-sync to offset 0 of the current generation — a consumer may re-observe entries from the top of a rotated/truncated file, but these are genuinely new bytes (the prior generation is gone), not duplicates.

The loop signature (`tailJSONLLoop(ctx, r io.ReadCloser, ch)`) is untouched. A minimal `statReader` interface (`Name`/`Stat`/`Seek` beyond `io.ReadCloser`) is type-asserted on `r` inside the EOF branch; `*os.File` satisfies it, the fault-injection seam `faultReader` (Read+Close only) does not, so recovery is a no-op under fault injection and both existing fault tests stayed green unchanged. Generation identity is read via a `//go:build !windows` `statIdentity` (`syscall.Stat_t` Dev+Ino) with a Windows-tagged stub returning `known: false`, making rotation detection a documented no-op on Windows (truncation, size-only, still works everywhere). Recovery is best-effort and never fails the tail — every stat/open/seek error or rotation-window race (`ENOENT` between unlink and replacement) parks and retries next poll tick.

Zero deviation from the architecture spec.

## Patterns established

- **Type-assert a capability interface on an already-abstracted parameter instead of widening its type.** `tailJSONLLoop` needed `Stat`/`Seek`/`Name` but its `r io.ReadCloser` parameter is deliberately narrow to preserve a fault-injection test seam. Defining `statReader` (superset interface) and type-asserting inside the function body — rather than changing the parameter type — adds the capability with zero call-site edits and, as a side effect, makes the *fault seam itself* the mechanism that disables the new behavior under injection (no separate feature flag needed).
- **A "known" bit on a comparable identity value self-disables a check on unsupported platforms.** `fileIdentity{dev, ino, known bool}` compares equal only when both sides are `known` — so Windows's zero-value stub (`known: false` on both sides of every comparison) makes the rotation branch inert rather than requiring a `runtime.GOOS` guard at the call site. Same shape as any cross-platform optional-capability value.
- **Platform file naming: `_other.go`/`_windows.go` with `//go:build !windows`/`//go:build windows`, not `_unix.go`.** Mirrors `session_signal_other.go`/`session_signal_windows.go` — this is now the second instance of the convention (`jsonl_ident_other.go`/`jsonl_ident_windows.go`), reinforcing it as the package norm over inventing a `_unix.go` name.
- **`defer` a closure, not a method value, when the receiver may be reassigned mid-function.** `tailJSONLLoop` changed `defer r.Close()` to `defer func() { _ = r.Close() }()` because rotation recovery reassigns the local `r` to a freshly reopened file — a bound method value would have closed the *original* fd and leaked the reopened one.

## Lessons learned

None — implementation matched the architecture doc with zero deviation.
