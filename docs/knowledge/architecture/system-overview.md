# System overview

Where things live and how data flows. Update when modules, types, or data flows change.

## Current state

The library proper (`pkg/tuidriver/`) is **shipped** (~25 files, ~80 tests) and exports the consumer-facing API: session lifecycle, state detection, modal-class detection + parsers, a single-arm (PTY-quiet) watchdog since [#164](../codebase/164.md), and a unified PTY+JSONL `Events()` channel. The seven `cmd/spike-*` binaries graduated from throwaway prototypes to example consumers — they import `pkg/tuidriver/` and compose its primitives into specific workflows, doubling as regression-detection harnesses:

- `cmd/spike-one-turn/` — single-turn happy path (idle → prompt → spinner → `end_turn` → SUCCESS). See [#1](../codebase/1.md), [#3](../codebase/3.md), [#4](../codebase/4.md), [#7](../codebase/7.md).
- `cmd/spike-multi-turn/` — three-turn loop (simple text → Bash tool use → slow thinking) with msg_id-grouped content extraction and a `runTurn` per-turn driver. See [#9](../codebase/9.md).
- `cmd/spike-cancel/` — three-probe cancellation binary (cancel during thinking → cancel during tool-use → recovery turn). Validates ESC as the cancel keystroke, documents the `user(text "[Request interrupted by user]")` JSONL cancellation marker, and verifies the same `--session-id` is recoverable post-cancel. See [#11](../codebase/11.md).
- `cmd/spike-permission/` — two-session three-probe permission-modal binary (observe modal with no response → auto-respond + complete turn → simulated escalation). First spike to drop `--permission-mode bypassPermissions`. Validates `1\r` as the approve keystroke, documents that permission modals have zero JSONL footprint (detection MUST be PTY-side), and sketches the consumer escalation-callback shape. See [#13](../codebase/13.md).
- `cmd/spike-multiselect/` — slash-command picker / `/mcp` / `/agents` modal parsers.
- `cmd/spike-ask-user/` — claude-initiated AskUserQuestion modal (`ParseAskUserQuestion`, shipped #109).
- `cmd/spike-long-prompt/` — bracketed-paste long/multi-line prompt submission; first consumer migrated onto the library `Events()` / `RunWatchdog` surface.

The spike binaries no longer carry `// copied from … — keep in sync until library extraction` attribution comments — the shared primitives now live in `pkg/tuidriver/` and the spikes call them directly.

## Concurrency model

Three goroutines per spike, coordinated by a single `context.WithCancelCause`:

| Goroutine | Owns | Exit |
|---|---|---|
| `main` orchestrator | linear state machine (single-turn) or per-turn driver loop (multi-turn), watchdog tick | state completes OR watchdog trips OR error |
| PTY reader | the rolling buffer (mutex-protected) | EOF from PTY master (happens when shutdown closes it) |
| JSONL tailer | the events channel (buffered, size 32) | context cancellation |

In `cmd/spike-multi-turn/` and `cmd/spike-cancel/` the events channel is **session-scoped, not turn-scoped** — one tailer goroutine services every turn/probe, and `runTurn` / `runProbe` non-blocking-drains residual events at turn start to discard any delta lines for the prior turn's msg_id that the tailer left buffered after `end_turn` was observed. Without the drain, the next turn's termination predicate could fire spuriously.

Shutdown is a `defer` with a `sync.Once`-guarded body: SIGTERM → 3 s grace race against `cmd.Wait()` → SIGKILL → close PTY → cancel context → `wg.Wait()`. Same sequence in all three spike binaries. Since [#168](../codebase/168.md) the library `Session.Close` targets the child's **process group** (`kill(-pid, sig)`) for both the SIGTERM and the escalated SIGKILL — not just the leader PID — so a hard Close reaps the tool subprocesses `claude` forks (Bash, etc.) instead of orphaning them to init, where they would keep burning subscription quota with nobody driving them. The child is already its own group leader (`PGID == PID`) via `creack/pty`'s `Setsid` at spawn, so the group is addressed by *negating the leader PID* — no `SysProcAttr`/`Setpgid` change (which is what keeps #168 off the same spawn-attr surface as the disjoint sibling #169). The two signal calls delegate to a new unexported `signalShutdown(sig)`; a pure `groupSignalTarget` guard rejects any `pid ≤ 1` so Close can never emit `kill(-1)` (every process the caller may signal) or `kill(0)` (the caller's own group), and falls back to the pre-fix leader-only `Process.Signal` on a rejected PID or a group-signal error (e.g. `ESRCH` if the group already exited during the grace). `syscall.Kill`/`Getpgid` are Unix-only, so `signalShutdown` and its tests live in `//go:build !windows` files with a leader-only Windows stub (mirroring the `cwd_darwin.go`/`cwd_other.go` split) — the `GOOS=windows` build stays green and behaves exactly as before. Every other shutdown step is unchanged, `Close`'s signature untouched.

`Close` covers only the **orderly** path; the **uncontrolled** path — the host daemon crashes or is `SIGKILL`ed without running `Close` at all — is backstopped since [#169](../codebase/169.md) by a kernel-level parent-death signal. `StartPTY` sets `cmd.SysProcAttr.Pdeathsig = syscall.SIGKILL` before `pty.Start`, so the moment the spawning process dies the kernel `SIGKILL`s the child — no cleanup code runs, so a crashed daemon can't leave `claude` reparented to init and rendering headless. This is a Linux-only field (absent from *both* darwin and windows `syscall.SysProcAttr`), so the setter is a `//go:build linux` helper `setParentDeathSignal` with a `//go:build !linux` no-op — the same "syscall is platform-specific → build-tag split, not `runtime.GOOS`" shape as #168, but split on `linux`/`!linux` (where `Pdeathsig` exists) rather than `!windows`/`windows`. The load-bearing invariant is that `creack/pty`'s `StartWithSize` only *adds* `Setsid`/`Setctty` to a caller-set `SysProcAttr` and never overwrites it, so a `Pdeathsig` set before `pty.Start` survives; the helper allocates the struct when nil so that later augmentation still applies. `StartPTY` is the library's single spawn seam (used by `Session.Spawn`), so the production `Session` path is covered — the `cmd/spike-*` binaries call `pty.Start` directly and are deliberately not (demo harnesses, not the `Session` path). Caveat (golang/go#27505): the kernel delivers `Pdeathsig` on spawning-*thread* death, not necessarily whole-process death, but Go parks threads so this is rare and fails safe (claude dies rather than survives). Together #168 (orderly `Close` → group kill) and #169 (crash → kernel `Pdeathsig`) seal both shutdown paths against a headless quota-burning `claude`.

**Reader-goroutine taps (library `Session`).** The PTY reader goroutine appends each chunk to the rolling buffer, and optionally tees it to (a) the `RecordTo`/`MirrorStderr` mirror sink and (b) since [#136](../codebase/136.md) the opt-in **raw-output stream** `(*Session).MirrorOutput() <-chan []byte` — a third tap taken from the *live* PTY read (before the parse-oriented buffer), delivering opaque per-chunk copies for a local `pyry attach` head to byte-mirror `claude`'s terminal. The reader is its sole sender + sole closer. Its send is **non-blocking drop-newest** (cap `defaultMirrorOutputBuffer = 256`), deliberately diverging from the `Events()`/`TailJSONL` block-on-full precedent: those run on *dedicated* goroutines, but this send is in the *shared* reader, where blocking would freeze state detection and deadlock `Close`'s `<-readerDone`. `defer close(mirrorOut)` is registered after `defer close(readerDone)` (LIFO → closes first), so a `Wait()`-then-drain sees the stream already closed **on the reader-drained path**. Since [#170](../codebase/170.md) `Wait` bounds that reader-drain wait by `ShutdownGrace` (so a tool grandchild holding the PTY slave FD open after the leader exits can no longer hang it), so on the **timeout** path `Wait` can return *before* `readerDone`/`mirrorOut` close and a `Wait()`-then-drain may find the stream still open until `Close` — the same re-scoping #170 applied to `Wait`'s own godoc. The twin unconditional "always observes it already closed" claim still on `MirrorOutput`'s exported godoc + the reader's LIFO comment (`session.go:195-197`, `:396-397`) is a tracked one-line doc follow-up ([#170](../codebase/170.md) code review). The paired production raw-input path is `(*Session).AttachInput([]byte) error` (over the internal `writeRaw`, distinct from the spike-only `SendKeys`). Full contract + SECURITY notes: [features/attach-mirror-surface.md](../features/attach-mirror-surface.md).

**Sealed `Session` geometry seam (not a reader tap).** Since [#138](../codebase/138.md) the attach surface is completed by `(*Session).Resize(rows, cols uint16) error` — the sanctioned replacement for the removed `Session.PTY` accessor, letting a consumer that holds only a `*Session` size the live hosted PTY (so foreground `pyry attach` renders at the operator's real terminal instead of the locked 40×120). It is **not** a reader-goroutine tap and adds **no goroutine, lock, or shared state**: a single `pty.Setsize` (`TIOCSWINSZ`) on the held master FD — the same call `StartPTY` uses for the default — which the kernel turns into `SIGWINCH` on the hosted process so `claude` redraws (SIGWINCH is a property of the ioctl, no signal-handling code). `s.pty` is immutable after `Spawn`, so the ioctl-vs-reader-`Read` race is the same kernel-serialised safety class as `AttachInput`'s `Write`-vs-`Read`; a `Resize` after `Close` ioctls a closed FD (`Fd() == -1`) → deterministic `EBADF`, no panic. Full contract: [features/session-resize.md](../features/session-resize.md).

**Write-path serialization (library `Session`).** Since [#171](../codebase/171.md) every byte written *to* the PTY master serializes on a single unexported `writeMu sync.Mutex` held for the full duration of one **logical** write — the write-side counterpart to the read-side mutexes (`Buffer`/`tracker`/`castRecorder` all guard read state, none guarded the write FD before #171). The `writeRaw` funnel (every keystroke path — `AcceptTrust`, `Answer`, `SendEsc`, `Navigate`, `SendKeys`, `AttachInput`) `Lock`s around its one `s.pty.Write`; `WritePrompt` reroutes through `writeRaw` to inherit it; and the **multi-write** helpers `TypePrompt` (byte-by-byte loop + inter-byte settles + `\r` commit) and `ClearInputLine` (Ctrl-U + settle) acquire `writeMu` **directly** across their whole span and keep raw `s.pty.Write` calls — funnelling a span through the non-reentrant `writeRaw` would self-deadlock. The load-bearing case is `TypePrompt`: Go's per-FD `writeLock` already serializes each *single* `os.File.Write`, so two single-write paths never split each other, but it does **not** protect `TypePrompt`'s `len(text)+1`-call sequence — the shared `writeMu` is what stops another writer (an `AttachInput` from an attach head, an `Answer`, a `WritePrompt`) landing between two byte-writes and corrupting an escape sequence or paste boundary. Holding the lock across `TypePrompt`'s inter-byte sleeps (blocking a concurrent writer for the whole typing span) is intended, not a cost — a keystroke injected mid-prompt would corrupt the prompt. `writeMu` is a **leaf lock** (while held, the code touches only `s.pty.Write`/`sleepFn`, never another lock), does not interact with the reader goroutine (guards writes only) or with `Close`/`Wait` (`Close` never acquires it, so a writer blocked in `pty.Write` can't wedge it). Deliberately out of scope: `DeliverPrompt`'s *cross-call* clear-then-write atomicity (lock is released between the two locked ops — a higher-level policy question) and write-after-`Close` ordering. See [#171](../codebase/171.md).

## Key signals

- **Idle:** since [#153](../codebase/153.md) `IsIdle` decides from the **bottom status region** of the rendered grid (`NewGrid(snap,0,0).ContainsInLastRows(...)` over the last `statusRegionRows = 6` rows), NOT a substring anywhere in the whole ANSI-stripped rolling *history* buffer: `❯` glyph (UTF-8 `\xe2\x9d\xaf`) present in the region AND no busy anchor present in the region — where "busy anchor" is, since [#156](../codebase/156.md), the spinner glyph `✻` **or** claude's `esc to interrupt` hint, OR'd in the single `busyInRegion` seam (a second, independent anchor so a change to claude's spinner glyph set alone can no longer flip busy→idle mid-turn), and since [#243](../codebase/243.md) **or** the plain middle-dot thinking frame's row shape (`dotSpinnerRe` — dot leading the row, then verb, then ellipsis; NOT a bare glyph in `spinnerGlyphs`, because claude also renders that dot as an in-region separator elsewhere in the bottom chrome, which would otherwise hold busy true at idle). The conjunction stays load-bearing — `❯` alone is not enough, it's redrawn beneath the spinner while thinking — and region-scoping additionally means a stale `❯` scrolled off into history no longer forges idle (CRITICAL-B fix, slice 4/6). Pre-#153 this was `bytes.Contains(StripANSI(snap), IdleGlyph)` AND `!IsThinking` over the entire buffer.
- **Thinking:** `✻\s+(\S+(?:\s+\S+)?)\s+for\s+(?:(\d+)m\s+)?(\d+)s` — captures a 1–2-word verb (variable per prompt) and a time-tail in `Ns` or `Nm Ns` form. **`ParseSpinner` (`✻ … for Ns`) matches 0/667 frames on claude 2.1.158, so the spinner-freeze watchdog arm it once fed was *retired* in [#164](../codebase/164.md) (resolving tui-driver#124); the PTY-quiet `RunWatchdog` arm and `Events()`'s `EventKindStallDetected` cover the freeze case, and `ParseSpinner` is retained for verb telemetry only.** Use `IsThinking` — since [#153](../codebase/153.md) its bare-`✻`-presence check is region-scoped to the **bottom status region** of the rendered grid (last `statusRegionRows = 6` rows via `NewGrid(snap,0,0).ContainsInLastRows`), NOT a whole-buffer `bytes.Contains(StripANSI(snap), SpinnerGlyph)`; region-scoping closes the CRITICAL-B forgery where a literal `✻` printed as mid-transcript markdown / tool output falsely reported thinking (slice 4/6). Note only `IsThinking`/`IsIdle` moved onto the grid — `ParseSpinner`/`ParseSpinnerTokens` above stay whole-buffer `StripANSI`. Use `IsThinking` as the in-flight anchor instead — since [#156](../codebase/156.md) it already recognises the `"esc to interrupt"` hint as a second, independent busy anchor OR'd with `✻` inside `busyInRegion` (the exported `tuidriver.InterruptHint` const, matched over the grid's space-preserved rendered form; the two anchors fail independently, so glyph drift alone no longer flips busy→idle mid-turn), and it is now the more reliable of the two given the dead `✻ … for Ns` format. Since [#243](../codebase/243.md) `busyInRegion` OR's in a **third**, independent anchor — `dotSpinnerRe`, a plain middle-dot thinking frame claude paints when both the sparkle cycle and (on long turns, where claude swaps the hint row for a rotating tip line) the interrupt hint are absent; shape-bound to the row (dot leads, then verb, then ellipsis) rather than a bare glyph, matching the #219/#242 shape-over-literal discipline. Hand-run census over two recordings: busy rising edges 764→275 and 209→122, uncovered mid-turn frames ~21%→7-11% (not fully closed — see [#243](../codebase/243.md) Lessons learned). Currently misses every observed verb in practice (CSI cursor-forward between glyph and verb eaten by ANSI strip; ellipsis-form verbs lack the `for Ns` counter); slow-path log lines are dormant pending a regex fix. A bare-glyph fallback (`hasSpinnerGlyph` — `bytes.Contains` against `\xe2\x9c\xbb` after ANSI strip) is the practical "claude has started processing" signal until the regex is fixed; introduced in `cmd/spike-cancel/main.go`.
- **Turn done (JSONL side):** at least one `type=="assistant"` line for the turn with `message.stop_reason=="end_turn"` AND non-empty concatenated `type:"text"` content on that line — the canonical per-entry predicate is `tuidriver.IsEndTurn(e JSONLEntry) bool` since [#60](../codebase/60.md). Note that `stop_reason` rides every delta of a multi-block message, not only the last line, so the text-non-empty half is what rejects the `thinking`-only / `tool_use`-only delta lines (see [JSONL layout § One Anthropic message ⇒ N JSONL lines](jsonl-layout.md)). The seven in-tree spike `isEndTurn` open-codes still check stop_reason alone; migration to the library helper is tracked separately.
- **Turn-complete predicate (multi-turn):** JSONL `end_turn` observed AND `❯` glyph present in the ANSI-stripped rolling buffer AND `rb.QuietFor() ≥ 1500 ms` (PTY-quiescence; `ptyQuietWindow` in `cmd/spike-multi-turn/main.go`). Composes the JSONL `end_turn` signal with the shared PTY-quiescence readiness predicate (below). The original `gotEndTurn ∧ isIdle for 250 ms` wedged against `claude 2.1.148` because a stuck `✻ Brewed for Ns` glyph stayed painted in the 4 KB rolling buffer after a fast assistant response, keeping `isIdle` false forever — quiescence sidesteps the buffer-residue problem by observing silence directly. See [#73](../codebase/73.md).
- **Post-approve readiness (permission modals):** in spike-permission's `runAutoRespond`, the post-approve return-to-idle is gated by `gotEndTurn ∧ ❯ glyph present in StripANSI(rb.Snapshot()) ∧ rb.QuietFor() ≥ ptyQuietWindow` (`cmd/spike-permission/main.go`). Same shape as the multi-turn turn-complete predicate (above), same empirical 1500 ms window, same buffer-residue failure mode it replaces — the original `gotEndTurn ∧ isIdle for 250 ms` wedged when a `✻` glyph painted during tool execution stayed in the 4 KB rolling buffer past `end_turn`. The approve keystroke and the JSONL-side end-of-turn signal are unchanged; only the PTY-side readiness predicate's shape changed. See [#70](../codebase/70.md).
- **Cancel-recovery readiness:** in spike-cancel's `runRecovery` (Probes 3/4/5 — `kindRecovery`), the post-`end_turn` return-to-idle is gated by `gotEndTurn ∧ ❯ glyph present in StripANSI(rb.Snapshot()) ∧ rb.QuietFor() ≥ ptyQuietWindow` (`cmd/spike-cancel/main.go`). Same shape and same 1500 ms window as the multi-turn turn-complete predicate (#73) and the post-approve predicate (#70). Pre-#69 this was the **verbatim pre-#74 spike-multi-turn predicate** — `gotEndTurn ∧ tuidriver.IsIdle stable for 250 ms` — copy-pasted from a sibling and never updated; it would have wedged Probes 3/4/5 on `claude 2.1.148` by the same buffer-residue mechanism (post-`end_turn` claude emits well under 4 KB so the `✻` glyph stays painted indefinitely). The `❯-disappeared` observer goroutine that still calls `tuidriver.IsIdle` is unchanged — it's bounded by `disappearedWindow = 500 ms` and emits best-effort logging only, can't wedge. See [#69](../codebase/69.md).
- **Content extraction:** the per-entry primitive (one JSONL line → concatenated text content of its `content[]` blocks where `Type=="text"`, in arrival order, skipping `thinking` / `tool_use`) is `tuidriver.AssistantText(e JSONLEntry) string` since [#60](../codebase/60.md). For multi-block messages (one Anthropic message → N JSONL lines under one `msg_id`), the cross-line aggregation rule still applies: collect every assistant event whose `.message.id` equals the latest `end_turn`-tagged line's msg_id, then concatenate `AssistantText(e)` across them in arrival order. The cross-line shape remains consumer-side (memory bounds on long turns, replay semantics on resume, msg_id selection rule vary per consumer). See [JSONL layout § One Anthropic message ⇒ N JSONL lines](jsonl-layout.md).
- **Unified PTY + JSONL event subscription:** since [#61](../codebase/61.md) (signature extended in [#141](../codebase/141.md)), `(s *Session).Events(ctx, jsonlPath, startOffset, tr *Tracker) (<-chan Event, error)` collapses the spike-binary select-loop ceremony (one ticker polling `Buffer.Snapshot`, one tailer over JSONL, one select reconciling both) into one library-owned merge goroutine. Emits typed `Event{Kind, Source, Time, Modal, Entry, Err}` values for PTY-side idle/thinking rising edges, modal show/hide pairs (Hidden(old) before Shown(new) on a class→class change), MCP-failure and network-failure banner Shown/Hidden edges since [#100](../codebase/100.md), the `EventKindStallDetected` safe-degrade marker since [#141](../codebase/141.md), per-entry JSONL events, and a synthetic `JsonlEndOfTurn` immediately after any `JsonlEntry` that satisfies `IsEndTurn`. Modal axis dominates — idle/thinking emissions are suppressed while a modal is active, because the input-line `❯` glyph is still painted under a permission prompt and would otherwise fire a false "ready for next prompt" signal. Since [#157](../codebase/157.md) that suppression is **symmetric**: the merge loop also freezes the `prev.idle`/`prev.thinking` trackers while a modal is active (`if cur.modal != ModalClassUnknown { cur.idle, cur.thinking = prev.idle, prev.thinking }` immediately before `prev = cur`), so the pre-modal rising edge survives the whole modal window and fires on the clear tick — after `EventKindPtyModalHidden` — instead of being silently swallowed. Before #157 `prev.idle` tracked the `❯`-under-modal classification to `true` while emission was suppressed, so a modal that cleared with claude still idle computed `cur.idle && !prev.idle → false` and no `EventKindPtyIdle` followed `EventKindPtyModalHidden`, hanging any "answer the modal, then wait for idle" consumer — the leak flagged on #61's review and re-deferred by #100. The freeze is safe against the stall axis because `cur.stalled` is computed earlier in the arm and the stall emitter reads `prev.stalled`, not `prev.idle`. The two banner axes added in #100 (`EventKindPtyMcpFailureShown` / `EventKindPtyMcpFailureHidden` / `EventKindPtyNetworkFailureShown` / `EventKindPtyNetworkFailureHidden`, wrapping `HasMcpFailureBanner` / `HasNetworkFailure` respectively) deliberately diverge from the suppression rule: the banners are condition events on an independent UI region (the lower status area), they coexist with modal/idle/thinking state by construction, and consumers want the signal regardless of the dominant axis (it's exactly when the user is looking at the `/mcp` modal that they want to know about MCP failures). The four banner kinds carry no payload fields beyond Source/Time — the kind itself is the signal; consumers wanting the failure count call `FailedMcpCount(snap)` directly. Internal classification refactor that came with #100: `classify` returns a private `ptyState` struct (`idle, thinking, modal, mcpFailure, networkFailure`) and `mergeEvents` keeps a single `var prev ptyState` local, replacing the prior triple of named previous-state booleans. The `stalled` axis added in #141 also lives on `ptyState` (so the same `prev`/`cur` machinery gives it a rising edge) but is the one axis **not** set by `classify` — `classify` is a pure function of the snapshot bytes and can't see quiet timings, so the merge loop computes `cur.stalled` inline in the ticker arm after `classify` returns. `EventKindStallDetected` is the ADR 025 *safe-degrade marker* (consumer-side `stall_detected {conversation_id}` on the wire): it fires on the rising edge when the session is mid-turn (`!idle`) AND the PTY has been quiet beyond the limit (`Buffer.QuietFor() > ptyQuietLimit`) AND no JSONL entry has arrived within that same window — the merge loop is the only goroutine that sees both PTY-quiet and JSONL-progress, so it is the only correct home for the combined condition. It reuses the **same** `Tracker.ptyQuietLimit` the fatal `RunWatchdog` PTY-quiet arm reads (see the watchdog bullet below) (one immutable field, two readers, no second cadence — which is why `Events` now requires a non-nil `tr *Tracker`, a deliberate break of the otherwise additive-only [#136](../codebase/136.md)/[#138](../codebase/138.md) seal posture); the fatal `CheckWatchdog` arm itself is untouched, so a consumer composes "degrade, don't die" (this marker) with "die on wedge" (`RunWatchdog`) as it chooses. Payload-free like the idle/thinking/banner kinds — consumers wanting the quiet duration call `Session.QuietFor()`. One residual ([#141](../codebase/141.md) Lessons): a *broken* (anchor-undetected) modal can render ❯ → `IsIdle` true → stall suppressed, faithful to both the AC and ADR 025's not-idle discriminator; a turn-state mid-turn signal is deferred until such a hang is observed escaping. Output channel is buffered cap 32 with backpressure-aware sends; ctx cancellation or `jsonlCh` closure drives the merge goroutine through one `defer close(out)` exit path within ≤50 ms (one poll tick). Since [#167](../codebase/167.md) that exit is **discriminated**: `tailJSONLLoop` closes `jsonlCh` with ctx still live *iff* it took its `default:` non-EOF `ReadBytes` arm (its only ctx-independent exit — every other exit is ctx-driven), so `mergeEvents` reads `ctx.Err() == nil` at the `!ok` branch as "the tail broke on a read" and emits **one terminal `EventKindError`** (twelfth emittable kind; `Err: ErrJSONLTailRead` — an exported sentinel matched via `errors.Is`, marking *that* the tail broke not *why*, no wrapped `os` cause; `Source EventSourceJsonl`; the new `Event.Err` field is populated only on this kind) immediately before `close(out)`. A clean shutdown (`ctx.Err() != nil`: ctx cancel / EOF-then-cancel) emits none, so a stream-only consumer (`for ev := range events`) tells a broken tail apart from Claude finishing cleanly. The concurrent-cancel race biases toward "clean" (a genuine read error racing a consumer cancel may see `ctx.Err() != nil` and suppress the event) — the safe report, matching [#160](../codebase/160.md)'s posture. - **Prompt-submit convention (`(s *Session).ClearInputLine` + `(s *Session).TypePrompt`):** consumers submitting a non-trivial short prompt MUST `Ctrl-U` (`0x15`) the input line first, then write the prompt body **one byte at a time** with a 10 ms inter-byte delay (`PromptInterByteDelay`), pause 50 ms (`PromptCommitSettle`), then write `\r` as a separate `s.PTY.Write`. Bulk-writing `prompt+"\r"` in a single write trips claude 2.1.148's auto-paste-detection heuristic: the `\r` is absorbed as a literal newline inside the pasted block instead of as a submit, the input handler accepts the prompt body but never starts the turn, the session JSONL never materialises, and any post-prompt deadline (e.g. `sessionFileWait` in the spikes) trips once it expires (~10 s in most spikes; raised to 30 s in `spike-one-turn` by [#185](../codebase/185.md) so the *legitimate-but-slow-under-load* JSONL-appearance case is tolerated rather than reddening `make e2e`). Immutable value fully computed at construction from the caller-owned copy `Buffer.Snapshot` hands back — no goroutines, locks, or defensive copy; no error returns (mirrors `Render`). **Targeted exception to [ADR 0002](../decisions/0002-pattern-matching-over-emulation.md)** in the same vein as `Render` itself ([#90](../codebase/90.md) Render-vs-`StripANSI` split): cheap text predicates (`IsIdle`, `HasTrustModal`) still `StripANSI`-match, but column-aligned/region-scoped parsing routes through the vt10x grid. **This slice wires no detector and changes no behaviour** — slices 2–6 migrate the three ad-hoc `Render`-consumers (`ParseAgentList` `agents.go:42`, `ParseMcpStatus` `mcp.go:72`, `ParseModalContent`/`modalLines` `permission.go:73`) plus the raw-history `strings.Contains` predicates onto `Grid`; new region predicates (`FirstRowWithPrefix`, `ContainsInFirstRows`, …) are added to the method set when a migration needs them, not speculatively. **Slice 4/6 landed [#153](../codebase/153.md)** — the idle/busy axis (`IsIdle` / `IsThinking`) is the first raw-history *predicate* pair migrated onto `Grid`: both now decide from the bottom `statusRegionRows = 6` rows via `ContainsInLastRows`, with a single unexported `busyInRegion(g)` seam holding the region-scoped busy predicate — [#156](../codebase/156.md) then OR'd claude's `esc to interrupt` hint into that one place as a second, independent busy anchor (`tuidriver.InterruptHint`), so both `IsIdle`/`IsThinking` inherited it coherently with no signature change (and #154 finds no parallel whole-buffer path on this axis to remove); closes both CRITICAL-B forgeries (mid-transcript `✻` no longer forges thinking, scrolled-off `❯` no longer forges idle); signatures unchanged (grid built internally with `NewGrid(snap,0,0)`) so zero caller edits. [#243](../codebase/243.md) added a **third** busy anchor to the same seam — `dotSpinnerRe`, a per-row anchored regex over `Grid.LastRows(statusRegionRows)` matching claude's plain dot-frame thinking row (shape-bound, not a bare glyph, per the #219/#242 discipline) — still with no signature change. See [#150](../codebase/150.md).
- **Modal classification anchor-forgery protection — arc closed by [#242](../codebase/242.md):** every `DetectModalClass` arm now requires a structural co-signal beyond its anchor phrase, so a single on-screen line quoting a class's header/prompt text can no longer forge that class. `trust-folder` got the first shape-gate — `gridHasTrustDialog` (`trust.go`, #219) requires the trust header found anywhere on the whole grid AND a pointer-marked numbered option row within a downward lookahead (a full-panel class, so its co-signal scan is whole-grid via `g.Rows()`). The slash-picker, `mcp`, `model-select`, and `permissions-config` classes followed with picker-highlight chrome or the selection-option shape (`gridHasSelectionDialog`/`selectionOptionRe`, `dialog_shape.go`, #223) as their co-signal. (`agents` also carried a co-signal here until [#245](../codebase/245.md) retired its classifier arm outright — the `/agents` wizard is gone on the pinned claude, so there is nothing left to co-signal-gate; `ModalClassAgents`/`ParseAgentList`/`agents-snapshot.bin` are retained as frozen artifacts.) `permission` was the **last single-fabric class** — its arm fired on `anchorPermissionSpaced` (the proceed prompt) alone, region-scoped to the bottom `permissionRegionRows` window, and nothing else. That forged in production: corpus replay showed the class flapping shown/hidden 6 and 5 times respectively across two recordings, on frames whose rendered screen was plain agent-transcript prose quoting the phrase — this org's tickets are *about* this detector, so the false-fire rate was structural. `gridHasPermissionDialog` (`modal.go`) closes it: mirrors `gridHasTrustDialog` byte-for-byte except it iterates `g.LastRows(permissionRegionRows)` instead of `g.Rows()` — permission is a **bottom-overlay** class, not a full-panel one, and that region scope is load-bearing (it rejects an *above-window* transcript forgery, pinned since #150/#152). Requires the anchor **inside** that window AND, within `permissionDialogLookahead = 3` rows below it (same slack as trust), a pointer-marked numbered option row (`modalOptionRe`, group 1 = `❯`) — reuses `modalOptionRe` rather than `selectionOptionRe` deliberately, because a real permission overlay never renders the checkbox form the latter also admits, and reuse keeps the two shape-gate helpers structurally identical so they can't drift apart. One-line arm swap in `detectModalClassWithGrid`; no caller changes — `ParseModalContent` and `Session.AnswerModal` inherit the tightened classification for free. Accepted residual (same posture as trust): a forgery rendering **both** the phrase and a `❯`-numbered row within the lookahead still classifies — chrome content agents essentially never emit as prose. `security-sensitive`, verdict PASS. See [#242](../codebase/242.md). [#244](../codebase/244.md) then hardened the two co-signals `mcp`/`permissions-config` had carried since #223, which turned out to be weak: `snapHasPickerHighlight` matches its highlight shade **anywhere** in the snapshot, but that shade is a general light blue claude also paints on prose paths/links — present in most frames, so it added almost nothing, and a production recording classified `permissions-config` four times on plain prose. Both classes now gate on `snapHasRowOpeningHighlight` (`picker.go`) instead — the highlight must be the colour active at a rendered line's **opening** glyph, which both real panels satisfy via their top border rule but mid-line prose paths do not — and `permissions-config` additionally requires its three tab words (`Allow`/`Ask`/`Deny`) on **one** rendered row (`gridRowContainsAll`, bound to the tab row the real panel renders them on) rather than three independent anywhere-matches. `snapHasPickerHighlight` is unchanged and still gates slash-picker chrome. `security-sensitive`, verdict PASS. See [#244](../codebase/244.md). [#296](../codebase/296.md) then found the weak half of slash-picker's own AND was not its chrome (already probed by #244 and left unchanged there) but its **row-location signal**: `gridHasPickerRow` accepted a single bottom-region `/`-row, and a wrapped shell-output continuation (`/Users…`, `/gradlew…`) or claude's own footer tip wrapping to `/btw …` forged one inside the #237 region window — corpus-replay showed `slash-picker` firing in 4/4 production runs with the tool's flapping spurious-modal signature. Unlike #244's classes, row-opening chrome would **not** have helped here — a wrapped path legitimately opens its line in the highlight shade. The fix instead gates row **count**: `gridHasPickerRowBlock` (`picker.go`) requires a non-contiguous block of ≥`pickerRowBlockMin` (2) bottom-region `/`-rows, reusing `pickerRowStartRe` — a real picker paints a command *list* (the two committed captures carry 5 and 6 rows), a forgery is one stray line. `gridHasPickerRow` survives as the weak ≥1 signal solely for the non-vacuity regressions. Consciously **drops single-match filtered-picker detection** (structurally identical to the forgery) — safe because the consumer is headless and a real picker never surfaces there regardless. `security-sensitive`, verdict PASS. See [#296](../codebase/296.md).

## e2e harness

Top-level orchestrator at `cmd/e2e-runner/`, invoked by `make e2e`. Operates orthogonally to the rest of the system — it does not import `pkg/tuidriver/`, just shells out to the prebuilt spike + probe binaries under `./bin/<name>` and emits a single-file `e2e-report.json` artifact. Runs sequentially in one goroutine; `exec.CommandContext` handles subprocess lifecycle (SIGKILL on cancel) so no manual signal plumbing is required.

Headless-CI plumbing rides a single seam in `pkg/tuidriver/pty.go`: when `TUIDRIVER_STRICT_MCP_CONFIG=1` is set in the env, `EnsureClaudeEnv(cmd)` additionally appends `--strict-mcp-config` to `cmd.Args` (idempotent — skipped if already present). Every spike+probe already calls `EnsureClaudeEnv` between `exec.Command("claude", ...)` and `pty.Start`; the runner sets the env var on each child process, so the flag flows transparently with zero spike-side changes. Exported constant `tuidriver.StrictMcpConfigEnv` is the contract for the env-var name.

See [features/e2e-harness.md](../features/e2e-harness.md) for the operator runbook, report schema, and CLI flags. See [#34](../codebase/34.md) for the build notes.
