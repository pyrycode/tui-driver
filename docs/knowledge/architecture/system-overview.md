# System overview

Where things live and how data flows. Update when modules, types, or data flows change.

## Current state

The library proper (`pkg/tuidriver/`) is **shipped** (~25 files, ~80 tests) and exports the consumer-facing API: session lifecycle, state detection, modal-class detection + parsers, two-arm watchdog, and a unified PTY+JSONL `Events()` channel. The seven `cmd/spike-*` binaries graduated from throwaway prototypes to example consumers — they import `pkg/tuidriver/` and compose its primitives into specific workflows, doubling as regression-detection harnesses:

- `cmd/spike-one-turn/` — single-turn happy path (idle → prompt → spinner → `end_turn` → SUCCESS). See [#1](../codebase/1.md), [#3](../codebase/3.md), [#4](../codebase/4.md), [#7](../codebase/7.md).
- `cmd/spike-multi-turn/` — three-turn loop (simple text → Bash tool use → slow thinking) with msg_id-grouped content extraction and a `runTurn` per-turn driver. See [#9](../codebase/9.md).
- `cmd/spike-cancel/` — three-probe cancellation binary (cancel during thinking → cancel during tool-use → recovery turn). Validates ESC as the cancel keystroke, documents the `user(text "[Request interrupted by user]")` JSONL cancellation marker, and verifies the same `--session-id` is recoverable post-cancel. See [#11](../codebase/11.md).
- `cmd/spike-permission/` — two-session three-probe permission-modal binary (observe modal with no response → auto-respond + complete turn → simulated escalation). First spike to drop `--permission-mode bypassPermissions`. Validates `1\r` as the approve keystroke, documents that permission modals have zero JSONL footprint (detection MUST be PTY-side), and sketches the consumer escalation-callback shape. See [#13](../codebase/13.md).
- `cmd/spike-multiselect/` — slash-command picker / `/mcp` / `/agents` modal parsers.
- `cmd/spike-ask-user/` — claude-initiated AskUserQuestion modal (`ParseAskUserQuestion`, shipped #109).
- `cmd/spike-long-prompt/` — bracketed-paste long/multi-line prompt submission; first consumer migrated onto the library `Events()` / `RunWatchdog` surface.

The spike binaries no longer carry `// copied from … — keep in sync until library extraction` attribution comments — the shared primitives now live in `pkg/tuidriver/` and the spikes call them directly.

## Concurrency model

Three goroutines per spike, coordinated by a single `context.WithCancelCause`:

| Goroutine | Owns | Exit |
|---|---|---|
| `main` orchestrator | linear state machine (single-turn) or per-turn driver loop (multi-turn), watchdog tick | state completes OR watchdog trips OR error |
| PTY reader | the rolling buffer (mutex-protected) | EOF from PTY master (happens when shutdown closes it) |
| JSONL tailer | the events channel (buffered, size 32) | context cancellation |

In `cmd/spike-multi-turn/` and `cmd/spike-cancel/` the events channel is **session-scoped, not turn-scoped** — one tailer goroutine services every turn/probe, and `runTurn` / `runProbe` non-blocking-drains residual events at turn start to discard any delta lines for the prior turn's msg_id that the tailer left buffered after `end_turn` was observed. Without the drain, the next turn's termination predicate could fire spuriously.

Shutdown is a `defer` with a `sync.Once`-guarded body: SIGTERM → 3 s grace race against `cmd.Wait()` → SIGKILL → close PTY → cancel context → `wg.Wait()`. Same sequence in all three spike binaries.

**Reader-goroutine taps (library `Session`).** The PTY reader goroutine appends each chunk to the rolling buffer, and optionally tees it to (a) the `RecordTo`/`MirrorStderr` mirror sink and (b) since [#136](../codebase/136.md) the opt-in **raw-output stream** `(*Session).MirrorOutput() <-chan []byte` — a third tap taken from the *live* PTY read (before the parse-oriented buffer), delivering opaque per-chunk copies for a local `pyry attach` head to byte-mirror `claude`'s terminal. The reader is its sole sender + sole closer. Its send is **non-blocking drop-newest** (cap `defaultMirrorOutputBuffer = 256`), deliberately diverging from the `Events()`/`TailJSONL` block-on-full precedent: those run on *dedicated* goroutines, but this send is in the *shared* reader, where blocking would freeze state detection and deadlock `Close`'s `<-readerDone`. `defer close(mirrorOut)` is registered after `defer close(readerDone)` (LIFO → closes first), so a `Wait()`-then-drain always sees the stream closed. The paired production raw-input path is `(*Session).AttachInput([]byte) error` (over the internal `writeRaw`, distinct from the spike-only `SendKeys`). Full contract + SECURITY notes: [features/attach-mirror-surface.md](../features/attach-mirror-surface.md).

**Sealed `Session` geometry seam (not a reader tap).** Since [#138](../codebase/138.md) the attach surface is completed by `(*Session).Resize(rows, cols uint16) error` — the sanctioned replacement for the removed `Session.PTY` accessor, letting a consumer that holds only a `*Session` size the live hosted PTY (so foreground `pyry attach` renders at the operator's real terminal instead of the locked 40×120). It is **not** a reader-goroutine tap and adds **no goroutine, lock, or shared state**: a single `pty.Setsize` (`TIOCSWINSZ`) on the held master FD — the same call `StartPTY` uses for the default — which the kernel turns into `SIGWINCH` on the hosted process so `claude` redraws (SIGWINCH is a property of the ioctl, no signal-handling code). `s.pty` is immutable after `Spawn`, so the ioctl-vs-reader-`Read` race is the same kernel-serialised safety class as `AttachInput`'s `Write`-vs-`Read`; a `Resize` after `Close` ioctls a closed FD (`Fd() == -1`) → deterministic `EBADF`, no panic. Full contract: [features/session-resize.md](../features/session-resize.md).

## Key signals

- **Idle:** since [#153](../codebase/153.md) `IsIdle` decides from the **bottom status region** of the rendered grid (`NewGrid(snap,0,0).ContainsInLastRows(...)` over the last `statusRegionRows = 6` rows), NOT a substring anywhere in the whole ANSI-stripped rolling *history* buffer: `❯` glyph (UTF-8 `\xe2\x9d\xaf`) present in the region AND no busy anchor present in the region — where "busy anchor" is, since [#156](../codebase/156.md), the spinner glyph `✻` **or** claude's `esc to interrupt` hint, OR'd in the single `busyInRegion` seam (a second, independent anchor so a change to claude's spinner glyph set alone can no longer flip busy→idle mid-turn). The conjunction stays load-bearing — `❯` alone is not enough, it's redrawn beneath the spinner while thinking — and region-scoping additionally means a stale `❯` scrolled off into history no longer forges idle (CRITICAL-B fix, slice 4/6). Pre-#153 this was `bytes.Contains(StripANSI(snap), IdleGlyph)` AND `!IsThinking` over the entire buffer.
- **Thinking:** `✻\s+(\S+(?:\s+\S+)?)\s+for\s+(?:(\d+)m\s+)?(\d+)s` — captures a 1–2-word verb (variable per prompt) and a time-tail in `Ns` or `Nm Ns` form. **`ParseSpinner` (`✻ … for Ns`) matches 0/667 frames on claude 2.1.158 — spinner-freeze watchdog dead, see tui-driver#124.** Use `IsThinking` — since [#153](../codebase/153.md) its bare-`✻`-presence check is region-scoped to the **bottom status region** of the rendered grid (last `statusRegionRows = 6` rows via `NewGrid(snap,0,0).ContainsInLastRows`), NOT a whole-buffer `bytes.Contains(StripANSI(snap), SpinnerGlyph)`; region-scoping closes the CRITICAL-B forgery where a literal `✻` printed as mid-transcript markdown / tool output falsely reported thinking (slice 4/6). Note only `IsThinking`/`IsIdle` moved onto the grid — `ParseSpinner`/`ParseSpinnerTokens` above stay whole-buffer `StripANSI`. Use `IsThinking` as the in-flight anchor instead — since [#156](../codebase/156.md) it already recognises the `"esc to interrupt"` hint as a second, independent busy anchor OR'd with `✻` inside `busyInRegion` (the exported `tuidriver.InterruptHint` const, matched over the grid's space-preserved rendered form; the two anchors fail independently, so glyph drift alone no longer flips busy→idle mid-turn), and it is now the more reliable of the two given the dead `✻ … for Ns` format. Currently misses every observed verb in practice (CSI cursor-forward between glyph and verb eaten by ANSI strip; ellipsis-form verbs lack the `for Ns` counter); slow-path log lines are dormant pending a regex fix. A bare-glyph fallback (`hasSpinnerGlyph` — `bytes.Contains` against `\xe2\x9c\xbb` after ANSI strip) is the practical "claude has started processing" signal until the regex is fixed; introduced in `cmd/spike-cancel/main.go`.
- **Turn done (JSONL side):** at least one `type=="assistant"` line for the turn with `message.stop_reason=="end_turn"` AND non-empty concatenated `type:"text"` content on that line — the canonical per-entry predicate is `tuidriver.IsEndTurn(e JSONLEntry) bool` since [#60](../codebase/60.md). Note that `stop_reason` rides every delta of a multi-block message, not only the last line, so the text-non-empty half is what rejects the `thinking`-only / `tool_use`-only delta lines (see [JSONL layout § One Anthropic message ⇒ N JSONL lines](jsonl-layout.md)). The seven in-tree spike `isEndTurn` open-codes still check stop_reason alone; migration to the library helper is tracked separately.
- **Turn-complete predicate (multi-turn):** JSONL `end_turn` observed AND `❯` glyph present in the ANSI-stripped rolling buffer AND `rb.QuietFor() ≥ 1500 ms` (PTY-quiescence; `ptyQuietWindow` in `cmd/spike-multi-turn/main.go`). Composes the JSONL `end_turn` signal with the shared PTY-quiescence readiness predicate (below). The original `gotEndTurn ∧ isIdle for 250 ms` wedged against `claude 2.1.148` because a stuck `✻ Brewed for Ns` glyph stayed painted in the 4 KB rolling buffer after a fast assistant response, keeping `isIdle` false forever — quiescence sidesteps the buffer-residue problem by observing silence directly. See [#73](../codebase/73.md).
- **Post-approve readiness (permission modals):** in spike-permission's `runAutoRespond`, the post-approve return-to-idle is gated by `gotEndTurn ∧ ❯ glyph present in StripANSI(rb.Snapshot()) ∧ rb.QuietFor() ≥ ptyQuietWindow` (`cmd/spike-permission/main.go`). Same shape as the multi-turn turn-complete predicate (above), same empirical 1500 ms window, same buffer-residue failure mode it replaces — the original `gotEndTurn ∧ isIdle for 250 ms` wedged when a `✻` glyph painted during tool execution stayed in the 4 KB rolling buffer past `end_turn`. The approve keystroke and the JSONL-side end-of-turn signal are unchanged; only the PTY-side readiness predicate's shape changed. See [#70](../codebase/70.md).
- **Cancel-recovery readiness:** in spike-cancel's `runRecovery` (Probes 3/4/5 — `kindRecovery`), the post-`end_turn` return-to-idle is gated by `gotEndTurn ∧ ❯ glyph present in StripANSI(rb.Snapshot()) ∧ rb.QuietFor() ≥ ptyQuietWindow` (`cmd/spike-cancel/main.go`). Same shape and same 1500 ms window as the multi-turn turn-complete predicate (#73) and the post-approve predicate (#70). Pre-#69 this was the **verbatim pre-#74 spike-multi-turn predicate** — `gotEndTurn ∧ tuidriver.IsIdle stable for 250 ms` — copy-pasted from a sibling and never updated; it would have wedged Probes 3/4/5 on `claude 2.1.148` by the same buffer-residue mechanism (post-`end_turn` claude emits well under 4 KB so the `✻` glyph stays painted indefinitely). The `❯-disappeared` observer goroutine that still calls `tuidriver.IsIdle` is unchanged — it's bounded by `disappearedWindow = 500 ms` and emits best-effort logging only, can't wedge. See [#69](../codebase/69.md).
- **Content extraction:** the per-entry primitive (one JSONL line → concatenated text content of its `content[]` blocks where `Type=="text"`, in arrival order, skipping `thinking` / `tool_use`) is `tuidriver.AssistantText(e JSONLEntry) string` since [#60](../codebase/60.md). For multi-block messages (one Anthropic message → N JSONL lines under one `msg_id`), the cross-line aggregation rule still applies: collect every assistant event whose `.message.id` equals the latest `end_turn`-tagged line's msg_id, then concatenate `AssistantText(e)` across them in arrival order. The cross-line shape remains consumer-side (memory bounds on long turns, replay semantics on resume, msg_id selection rule vary per consumer). See [JSONL layout § One Anthropic message ⇒ N JSONL lines](jsonl-layout.md).
- **Unified PTY + JSONL event subscription:** since [#61](../codebase/61.md) (signature extended in [#141](../codebase/141.md)), `(s *Session).Events(ctx, jsonlPath, startOffset, tr *Tracker) (<-chan Event, error)` collapses the spike-binary select-loop ceremony (one ticker polling `Buffer.Snapshot`, one tailer over JSONL, one select reconciling both) into one library-owned merge goroutine. Emits typed `Event{Kind, Source, Time, Modal, Entry}` values for PTY-side idle/thinking rising edges, modal show/hide pairs (Hidden(old) before Shown(new) on a class→class change), MCP-failure and network-failure banner Shown/Hidden edges since [#100](../codebase/100.md), the `EventKindStallDetected` safe-degrade marker since [#141](../codebase/141.md), per-entry JSONL events, and a synthetic `JsonlEndOfTurn` immediately after any `JsonlEntry` that satisfies `IsEndTurn`. Modal axis dominates — idle/thinking emissions are suppressed while a modal is active, because the input-line `❯` glyph is still painted under a permission prompt and would otherwise fire a false "ready for next prompt" signal. The two banner axes added in #100 (`EventKindPtyMcpFailureShown` / `EventKindPtyMcpFailureHidden` / `EventKindPtyNetworkFailureShown` / `EventKindPtyNetworkFailureHidden`, wrapping `HasMcpFailureBanner` / `HasNetworkFailure` respectively) deliberately diverge from the suppression rule: the banners are condition events on an independent UI region (the lower status area), they coexist with modal/idle/thinking state by construction, and consumers want the signal regardless of the dominant axis (it's exactly when the user is looking at the `/mcp` modal that they want to know about MCP failures). The four banner kinds carry no payload fields beyond Source/Time — the kind itself is the signal; consumers wanting the failure count call `FailedMcpCount(snap)` directly. Internal classification refactor that came with #100: `classify` returns a private `ptyState` struct (`idle, thinking, modal, mcpFailure, networkFailure`) and `mergeEvents` keeps a single `var prev ptyState` local, replacing the prior triple of named previous-state booleans. The `stalled` axis added in #141 also lives on `ptyState` (so the same `prev`/`cur` machinery gives it a rising edge) but is the one axis **not** set by `classify` — `classify` is a pure function of the snapshot bytes and can't see quiet timings, so the merge loop computes `cur.stalled` inline in the ticker arm after `classify` returns. `EventKindStallDetected` is the ADR 025 *safe-degrade marker* (consumer-side `stall_detected {conversation_id}` on the wire): it fires on the rising edge when the session is mid-turn (`!idle`) AND the PTY has been quiet beyond the limit (`Buffer.QuietFor() > ptyQuietLimit`) AND no JSONL entry has arrived within that same window — the merge loop is the only goroutine that sees both PTY-quiet and JSONL-progress, so it is the only correct home for the combined condition. It reuses the **same** `Tracker.ptyQuietLimit` the fatal `RunWatchdog` PTY-quiet arm reads (see the watchdog bullet below) (one immutable field, two readers, no second cadence — which is why `Events` now requires a non-nil `tr *Tracker`, a deliberate break of the otherwise additive-only [#136](../codebase/136.md)/[#138](../codebase/138.md) seal posture); the fatal `CheckWatchdog` arm itself is untouched, so a consumer composes "degrade, don't die" (this marker) with "die on wedge" (`RunWatchdog`) as it chooses. Payload-free like the idle/thinking/banner kinds — consumers wanting the quiet duration call `Session.QuietFor()`. One residual ([#141](../codebase/141.md) Lessons): a *broken* (anchor-undetected) modal can render ❯ → `IsIdle` true → stall suppressed, faithful to both the AC and ADR 025's not-idle discriminator; a turn-state mid-turn signal is deferred until such a hang is observed escaping. Output channel is buffered cap 32 with backpressure-aware sends; ctx cancellation or `jsonlCh` closure drives the merge goroutine through one `defer close(out)` exit path within ≤50 ms (one poll tick). The existing snapshot predicates (`IsIdle` / `IsThinking` / `DetectModalClass` / `HasMcpFailureBanner` / `HasNetworkFailure`) and `TailJSONL` stay public for consumers that want to compose the streams themselves — `Events` is the merged-channel shortcut, not a replacement. Spike-binary migrations to consume `Events()` are tracked in #62 — `cmd/spike-long-prompt` landed first as of [#62](../codebase/62.md) (the binary whose pre-refactor source was the original extraction target for #58–#61; ~150 production-source lines deleted from the consumer in exchange for `SessionJSONLPath` + `WaitForSessionJSONL` + `Events()` + `AssistantText` calls); the remaining spikes are mechanical templates of the same shape. One consumer-side gotcha that surfaced during #62 and is worth flagging for future consumers: the library's `EventKindPtyThinking` fires on `IsThinking` (✻ glyph present) and the corresponding `EventKindPtyIdle` fires when `IsThinking` flips back to false, but the rolling buffer (4 KB cap) retains the ✻ bytes past the visual end-of-spinner, so for fast-path short turns the buffer can stay "thinking" indefinitely after a transient ✻ flash and no `EventKindPtyIdle` ever fires. Consumers that need an unambiguous "thinking → spinner-gone" pair against short turns must gate on a stricter local predicate — `tuidriver.ParseSpinner(snap) (verb, totalSeconds, ok)` since [#89](../codebase/89.md) (the same class-A `✻ Verb for Ns` regex that the seven spike-resident `matchSpinner` copies pre-#89 implemented; lives next to `ParseSpinnerTokens` in `state.go` under the same package-private-regex + exported-pure-function template; class B / C / D return `ok=false`); the library's bare event pair alone is fit for the slow path only. Library follow-up candidate: promote verb extraction into `EventKindPtyThinking`'s payload + document the ✻-retention rolling-buffer behaviour in the package doc.
- **1 Hz watchdog primitive (`tuidriver.RunWatchdog`):** library-owned blocking loop since [#89](../codebase/89.md) — `RunWatchdog(ctx, *Buffer, *Tracker, WatchdogOpts) error` drives the spike-calibrated per-tick work list (`Buffer.Snapshot` → `tuidriver.ParseSpinner` → `Tracker.ObserveSpinner` → `Tracker.CheckWatchdog`) at `WatchdogOpts.Tick` cadence (zero falls through to the exported `DefaultWatchdogTick = 1 * time.Second`). Returns `nil` on `ctx`-cancel (matching `Spawn` / `Session.Wait`'s cancellation convention) or the `CheckWatchdog` error verbatim on wedge — already names the failure mode (`watchdog: PTY quiet for ...` / `watchdog: spinner counter frozen ...`) and the last recorded state, so consumers' `log.Printf("%v", err)` works without wrapping. Returned-error rather than callback-or-cancel-cause: callers spawn a goroutine, compose with whichever cancellation strategy they use (`context.WithCancelCause` is the in-tree default but not required). The function is a free function rather than a method on `*Tracker` or `*Buffer` because neither type is the natural owner of a goroutine-driven loop reading from both. `cmd/spike-long-prompt` was the first consumer migrated (22-line inline ticker collapses to 5 lines wrapping `RunWatchdog`); since then [#112](../codebase/112.md) (spike-one-turn + spike-multiselect), [#116](../codebase/116.md) (spike-multi-turn), [#117](../codebase/117.md) (spike-cancel), [#118](../codebase/118.md) (spike-permission), and [#114](../codebase/114.md) (spike-ask-user) have landed — the arc is closed, no inline copies remain. `cmd/probe-first-prompt-hang/main.go`'s first-PTY-byte marker goroutine is intentionally NOT a watchdog (no `Tracker` / spinner / wedge-error return; pure instrumentation) and stays verbatim — substituting `RunWatchdog` would abort runs the probe is designed to characterise (see [#114](../codebase/114.md) for the audit shape). See [#89](../codebase/89.md) for the API design + the design-(a)-over-(b) reasoning that bundled `ParseSpinner` extraction alongside the loop.
- **Cancel keystroke:** ESC (`\x1b`) — single byte, single `pty.Write`, no `\r`. Double-ESC and Ctrl-C also work but ESC is the default (matches the on-screen `esc to interrupt` hint, simplest single-byte representation). The keystroke does NOT go through `typePrompt` — the inter-byte-delay / `\r` reasoning that drives `typePrompt` does not apply to a `\r`-less single byte. See [#11](../codebase/11.md).
- **Prompt-submit convention (`(s *Session).ClearInputLine` + `(s *Session).TypePrompt`):** consumers submitting a non-trivial short prompt MUST `Ctrl-U` (`0x15`) the input line first, then write the prompt body **one byte at a time** with a 10 ms inter-byte delay (`PromptInterByteDelay`), pause 50 ms (`PromptCommitSettle`), then write `\r` as a separate `s.PTY.Write`. Bulk-writing `prompt+"\r"` in a single write trips claude 2.1.148's auto-paste-detection heuristic: the `\r` is absorbed as a literal newline inside the pasted block instead of as a submit, the input handler accepts the prompt body but never starts the turn, the session JSONL never materialises, and any post-prompt deadline (e.g. `sessionFileWait` in the spikes) trips once it expires (~10 s in most spikes; raised to 30 s in `spike-one-turn` by [#185](../codebase/185.md) so the *legitimate-but-slow-under-load* JSONL-appearance case is tolerated rather than reddening `make e2e`). Library-owned since [#87](../codebase/87.md) — `pkg/tuidriver/session.go` exports `(*Session).TypePrompt(string) error` + `(*Session).ClearInputLine() error` alongside the three calibration constants (`PromptInterByteDelay`, `PromptCommitSettle`, `ClearLineSettle`); `cmd/spike-ask-user/main.go` was the first consumer migrated, followed by `spike-multi-turn` ([#116](../codebase/116.md)), `spike-cancel` ([#117](../codebase/117.md)), and `spike-permission` ([#118](../codebase/118.md)) — the arc is closed (the spike-ask-user tail-side migration in [#114](../codebase/114.md) completed the same binary's library-surface adoption from the other direction). No `// copied from … — keep in sync until library extraction` attribution-chain comments remain. The deliberate-paste path (`pkg/tuidriver/Session.WritePrompt`, introduced in [#47](../codebase/47.md)) is the **complementary** primitive for long/multi-line prompts — it sends `\x1b[200~ … \x1b[201~ \r` so claude doesn't have to heuristic-detect; both methods survive after #87 because they serve different prompt-size regimes (choose `TypePrompt` for short single-line, `WritePrompt` for long/multi-line). The convention does NOT apply to single-byte `\r`-less keystrokes (ESC cancel, `1\r` approve — both go through `sendKeystroke` as single bulk writes). See [#9](../codebase/9.md) for the empirical derivation, [#71](../codebase/71.md) for the paste-detection-on-first-prompt generalisation, and [#87](../codebase/87.md) for the library promotion + the package-private `sleepFn` clock-seam pattern that makes the timing testable.
- **PTY-quiescence readiness:** the general "claude has finished settling" signal — `❯` glyph present in the ANSI-stripped rolling buffer AND `rb.QuietFor() >= 1500 ms`, where `QuietFor` is "time since the last byte was appended to the rolling buffer." Directly observes silence instead of going through a proxy ("the spinner glyph has rolled out of the buffer"), which is unsound because claude doesn't emit enough bytes after a small redraw to roll the 4 KB rolling buffer past the stale spinner glyph. Introduced in `cmd/spike-cancel/main.go` as post-cancel readiness; now drives five call sites across four binaries — `waitReappeared` (post-cancel) + `runRecovery` (post-`end_turn` recovery) in `cmd/spike-cancel/main.go` (#11 + #69), `runTurn` in `cmd/spike-multi-turn/main.go` (#73), `runAutoRespond` in `cmd/spike-permission/main.go` (#70), and `run` (single-turn turn-complete) in `cmd/spike-one-turn/main.go` (#97) — all against the same `✻ Verb for Ns` stuck-glyph-in-rolling-buffer failure mode. All five sites compose `bytes.Contains(tuidriver.StripANSI(snap), tuidriver.IdleGlyph)` directly rather than going through `tuidriver.IsIdle` — the IsIdle wrapper's spinner-absent half is the exact clause that wedges. Five-consumer pattern across the four spike binaries that consume the predicate (the remaining spike binaries don't have a `gotEndTurn`-style readiness gate); the predicate the library will lift post-extraction (#58–#62), likely as a `ReadyForInput`-shaped primitive distinct from `IsIdle` (which keeps the spinner-absent half for callers that want it). See [#11](../codebase/11.md) for the empirical derivation, [#73](../codebase/73.md) for the first ticket that dropped the IsIdle wrapper, [#70](../codebase/70.md) for the permission-modal adoption, [#69](../codebase/69.md) for the second spike-cancel site + the IsIdle-wrapper drop in `waitReappeared`, and [#97](../codebase/97.md) for the spike-one-turn slow-path port (the last "same failure mode, port to another binary" ticket before library extraction lifts the shape).
- **Cancellation acknowledged (JSONL side):** a `user`-role event with content `[{type:"text", text:"[Request interrupted by user]"}]` — NOT a new `stop_reason` value. The cancelled assistant message keeps its pre-cancel `stop_reason`. The current assistant-only tailer filter drops this marker; consumers needing JSONL-side acknowledgment must widen the filter or rely on PTY quiescence. See [JSONL layout § Cancellation signal](jsonl-layout.md).
- **Input-box state across cancels:** post-cancel, claude restores the cancelled prompt as drafted input. The next prompt write must `Ctrl-U` (`0x15`) the input line first; idempotent on an empty input box. See [#11](../codebase/11.md).
- **Permission modal present (PTY side):** literal-text predicate over the stripped buffer — match any of `Esctocancel`, `Doyouwanttoproceed`, `Do you want to proceed`. Two forms of the "proceed" phrase because claude renders permission-modal text differently per tool: Bash uses `\x1b[1C` (CSI cursor-forward) between words, so the stripped buffer has NO interword spaces; Read uses literal spaces. The dual-form match is mandatory. The cheap "any box-drawing char in the buffer" alternative is false-positive at idle (claude's own input box uses `╭ ╰ │`). Strip both CSI (`ansiRe`) AND OSC (`oscRe = \x1b\][^\x07]*\x07`) before matching; OSC payloads otherwise contaminate the buffer. See [#13](../codebase/13.md). Permission modals have **zero JSONL footprint** — detection MUST be PTY-side; see [JSONL layout § Permission modals (zero JSONL footprint)](jsonl-layout.md).
- **Modal text extraction:** last `─{20,}` run BEFORE the proceed-marker is the start anchor; the line containing `Esctocancel` is the end anchor. Per-line, strip leading/trailing box-drawing border chars + whitespace, drop empty lines, join with `\n`. Robust across both Bash and Read modal variants (the alternatives — `modalSepRe.Split`, walk-back-N-newlines from the marker — fail for one or the other). Implemented in `cmd/spike-permission/main.go` as `extractModalText`. See [#13](../codebase/13.md).
- **Structured modal content (library, screen-side):** `tuidriver.ParseModalContent(snap []byte) *ModalContent` since [#146](../codebase/146.md) is the **library-side structured successor** to spike #13's raw-text `extractModalText` — it projects a `permission` / `trust-folder` modal into a neutral, JSON-tagged typed value (`ModalContent{Class ModalClass; Title, Prompt string; Options []ModalOption; Default int}`, `ModalOption{Index, Label}`) for the mobile-remote-head daemon (pyrycode#597 Phase 3 / substrate seal), which must receive a modal as a typed value and never read claude's screen text. Screen-sourced **sibling of `ParsePicker`** (NOT the JSONL `Parse<Tool>` family — modals have zero JSONL footprint). Behaviour: `class := DetectModalClass(snap)` (reuse, don't re-detect) → `nil` unless `permission`/`trust-folder` → `Render(snap, 0, 0)` (vt10x, **not** `StripANSI` — repaints `\x1b[1C` cursor-forwards back to spaces so option text reads `"2. Yes, allow…"` not `"2.Yes,allow…"`) → per-class branch → `nil` if zero option rows parse (no half-struct, mirroring `ParseAskUserQuestion`'s "nil if it would be empty"). One unexported `modalOptionRe = ^(❯\s*)?(\d+)\.\s*(.+)$` extracts each row in render order with the `N.`/❯ outside the label capture (clean by construction) and sets `Default` to the ❯-marked row's 1-based index (`0` = none). The **JSON tags ARE the serializer** (no `Marshal*` method — same as `AskUserQuestion`/`Agent`); the serialized push shape carries no ANSI/OSC bytes and no box-drawing glyph (asserted by test, AC2). **Trust boundary:** the modal content is prompt-/tool-influenceable, so `Index` (claude's rendered number) is the security-relevant selector the answer child routes on (`Answer(strconv.Itoa(opt.Index))`); `Label` is advisory display text that can mislead a human but cannot change which grant a keystroke applies. All claude screen literals stay unexported (reuses `modal.go`'s permission anchors; new `anchorTrustHeaderSpaced` for the Render-side trust match, because `modal.go`'s space-stripped `anchorTrustFolder` does not appear in `Render` output). Pure stateless function — no goroutines, locks, or shared state. The write counterpart (choice → keystroke + re-read confirmation) shipped in [#147](../codebase/147.md) as `AnswerModal` (next bullet) and builds on this struct. See [#146](../codebase/146.md).
- **Approve keystroke (permission modals):** `1\r` (`0x31 0x0d`) — single bulk `pty.Write`, no inter-byte delay. Matches the on-screen `❯1.Yes` numbered default ("Yes, once" — narrowest grant). `y\r`, bare `\r`, and `\x1b[B\r` (down + enter) also work; the down-arrow variant selects option 2 (project- or session-scope grant, tool-dependent) and is ~1 s slower. Library default for "approve once" should be `1\r`; "approve broader scope" is a separate product affordance, not a fallback. Same single-byte single-write semantics as the cancel keystroke — both go through `sendKeystroke` (which is the same body spike #11 introduced as `sendCancel`, renamed because cancel and approve share semantics). See [#13](../codebase/13.md).
- **Safe modal-answer (library, screen-side writer):** `(s *Session).AnswerModal(ctx, AnswerModalOpts) error` since [#147](../codebase/147.md) is the **write counterpart** to `ParseModalContent` (the reader, two bullets up) — given a modal `Class` + the chosen option's `Choice` (`ModalOption.Index`), it sends the per-class keystroke that selects that option then re-reads the screen to confirm the modal dismissed, for the mobile-remote-head daemon (pyrycode#597 Phase 3 / substrate seal). `AnswerModalOpts{Class ModalClass; Choice int; ConfirmTimeout time.Duration}` carries **Class + Choice only** (never the full `*ModalContent`, never `Label` / screen text); exported `DefaultAnswerConfirmTimeout = 2s` bounds the confirm poll. **Mirrors `DeliverPrompt`'s deliver→re-read→confirm structure and injectable seams almost line-for-line:** the public method wires `s.Answer` + a `modalDismissed` closure over `s.Snapshot` into an `answerDeps{answer, dismissed}` struct (cf. `deliverDeps`); the unexported pure driver `answerModal(opts, deps)` dispatches the keystroke then confirms; tests drive the driver with fakes, no PTY (and the confirm poll `modalDismissed` mirrors `promptDidCommit`'s `time.NewTimer` + `time.NewTicker` + `select{ctx.Done/deadline/tick}` exactly, swapping the commit predicate for `DetectModalClass(snap) != class`). **Per-class dispatch is one `switch`** — both classes `ParseModalContent` returns today (`permission`, `trust-folder`) are number-select, so both share a single `case` mapping `Choice` → `Answer(strconv.Itoa(Choice))` (byte-identical to `AcceptTrust`'s `1\r` for `Choice == 1`, and also honours `Choice == 2` decline which the hardcoded `AcceptTrust` cannot); the `switch` IS the extension seam — a future non-number-select class (y/n, arrow+enter) adds its own `case` + `answerDeps` seam **once fixtured** (do NOT pre-build, #146 follow-up). **Security:** routes only on `Choice` = `Index` (claude's rendered number), never the prompt-/tool-influenceable `Label` (the #146 contract, now enforced on the write side); the keystroke funnels through the **sealed** `Answer` → `writeRaw` path (never the spike-only `SendKeys` / a raw `Write`); error messages carry only the `ModalClass` enum + the integer `Choice`, no screen literal. **Confirm is class-level, not content-level:** `DetectModalClass(snap) != class` reads claude's structural anchors (unforgeable from prompt content) — any non-matching screen (idle, *or a different modal that popped after*) counts as dismissed (the answered class is gone; a new modal is a fresh parse→answer cycle for the daemon). A still-present **same**-class modal returns the still-present error — a deliberate conservative false-negative (the daemon retries / degrades; content-diffing to distinguish A from B would route on the forbidden screen text). No goroutines / locks of its own; the single keystroke reuses the existing `writeRaw` → `pty.Write` path. `security-sensitive`, security-review verdict **PASS** (sends a grant-selecting keystroke on a live claude; grant-redirection mitigated structurally by Index-routing). The permission *decision* / who-may-answer / answer-keystroke staleness stay consumer-side (ADR 025). See [#147](../codebase/147.md).
- **Addressable rendered-grid accessor (`Grid`):** `tuidriver.NewGrid(snap []byte, cols, rows int) *Grid` since [#150](../codebase/150.md) is an immutable, addressable view over the rendered VT100 *screen* — the foundation of the **rendered-grid refactor (Cross-Repo Code Review 2026-07-03, slice 1 of 6, fixes CRITICAL A + B)**. Root cause the chain removes: detectors classify state by `strings.Contains` over the raw append-only **history** buffer (`Buffer.Snapshot()`), so text that has **scrolled off the top of the visible grid still lives in history** and is matched as if on-screen. `Grid` closes that gap by exposing what `Render` already computes (the visible grid) as structure instead of one joined string. `NewGrid` is a one-liner over `Render` (`strings.Split(Render(snap, cols, rows), "\n")`) — **rendering, right-trim/drop-trailing-empties, and the `0`→`DefaultGridCols`/`DefaultGridRows` (120×40) dimension fallthrough are all delegated to `Render`, never re-implemented** — with the one non-obvious guard that an empty/whitespace-only render (`Render` returns `""`) yields **zero** rows, not the `[""]` a naive `strings.Split("", "\n")` gives. Accessors: `Rows() []string` (the cached rows, backing slice, documented read-only — same as `AgentList`/`McpStatus`); `ContainsInLastRows(sub string, n int) bool` (region-scoped — `n<=0`→false, `n` clamped to the row count via the `min` builtin, scans only `rows[len-n:]`, match must fall inside a single row); `RowHasPrefix(i int, prefix string) bool` (out-of-range `i`→false, **never panics** — a hard AC so migrated detectors probe rows without length guards). Region semantics are the point: `ContainsInLastRows(x, k)` is **false** when `x` is on the grid but above the last-`k` window, even though a raw `strings.Contains` over the snapshot bytes is **true** (pinned by the headline test). Immutable value fully computed at construction from the caller-owned copy `Buffer.Snapshot` hands back — no goroutines, locks, or defensive copy; no error returns (mirrors `Render`). **Targeted exception to [ADR 0002](../decisions/0002-pattern-matching-over-emulation.md)** in the same vein as `Render` itself ([#90](../codebase/90.md) Render-vs-`StripANSI` split): cheap text predicates (`IsIdle`, `HasTrustModal`) still `StripANSI`-match, but column-aligned/region-scoped parsing routes through the vt10x grid. **This slice wires no detector and changes no behaviour** — slices 2–6 migrate the three ad-hoc `Render`-consumers (`ParseAgentList` `agents.go:42`, `ParseMcpStatus` `mcp.go:72`, `ParseModalContent`/`modalLines` `permission.go:73`) plus the raw-history `strings.Contains` predicates onto `Grid`; new region predicates (`FirstRowWithPrefix`, `ContainsInFirstRows`, …) are added to the method set when a migration needs them, not speculatively. **Slice 4/6 landed [#153](../codebase/153.md)** — the idle/busy axis (`IsIdle` / `IsThinking`) is the first raw-history *predicate* pair migrated onto `Grid`: both now decide from the bottom `statusRegionRows = 6` rows via `ContainsInLastRows`, with a single unexported `busyInRegion(g)` seam holding the region-scoped busy predicate — [#156](../codebase/156.md) then OR'd claude's `esc to interrupt` hint into that one place as a second, independent busy anchor (`tuidriver.InterruptHint`), so both `IsIdle`/`IsThinking` inherited it coherently with no signature change (and #154 finds no parallel whole-buffer path on this axis to remove); closes both CRITICAL-B forgeries (mid-transcript `✻` no longer forges thinking, scrolled-off `❯` no longer forges idle); signatures unchanged (grid built internally with `NewGrid(snap,0,0)`) so zero caller edits. See [#150](../codebase/150.md).

## e2e harness

Top-level orchestrator at `cmd/e2e-runner/`, invoked by `make e2e`. Operates orthogonally to the rest of the system — it does not import `pkg/tuidriver/`, just shells out to the prebuilt spike + probe binaries under `./bin/<name>` and emits a single-file `e2e-report.json` artifact. Runs sequentially in one goroutine; `exec.CommandContext` handles subprocess lifecycle (SIGKILL on cancel) so no manual signal plumbing is required.

Headless-CI plumbing rides a single seam in `pkg/tuidriver/pty.go`: when `TUIDRIVER_STRICT_MCP_CONFIG=1` is set in the env, `EnsureClaudeEnv(cmd)` additionally appends `--strict-mcp-config` to `cmd.Args` (idempotent — skipped if already present). Every spike+probe already calls `EnsureClaudeEnv` between `exec.Command("claude", ...)` and `pty.Start`; the runner sets the env var on each child process, so the flag flows transparently with zero spike-side changes. Exported constant `tuidriver.StrictMcpConfigEnv` is the contract for the env-var name.

See [features/e2e-harness.md](../features/e2e-harness.md) for the operator runbook, report schema, and CLI flags. See [#34](../codebase/34.md) for the build notes.
